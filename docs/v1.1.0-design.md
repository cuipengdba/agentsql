# v1.1.0 双身份控制链设计

## 目标与发布边界

每个 MCP HTTP 请求同时验证活跃的人类委托令牌与 Agent Key。v1.0.0 已覆盖普通查询；本版将相同身份约束延伸到审批申请、审批执行和 B5 跨请求会话。旧的单 Agent 部署保持原有行为。v1.1.0 单独测试、合并、打 tag 并创建正式 GitHub Release。按产品负责人要求，官网和公网 Demo 保持 v1.0.0，到 v1.5.0 完成后一次性更新。

## 安全不变量

1. 委托令牌从服务端会话签发，绑定用户、Agent、租户、令牌 ID、有效期和活跃控制台会话；MCP 入口每次重新验证。控制台可持原令牌撤销单个令牌，其余委托与登录会话继续有效。用户停用、退出、撤销会话、Agent 停用、租户变化或任务授权失效时拒绝请求。
   v1.0.0 已签发的无令牌 ID 委托凭据保留原来的最长 30 分钟有效期，可通过退出父会话撤销；新令牌才支持单独撤销。
2. 委托审批单保存请求用户 ID，并将其加入不可变 HMAC seal；只有同一用户、同一 Agent、同一租户能读取与领取。领取谓词在数据库原子更新中检查用户，拒绝不会消耗审批单。旧审批单不能由委托请求领取。
3. B5 会话 principal 含可审计的用户 ID 与由服务端验证的用户、Agent、租户三元组派生的摘要。该 principal 参与持久化会话、密钥 AAD、continuation proof 与计划 digest。不同用户或单 Agent 请求即使持有 session ID 和 continuation secret 也不能继续会话。超出 B5 身份长度上限的用户 ID 直接拒绝。
4. B5 begin 的审批必须匹配包含上述 principal 的计划 digest；审计仍记录原有事务 ID、会话 ID、计划 digest 和 Agent，普通审批审计还记录委托用户。未知授权、审计故障和身份不匹配均在取得业务写连接前拒绝。
   DML grant 仍按经过认证的 Agent 检索，再映射到本次已验证的委托 principal 供 binder 校验；委托用户不会因此获得 Agent 原本没有的 grant。
5. 审批执行发生审计或数据库不确定结果时保留 `claimed`/`unknown` 终态语义，不自动重放写入。
6. 控制台密码与 LDAP 登录按租户、账号限制每分钟尝试次数，避免直接暴露账号存在性；MFA challenge 保持一次性消耗。该限流目前属于单实例边界，多实例共享限流留待 v1.4.0。

## 验收矩阵

| 路径 | 必须验证 |
|---|---|
| 委托审批 | 申请人持久化和 seal；另一用户与无委托请求均不能读取或领取；正确用户仅领取一次；失效令牌无法进入工具 |
| B5 会话 | 委托人可建立会话；同一用户可继续；更换用户、Agent 或租户失败；旧单 Agent 会话不被委托人接管 |
| B5 计划 | plan principal 与会话 principal 一致；计划 digest 绑定身份；无法证明授权、审计或连接状态时拒绝 |
| 兼容性 | 非委托部署原有审批和 B5 测试继续通过；升级迁移在 SQLite 与 PostgreSQL 通过 |

真实数据库、MCP 客户端、升级及回滚、CI 与发行物签名的证据记入发布验收报告。尚未实测的组合必须明确标注，不能据此扩大生产支持范围。
