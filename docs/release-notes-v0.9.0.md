# AgentSQL v0.9.0 发布说明

v0.9.0 聚焦临时任务 Key 的使用预算、管理审计投递可观测性和策略变更前的离线解释。数据库适配分档沿用 v0.8.0 的证据边界；本版不把任何协议兼容路径升级为完整生产支持。

## 新增与变更

- 新申请的任务级只读 Key 默认最多返回一次结果，可在申请时设置 1–10 次。申请、审批、签发、查看与撤销流程展示预算及已用次数。授权在执行前检查余量，在持久审计后、结果返回前以元数据库的条件更新原子扣减；并发跨实例最多放行预算内的结果。传输失败或进程异常时已经扣减的次数不退还。v0.8.0 及更早创建、未设置预算的授权维持原有效期与撤销语义。
- 分库审计部署的总览页展示当前租户管理审计 outbox 的待投递数、重试数和最老等待时间。超过 60 秒或存在重试显示延迟，超过 5 分钟显示严重积压；状态读取失败明确报错。它不替代流量审计库的就绪检查和持久审计门禁。
- 权限页新增 SQL 策略离线预检：读取当前已保存的 Agent、数据源、表策略并复用静态规则。只返回可证明的拒绝或“尚不能确认允许”，列出相关策略 ID；不连接业务库、不执行 SQL、不写流量审计。列级绑定、动态规则、视图/函数副作用和业务库状态仍须通过真实网关与 MCP 客户端验收。
- PostgreSQL/MySQL 敏感派生输出负向用例扩展到 `COALESCE`、`NULLIF`、`MD5` 等表达式，并继续覆盖函数、聚合、CTE、UNION 和视图等已实现的来源追踪与失败关闭路径。结果层脱敏仍不是完整 DLP；数据库账号最小权限、列级授权和安全视图仍是必要边界。
- 公开 Demo 的健康探针不再回显演示管理员登录凭据。隔离演示环境的登录配置接口继续向登录页提供公开演示账号，以保留自动填充；非 Demo 部署不返回该字段。

## 升级与兼容

- SQLite 合并库 metadata schema 从 `19` 升至 `20`；独立 metadata 的 SQLite/PostgreSQL 从 `18` 升至 `19`；audit-only schema 保持 `6`。新字段为 `max_uses`（可空）及 `used_count`（非空、默认 0）。旧授权的空预算表示不限次，避免升级时意外失效。
- 升级前停止写入，成套备份 metadata、audit（如分库）及配对的 `AGENTSQL_SECRET`；运行 `agentsqlctl migrate --check`，升级后再次检查。回退必须恢复升级前的成套备份，不能用旧程序直接打开新版 schema。
- v0.8.0 客户端创建新申请时若省略 `max_uses`，v0.9.0 会赋默认值 1。同一幂等键重放 v0.8.0 时代未设置预算的旧申请，可能得到内容冲突；应用应读取原申请并使用新幂等键提交新的有预算申请。

## 明确边界

- 预算限制的是向 MCP 客户端返回结果的次数，不阻止预算内并发请求先发起只读查询；最终返回前原子扣减。一次已审计结果在网络断开后可能消耗一次预算。
- 总览 outbox 统计按管理登录租户隔离，只覆盖待投递管理审计，不表示外部通知 Webhook/Syslog 的投递状态。
- 离线预检不产生“允许执行”结论，也不包含待提交策略变更；真实权限、执行、脱敏与审计仍以网关执行时的当前状态为准。
- DM8、KingbaseES V9 和 Vastbase G100 的能力仍限于已记录的指定实例、模式、合成数据和有界用例，不代表厂商认证、跨版本兼容或生产负载支持。
