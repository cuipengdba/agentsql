# AgentSQL v3.8.0 升级与回退

**语言 / Language:** [简体中文](v3.8.0-upgrade.md) | [English](en/v3.8.0-upgrade.md)

## 升级前

1. 停止旧网关写入，成套备份 metadata、独立 audit 库（如有）与 `AGENTSQL_SECRET`。在隔离环境用 v3.7.0 正式包和 v3.8.0 候选包分别运行 `agentsqlctl migrate --check`。本版不新增迁移：SQLite 合库版本仍为 27，独立 PostgreSQL metadata 25、audit-only 7。
2. 按[设计](v3.8.0-design.md)配置可选 `read_control_json`。启用 ClickHouse 预算前，DBA 须在只读角色为三项预算和两个溢出模式设置 `CHANGEABLE_IN_READONLY`；三项预算同时设定不得高于网关旧上限的 `MAX`。在真实业务数据源启用前测试正常查询、超预算抛错和错误角色约束。
3. 启用 Milvus 租户过滤前，在每个目标集合建立静态 String/VarChar 租户字段，填入与 AgentSQL 租户 ID 完全一致的值，并为租户字段、向量字段、输出字段和过滤字段配置精确列授权。先以合成数据确认跨租户命中为零、过滤字段越权拒绝和脱敏结果。

## 回退

停止 v3.8.0 网关，恢复升级前的 metadata、audit、密钥及 v3.7.0 正式二进制/镜像，检查 schema 与 `/healthz`。本版没有 schema 变更；仍应使用成套快照以保持审计与元数据同一时间点。回退后新增的 v3.8.0 配置和审计事件不会自动回放，须由维护窗口记录处理。
