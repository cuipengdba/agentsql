# AgentSQL v1.9.0 接入体验设计

**语言 / Language:** [简体中文](v1.9.0-onboarding-design.md) | [English](en/v1.9.0-onboarding-design.md)

状态：设计确定，尚未发布。目标用户是第一次把 Dify 自托管或 MCP Inspector 接到 AgentSQL 的管理员。当前控制台已有数据源/Agent/策略计数、连接预检、独立的 SQL 策略预检与错误码说明；但客户端配置散落在文档中，选择 Agent 和数据源后无法在同一流程解释目标 SQL、找到对应审计。v1.9.0 解决这一段接入工作，不改变网关的授权结论。

## 用户任务与预期结果

1. 管理员选定本租户 Agent 和数据源，完成状态、连接、策略存在性检查。
2. 选定 Dify 1.17.1 或 MCP Inspector 0.16.8，填写客户端可达的 AgentSQL 根地址，复制不含真实密钥的 URL/请求头说明。Dify 使用 `/mcp` 和显式 `MCP-Protocol-Version: 2025-06-18`；Inspector 使用同一入口但不手工重复添加版本头。
3. 输入一条明确 SQL，看到离线策略解释：明确拒绝时列出对象/策略 ID/静态规则；其他情况只显示“尚不能确认允许”，引导在真实客户端发起允许和拒绝请求。
4. 从客户端取得审计 ID 后直达审计详情，核对 Agent、数据源、决策、规则、脱敏和错误阶段；未能取得审计 ID 时按认证、协议、连接、执行或审计依赖排障。

## 必须交付

- 在接入向导复用同一 Agent/数据源选择，加入客户端配置说明、离线 SQL 解释和审计 ID 定位，不重复创建权限或执行 SQL。
- 客户端配置只包含 `<Agent API Key>` 占位符；控制台不索取、显示、复制、保存或写入 URL 中的真实 Key。地址输入只保存在页面内存，拒绝含用户名、密码、查询串或片段的 URL。
- 复用现有 `POST /api/v1/policies/preflight`。该 API 只读策略快照并解析 SQL，不访问业务库，输出 `deny` 或 `unknown`；UI 不把 `unknown` 变成允许，不把连接 Ping 或“有策略”解释为执行许可。
- Dify 容器内 `127.0.0.1` 指向 Dify 自身；若填写 loopback，给出明确警告。Inspector 手工重复添加 MCP 版本头会产生错误，配置说明须分别展示。
- 远端明文 HTTP 会传输 Agent Key；向导需提示改用 HTTPS 或隔离内网。本机回环演练不显示远端告警。
- 保留原有 Agent 身份、租户、授权、执行、脱敏、审批、持久审计和故障关闭合同。

## 不在本版

不自动生成或回显 Agent Key，不代用户在客户端创建连接，不因离线预检而直接执行 SQL，不扩大 `/mcp/2026-07-28` 或 OAuth 客户端认证范围，不把现有指定实例数据库支持升级为完整生产支持。真实客户尚未找到，因此不声称外部用户任务完成率；先记录内部引导演练的步骤、时间和失败点。

## 验收

1. 控制台对空状态、无权限、失效 Agent、无策略、断库、离线明确拒绝、离线未知、协议版本不符和审计依赖故障给出准确行动；切换 Agent/数据源或 SQL 后旧结果不再显示。
2. 配置说明在 Dify 与 Inspector 间切换后 URL/请求头准确，复制文本始终不含真实 Key；错误地址不生成可用配置。
3. Dify 1.17.1 与 MCP Inspector 0.16.8 分别真实完成允许/拒绝调用，核对脱敏与持久审计 ID；内部从空白配置到首次审计的任务演练记录，不等同真实用户研究。
4. 仍按[每版交付流程](RELEASE_ROUTINE.md)完成封版 CI、双架构签名资产、从 v1.8.0 升级恢复、GHCR、官网、Live Demo 与公网复验。
