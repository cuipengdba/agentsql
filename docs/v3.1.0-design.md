# AgentSQL v3.1.0 设计：SQLBot 业务接入

**语言 / Language:** [简体中文](v3.1.0-design.md) | [English](en/v3.1.0-design.md)

状态：开发与验收中。正式支持范围以本版验收记录为准。

## 用户目标

让企业管理员配置 SQLBot 工作空间、数据源和人员到 AgentSQL 的映射，使用实际模型完成自然语言问数、脱敏表格及指定图表。被拒绝的查询应解释原因并提供请求定位；需要审批的请求由用户明确提交和接续。

## 必须交付

- 固定 SQLBot v1.10.2 源码和镜像基线；补丁在版本或文件哈希不符时停止安装。
- PostgreSQL 数据源的完整业务调用，不扩大数据库支持级别；MySQL 接入留给 v3.2.0。
- 租户隔离的映射管理、配置导出、诊断、禁用、删除和连接凭据轮换；中英文界面。
- 每个 SQLBot 用户独立映射到既有 AgentSQL 人员及只读 Agent，使用短期、限定用途的人员令牌；每请求检查当前映射、人员权限和 Agent 状态。
- 表与字段元数据按当前用户的网关权限过滤后才能送入模型；禁止数据库直连回退。
- 安全拒绝不触发模型自动修改 SQL 重试；用户主动发起只读审批，批准后按原用户、Agent、数据源与封存 SQL 单次执行。
- 审批完整链路仅在明确关闭 B2 的 PostgreSQL 环境交付；B2 列级授权开启时，审批申请必须关闭失败，不能为申请自动降低授权级别。
- 真模型、真 SQLBot、真 PostgreSQL 的合成业务验收，覆盖跨工作空间/人员访问、撤权、审计故障、凭据轮换和审批重放。

## 信任与执行链

```text
SQLBot 普通登录用户
  → 服务端认证 current_user（跨 LLM 工作线程显式传递）
  → 本地精确 workspace / datasource / user 绑定
  → 独立 connector 凭据访问 AgentSQL resolve
  → 当前绑定 + 当前人员 RBAC + 当前只读 Agent
  → 2 分钟 SQLBot 专用人员令牌
  → Agent Key + 人员令牌 + 当前绑定版本逐请求校验
  → 指定 PostgreSQL 数据源的受控读取 / 只读审批
  → 原有授权、脱敏与持久审计
  → SQLBot 表格或已验收图表
```

连接凭据授权受信任的 SQLBot 服务端代表该条绑定中的外部用户。创建、修改和轮换要求策略、人员和数据源管理权限。不能将外部用户 ID 当作浏览器或模型可自行声明的身份。嵌入式 assistant/ask-token 路径不纳入本版用户级验收。

新人员令牌使用独立签名用途，不构造虚假的控制台登录会话，也不能作为管理 API 登录凭据。映射和连接凭据的变更提高 revision，使已签发令牌在后续请求失效。Agent Key 按既有 Agent 凭据生命周期管理，保存在 SQLBot 服务端环境变量中；导出配置只含变量名。撤销 Agent Key 用于停止该 Agent 的全部访问。

限定令牌只能调用读取、结构发现和只读审批工具。它不能访问 B5、写工具、其他数据源或 SSE 重放；MCP 会话还绑定映射 ID 与 revision。绑定 schema 用于结构发现，SQL 对象的实际权限仍由原策略和执行链判定。

## 存储与升级

增加租户隔离 `sqlbot_bindings` 元数据及事务管理审计。连接凭据仅存摘要；不保存 SQLBot 登录密码、模型密钥或 Agent 明文 Key。组合 schema 由 23 升至 24，分库 metadata 由 22 升至 23，audit 保持 6。升级前备份元数据、审计数据、配置及密钥；回退使用成套备份，不能用旧版本直接打开新 schema。

## 发布门槛

1. 管理权限、跨租户、字段校验、凭据泄漏和陈旧 revision 测试通过。
2. SQLBot 当前用户在普通请求、模型线程、元数据和审批路径一致；无上下文时拒绝。
3. 真实模型自然语言生成 SQL，经网关执行、脱敏并生成指定图表；固定 SQL 模拟服务不作为该项证据。
4. 旧 v1 适配配置回归；只按旧的工作空间级边界描述其能力。
5. 空库、v3.0.2 升级、同库/分库及备份恢复验证；Go/Web/Python/文档检查和对应提交 CI 通过。
6. 签名双架构资产、镜像、官网、Demo 和公网烟测完成后才声明发布。

客户试点等待用户提供实际客户和授权后另行排期。本次只实施 v3.1.0。
