# Vastbase G100 v0.6.0 适配边界

状态：候选实现，**尚无 Vastbase G100 真库验收**。数据库类型独立使用 `vastbase`；不能把 PostgreSQL 容器、PG 协议连通或其他国产数据库的测试当作 G100 结果。正式支持口径以目标版本及模式的验收报告为准。

## 当前实现

- 仅针对 G100 的 **PG 兼容模式**尝试使用 PG wire 连接。要求具备只读权限的数据库账号；连接参数强制 `default_transaction_read_only=on`，并在建连时检查产品标识含 `Vastbase`、只读事务参数为 `on`。不满足即拒绝；目标版本可能需要调整检测逻辑。行数和语句超时仍由 AgentSQL 限制。
- 原始 SQL 只接收一个显式 schema 的单表 `SELECT`，必须带 `WHERE` 与 `LIMIT`，并拒绝解析器识别出的恒真条件；投影必须是可解析的直接列。拒绝函数、注释、通配符、JOIN、CTE、子查询、聚合、排序、锁行、`SELECT INTO`、写语句及多语句。
- 执行器再次解析 SQL；会话、事务及写入入口在数据库调用前拒绝。普通 PostgreSQL 专属 B2 列级绑定和 B5 事务协调不继承。配置了 B2 列级策略的 G100 查询拒绝执行。
- 元数据读取走固定的 `information_schema.columns` 查询及参数，不接收客户端任意 SQL。敏感发现只能使用元数据模式；采样待真库验收。
- `EXPLAIN (FORMAT JSON)` 和 PG 结果协议目前是待验证的兼容假设。任何不兼容均停止执行，不自动降级为无计划检查或绕过解析。

## 发布前必须完成

1. 记录 G100 产品及版本、PG 模式、授权许可证、驱动协议、运行拓扑、数据库账号权限和初始数据。
2. 验证连接、固定元数据读取、带 WHERE/LIMIT 的表查询、EXPLAIN JSON、结果列与行数、超时/取消及断库。
3. 从 MCP 客户端测试对象授权、普通表级权限、脱敏和持久审计；带列级策略时应明确拒绝，不能默默忽略。
4. 用真库证明写入、DDL、锁行、多语句、未授权表、解析失败、超限均无数据库副作用，并留下请求 ID、审计 ID 与数据库侧证据。
5. 验证安装、升级、回滚及故障恢复后再调整支持矩阵。没有目标安装包、许可或可用实例时，此项保持“待真库验收”，v0.6.0 不能宣称完整生产支持。
