# AgentSQL v3.0.0 设计：能力声明与可复核交付

状态：设计与开发中。基线是已发布 v2.9.0；不以主版本号暗示 30 款注册数据库具有相同执行能力。

## 用户问题和取舍

控制台目前把所有关系型数据源标成 `relational`，把所有其他数据源标成 `nosql-connect`。这无法告诉管理员或 MCP Agent 哪些类型只有连接预览、哪些具有指定实例的受控读取工具，也无法显示真实查询仍受版本、开关、账号、对象策略和审计可用性约束。运维人员虽然能分别运行 `check-config` 和 `migrate --check`，但缺少一个结构化、只读且可自动判定的交付前检查入口。

Bytebase 的[官方 MCP 页面](https://www.bytebase.com/database-mcp-server/)与[接入文档](https://docs.bytebase.com/integrations/mcp)已经把身份、权限、脱敏、审计和客户端接入作为统一产品体验。AgentSQL 本版把自身已验证的能力范围表达清楚，并给运维提供可复核的预检与客户端烟测；不继承竞品网站对数据库数量或跨引擎治理范围的营销声明。

## 交付范围

1. 建立由服务端维护的 30 款数据源能力目录。四个层级为 `controlled_sql`（PostgreSQL/MySQL 既有受控 SQL 子集）、`bounded_sql`（指定实例的有界 SQL 只读）、`controlled_read_tool`（MongoDB、Redis、Valkey、ClickHouse、Milvus 的独立受控读取工具）和 `connection_preview`（其余类型的连接或管理预览）。每项有 Agent 工具入口、验收范围和证据文档。声明仅描述可能进入的路径，绝不是授权承诺；每次调用仍在现有身份、策略、执行、脱敏和审计链路判定。
2. 管理 API 的 `/api/v1/datasource-types` 与控制台“数据源”页使用同一能力目录。MCP `list_datasources` 只给当前 Agent 已获授权的数据源附带同一声明，不泄露未授权数据源、连接凭据或内部地址。保留原 `capability` 字段作为旧客户端兼容字段，并明确其语义不足以判断可执行能力。
3. 新增 `agentsqlctl doctor --config ... --format json|text`。它只读取配置和元数据、审计库迁移历史，不做 DDL、创建 SQLite 库或修改运行时身份。报告每个存储角色的当前/目标 schema、`ready`、`pending`、`blocked` 状态和下一步动作；待迁移返回退出码 2，损坏、未来 schema 或不可达返回 1。输出不含 DSN、密码或密钥。
4. 提供固定输入的 MCP 客户端验收脚本和操作步骤：工具发现、合成数据允许与拒绝、脱敏及审计 ID。API Key 只从环境读取，脚本不打印原始行或密钥，支持 Demo 的 2 QPS 限额。MCP Inspector 与 Dify 继续以真实客户端单独验证。
5. 对 v2.9.0 官方包到 v3.0.0 候选包执行 SQLite 与 PostgreSQL 成套升级和恢复；若本版没有 schema 迁移，应证明版本保持不变。补齐签名资产、两架构 GHCR、官网、Live Demo 和公网复验。

## 安全与兼容边界

- 能力目录不能绕过授权，也不根据是否能连接自动提升为“完整生产支持”。既有 MCP 工具名称和管理 API 字段保留；新增字段只做扩展。
- 对未知注册类型或缺少能力声明的情况，API 和 MCP 不生成乐观工具列表；目录覆盖测试阻止此状态进入发布。
- `doctor` 不调用会持久化实例 ID 的配置加载路径；SQLite 通过只读连接检查，PostgreSQL 仅执行只读查询。诊断错误使用固定码与下一步提示，不回显第三方驱动错误及凭据。
- 客户端烟测只能使用明确标记的合成数据，不发送真实用户数据。真实结果是否可交付仍由持久审计成功和现有故障关闭逻辑决定。
- 本版不增加数据库驱动、不放开写入、不自动迁移或回退生产数据，不声明厂商认证、HA 或所有数据库的完整生产支持。

## 发布阻断用例

目录覆盖全部 30 类型、四层级互斥且证据可读；管理 API 与 MCP 对相同类型声明一致，未授权数据源不出现；权限撤销后工具调用仍拒绝。`doctor` 对缺失 SQLite、待迁移、历史缺口、未来 schema、独立审计库不可达和含密码 DSN 均保持只读并给出正确退出码。公网客户端的允许、R010 拒绝、脱敏和持久审计通过；v2.9.0 正式包升级与同点恢复、GitHub CI、正式资产、GHCR、官网和 Live Demo 均须有真实证据。
