# AgentSQL v1.0.0 设计与验收范围

**语言 / Language:** [简体中文](v1.0-design.md) | [English](en/v1.0-design.md)

## 目标

v1.0.0 以 PostgreSQL/MySQL 的既有证据范围为基础，收紧 SQL 列授权和 MCP 人员身份边界，并使运维人员能够判断为什么拒绝、如何恢复。版本号表示产品接口与交付流程进入稳定阶段，不代表所有已注册数据库获得完整生产支持。

真实客户试点待取得愿意参与的客户和测试授权后另行排期。DM8、KingbaseES V9、Vastbase G100 只沿用各自指定版本与合成数据的有界结论；不提升支持等级。

## 安全合同

| 场景 | 预期行为 |
| --- | --- |
| PostgreSQL 有列策略，B2 绑定器可用 | 将 SELECT 的投影、谓词、JOIN/自连接引用等交给数据库支持的列绑定路径；仍须通过表策略、规则、受控执行、脱敏和审计。 |
| 有列策略，但 B2 不可用或目标方言缺少等价证明 | 执行前失败关闭并写审计；不能退回只校验表名的旧路径。MySQL/Vastbase 列级策略继续明确不支持。 |
| HTTP MCP 双身份模式 | Agent Key 决定机器身份和租户；另一个 30 分钟内有效、绑定指定 Agent 的用户委托令牌证明人员身份。每次请求检查原控制台会话、用户状态和 `query.execute` 权限。跨租户、错 Agent、错任务授权签发人或失效凭据均拒绝。 |
| 控制台登录令牌 | 只用于控制台；不能直接充当 MCP 用户委托令牌。委托令牌也不能访问控制台 API。签发动作写管理审计，故障时不交付令牌。 |
| 有状态 MCP 会话 | 传输会话同时绑定 Agent 与用户；更换任一身份必须重新初始化。无状态入口逐请求验证。 |
| B5/审批执行 | 现有 B5 计划和 `execute_approved` 未携带完整双身份合同时，在双身份模式下关闭；普通模式维持原行为。 |

双身份是可选开关 `mcp.delegation.require_human_token`，默认关闭以保持已有 MCP 客户端兼容。启用时要求控制台开启；所有 HTTP MCP 请求都携带两枚独立凭据，stdio 不使用这一 HTTP 合同。现有普通 Agent 仍可按原策略调用基础工具；任务 Key 额外受原 SQL、预算和签发人约束。

## 控制台与文档

控制台的「任务授权」页在双身份模式下提供按 Agent 签发人员令牌与一次性展示。权限页明确列策略的真实运行边界，避免把离线预检的“表级候选通过”误当执行许可。接入指南给出双请求头示例、凭据失效与客户端兼容说明；发布说明列出升级影响和恢复方法。

## 发布阻断项

1. 列策略负向集覆盖 JOIN、自连接、通配投影、谓词引用和 B2 不可用；拒绝时业务 SQL 不执行，审计有记录。
2. 委托令牌覆盖签发、错 Agent/租户、过期、登出、用户禁用、权限撤销、任务 Key 签发者错配和有状态会话身份替换；不泄露令牌到审计或日志。
3. Go、Web、官网自动测试通过；MCP Inspector 的两个 HTTP 入口及 Dify 兼容路径有真实调用证据。
4. SQLite 合并库和 PostgreSQL metadata/audit 分库的升级、恢复与审计故障关闭通过；DM8、金仓、Vastbase 只记录确实完成的复验。
5. 同提交 CI、签名资产、双架构 GHCR、GitHub Release、官网和 Live Demo 公网烟测全部通过，并按 [每版交付流程](RELEASE_ROUTINE.md)记录证据。
