# AgentSQL v3.5.0 发布说明

**语言 / Language:** [简体中文](release-notes-v3.5.0.md) | [English](en/release-notes-v3.5.0.md)

状态：发布候选。正式交付以[验收记录](v3.5.0-acceptance.md)和 GitHub Release 为准。

## 本版改进

| 范围 | 变化 |
| --- | --- |
| 三网关部署 | Kubernetes 样例固定三个工作节点、三个独立 RWO PVC 和稳定 B2 实例 ID；预检、只读 schema 检查、反亲和、就绪探针及中断预算与该拓扑一致。 |
| 跨网关审计事件 | PostgreSQL 审计写入在事务内分配按租户递增的提交游标。管理端 SSE 从独立 audit 库按游标有界读取，支持本租户 `Last-Event-ID` 续接；Web 保存帧游标而非审计记录 ID。越界、断档、审计不可用和连接过量按失败处理。 |
| 故障与容量边界 | 三节点允许、拒绝、脱敏、持久审计、单节点故障、双库故障及恢复经隔离环境验证。每节点 Agent QPS 上限为 10、管理 SSE 连接上限为 50；聚合上限是配置预算，不是生产吞吐承诺。 |
| B5 身份修复 | 普通 Agent 的显式会话加密使用认证租户，与仓储租户保持一致，避免合法续接因 AAD 不一致被拒绝。三副本发布样例继续关闭 B5 会话和事务；修复不代表跨实例数据库事务迁移已经开放。 |

## 升级与兼容边界

共享 PostgreSQL metadata 为第 23 版，独立 audit 升至第 7 版。先成套备份两个数据库，停止全部旧 B2 网关并等待租约过期，执行迁移与只读检查后再启动三个新版副本。回退同样全停，恢复成套备份并使用旧版正式镜像；只回退镜像不满足 schema 兼容要求。隔离 v3.4.1 双副本到 v3.5.0 三副本，再恢复备份回到 v3.4.1 的流程见[验收记录](v3.5.0-acceptance.md)。

公开 Demo 可能采用单实例或简化拓扑，应以页面实际标注为准。此版不宣称 B2 混合版本无停机滚动升级，也不宣称 B5 状态会话在其他节点静默恢复；生产环境还需复核自身 PostgreSQL、网络、存储、TLS 和负载。
