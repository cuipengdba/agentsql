# AgentSQL v3.5.0 三网关验收记录

**语言 / Language:** [简体中文](v3.5.0-acceptance.md) | [English](en/v3.5.0-acceptance.md)

状态：候选验收中。正式签名资产、公开镜像、官网及公网 Demo 须在发布后单独验收。

## 隔离环境与边界

使用本机 kind v0.33.0、Kubernetes v1.35.8，一个控制平面与三个工作节点。控制平面在第一次自动建群超时后，按 kind 随镜像提供的 kubeadm 与 CNI 清单手工完成启动。三个 AgentSQL Pod 分别在不同工作节点，使用独立 RWO PVC 和稳定实例 ID。共享 metadata、独立 audit 及合成业务数据均位于本机 PostgreSQL 18 测试容器；没有使用生产客户数据。主发布样例保持 MCP HTTP 无状态、B5 会话和事务关闭。

三节点及升级演练使用候选镜像 `sha256:4ee19cf264ff3b3c96e52bca9b8d0ea7d6f7ea25570cd10e6510c1c4a60decaf`（功能提交 `2a8cbfc`）；B5 修复后双网关试验使用 `sha256:1a7ce13bc100e812363588f07df307272c04c1237099ee655c8014eb169073c5`（代码提交 `5c95272`）。前者与最终发布提交不同，正式资产仍须从合并后的 SHA 重建并核验。

## 已通过的链路

| 项目 | 实测结果 |
| --- | --- |
| 安装与迁移 | metadata/audit 独立 PostgreSQL 迁移及只读检查通过，分别为第 23/7 版；预检确认三个 Ready 工作节点。三个 Pod 的实例 ID 不同，重启后各自 PVC 上的 ID 不变。 |
| 跨网关请求 | 同一管理员令牌跨网关可用；三个节点的 MCP 初始化成功。合成 PostgreSQL 数据的允许查询、未授权列拒绝和邮箱脱敏通过，允许与拒绝均有持久审计。 |
| 跨网关审计 SSE | 节点 0/2 产生的允许与拒绝审计可在节点 1 的 SSE 看到。节点 2 使用节点 0 产生事件前的本租户 `Last-Event-ID` 获得下一帧；另一个租户看不到默认租户历史，跨租户游标返回 HTTP 400。 |
| 单节点故障 | 停止一个工作节点后，Service 移除其 Pod；其余两个网关继续完成允许、拒绝、脱敏及 SSE。节点恢复后原 Pod 再次就绪。 |
| 审计库故障 | 隔离 audit 库拒绝新连接并终止既有连接后，查询失败关闭，新的 SSE 请求返回 HTTP 503；恢复连接后允许查询重新成功。 |
| metadata 故障 | 中断 metadata 超过租约时间后，网关 `/readyz` 返回 503，MCP 不返回允许；恢复数据库并按运维流程重建三个 Pod 后，三者再次就绪，稳定实例 ID、权限、脱敏和持久审计复验通过。 |
| 有界并发 | 三节点 36 次并发请求：25 允许、9 拒绝、2 错误；25 个允许结果都有对应持久审计 ID，P50 821ms、P95 1070ms。单节点停用后的两节点 24 次请求：10 允许、2 拒绝、12 错误；10 个允许结果均有审计，P50 1473ms、P95 2561ms。仅为本机样本，不是生产 SLA。 |
| 旧版升级与回退 | 隔离命名空间中 v3.4.1 双副本就绪、管理员登录通过，随后全停并备份成套 metadata/audit；迁移 v3.5.0 后版本为 23/7，三个候选 Pod 就绪。再次全停并从备份恢复后版本回到 23/6，v3.4.1 双副本重新就绪，管理员登录及 schema 检查通过。该流程没有声称 B2 混合版本滚动升级。 |
| B5 会话负向验证 | 临时开启 B5 的两个独立 Docker 网关共用 PostgreSQL metadata，修正后的镜像上会话创建和 owner 续接通过；误投另一个网关返回 `SESSION_WRONG_INSTANCE`，旧 epoch 与坏 proof 被拒绝。owner 停止时其他节点未接管，原 owner 携持久实例 ID 重启后可续接；调用方伪造租户被拒绝。此试验不等同于三节点 B5 事务发布验收。 |

## 尚未计入发布验收

B5 会话临时开启试验揭示普通 Agent 的会话加密 AAD 与仓储租户不一致，导致有效签名续接被拒绝。身份来源修正后，以上双网关 Docker 回归通过。三副本正式样例继续关闭 B5 和 HTTP 状态会话，不能宣称跨实例事务无缝迁移；B5 的真实三节点定向路由与事务故障切换尚未验收。

上述 Kubernetes 验收使用本机合成数据和候选镜像。控制平面在并行镜像构建期间曾因本机资源压力重启；正式发布前须用最终提交重跑 CI 与关键链路，并验证签名资产、匿名拉取、官网和公网 Demo。公网 Demo 的实际部署拓扑应单独标注。
