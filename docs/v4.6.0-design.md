# AgentSQL v4.6.0 设计与验收合同

> 开发分支合同。只有最终精确提交的验收结果和正式发布说明构成支持声明。

## 范围

v4.6.0 在 v4.5.0 独立问数与 MCP Server 安全网关之上，交付 SQLBot Community v1.10.3 的 Type 1 高级助手和第三方前后端分离接入。使用未修改的原版助手客户端；第三方目录只提供待映射的 ID 与展示名称，数据库连接和执行始终由 AgentSQL 运营方登记的网关别名决定。

v4.7.0 承接角色、多用户、非空白名单活动权限规则；v4.8.0 承接其余社区页面/API 与任意连接创建编辑。v4.6.0 不因高级助手接入扩大这两部分支持范围。

## 已确认的原版协议与安全分界

固定原版镜像 `dataease/sqlbot:v1.10.3` 的独立黑盒探测确认：Type 1 配置可创建、列出、删除；未修改 `assistant.js` 首先调用公开密钥和 `GET /system/assistant/info/{id}` 取得虚拟助手令牌，进入问数时调用默认模型与 `GET /system/assistant/ds`。原版浏览器会从宿主消息读取 `certificate`，之后把 `btoa(encodeURIComponent(certificate))` 放入 `X-SQLBOT-ASSISTANT-CERTIFICATE`。证书消息缺失时，原版目录请求失败。该引导签名使用公开密钥形成，不能证明真实最终用户身份。测试探测使用一次性原版容器，不构成 AgentSQL 通过状态。

AgentSQL 必须把引导令牌限定为应用与来源上下文。只有宿主凭据与运营方预登记的目录端点、密钥指纹、真实非管理员用户、工作空间及外部 ID→当前受权网关别名映射同时匹配，才允许目录与问数。来源检查是附加约束，不能代替凭据。所有数据入口和异步返回前重新核对身份、应用修订、目录登记修订、绑定及表列行权限；失败不得返回旧 SQL、数据、历史或导出。目录响应中的主机、端口、账号、口令等字段不得作为连接配置。HTTPS 必须验证证书链、主机名和运营方固定的叶证书哈希；HTTP 仅允许显式批准的隔离测试入口。

运营方在私有 `assistant_catalogs` 登记中用 `assistant` 字段指定 Type 1 应用 ID。该应用的 `configuration.endpoint` 必须与登记端点完全一致。未配置或多份活动登记时，公开引导拒绝发令牌。公开引导令牌本身不能调用数据入口；原版宿主提供的证书字符串仅用作 HMAC 指纹匹配。目录展示时把外部 ID 映射为本地受权网关别名，浏览器后续会话使用该别名，目录中的连接参数全部丢弃。目录移除仅影响下一次目录获取；**即时撤权必须停用登记、应用、用户或网关绑定**，这些状态在执行与返回前复核。

## 实施顺序

1. 固定原版 Type 1 浏览器请求、消息及目录响应形状，补全可复核的协议记录。
2. 增加仅用于 Type 1 的短时无数据引导令牌与宿主凭据校验；无凭据时只允许无敏感内容的引导响应。
3. 把 Type 1 应用绑定到运营方登记的目录与真实用户，目录 ID 在边界映射为当前受权网关别名；执行仍走现有 ChatBI 受控网关、模型租约和持久审计。
4. 用同一精确提交完成原版客户端、合成目录、真本地模型/真数据库正向，凭据错配、来源伪造、目录变化、用户/别名/行列权限撤销、模型/数据库/审计/存储故障和历史导出负向；记录 CPU/内存和冷/热首问，不宣称 SLA。
5. 五项 CI 全绿后构建该精确提交的正式双架构资产，以生产密钥签名并独立公钥验签；AMD64 与 QEMU ARM64 断网 real-systemd 新装、v4.5 升级和失败回滚全部通过，再发布 GitHub Release、GHCR、官网和明示模拟的 Demo，并匿名回下载核验。

## 发布用语

仅声明实际验证的应用类型、目录形状、模型、数据库、入口及部署架构。QEMU ARM64 不写作 ARM 实机。未在用户真实业务系统验证，不宣称 100% 兼容或零改动切换。
