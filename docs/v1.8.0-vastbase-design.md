# v1.8.0 Vastbase G100 深化设计

**语言 / Language:** [简体中文](v1.8.0-vastbase-design.md) | [English](en/v1.8.0-vastbase-design.md)

状态：开发中。目标实例为 Vastbase G100 V3.0 Build 9、commit 30156、PG 兼容模式。其他 Build、模式、许可和部署拓扑须单独验收。

## 用户问题和范围

v1.6.0 已验证指定实例的有界只读 SQL、安全策略、脱敏、持久审计及单实例故障关闭。v1.8.0 重点补齐该路径的服务端身份校验和部署约束，避免管理员误以为“PG 兼容”自动代表安全 TLS 或完整生产支持。查询范围继续限定为明确 schema、带 `WHERE` 和 `LIMIT` 的单表 `SELECT`；继续拒绝写入、跨表、无界查询和未明确授权的对象。

目标：

1. 管理 API 和控制台保存并展示 `verify-full`、CA 文件及证书主机名；错误 CA、错误主机名、不安全信任选项均失败关闭。
2. 在隔离的 G100 Build 9 实例上用最小权限只读账号验证正确 TLS、错误证书、明文拒绝、允许查询、越权拒绝、脱敏和持久审计。
3. 记录试用许可、协议版本和部署方法；证书和凭据轮换、故障恢复仅按实际结果声明。
4. 完成上一正式版到候选版的升级与成套备份恢复，不隐式改变数据库 schema。

非目标：在只有一台试用授权实例时声明主备高可用、厂商认证、生产容量或完整生产支持。若无法取得正式许可和可验证主备拓扑，该项保留为明确未验证边界。

## 安全链路

`MCP 客户端 → Agent/租户身份 → 数据源与对象授权 → SQL 解析及只读限制 → G100 PG 模式的只读账号与 verify-full TLS → 有界结果 → 列脱敏 → 持久 allow/deny 审计`。审计库不可用时请求失败关闭；连接、证书或账号轮换错误不能退回明文连接。服务端还须对只读账号设置 `hostnossl ... reject`，使其他客户端也不能用明文绕过 TLS 要求。

## 指定实例的 TLS 部署约束

隔离试验中，G100 `ssl=on`、服务端证书与密钥权限为 `0600`、`require_ssl=off`，并在 `pg_hba.conf` 为只读账号优先配置 `hostnossl ... reject`。启用 `require_ssl=on` 后，G100 会拒绝当前 `pgx` 驱动的协议 3.0 启动包，即使 TLS 握手成功；该开关因此不是此适配路径的可用配置。`verify-full` 客户端使用 CA 和主机名校验，禁止降级到明文。此结论来自指定 Build 的隔离实测，不推广到其他版本或驱动。

厂商文档分别描述 [G100 的 SSL 连接](https://docs.vastdata.com.cn/zh/docs/VastbaseG100Ver2.2.5/doc/%E5%BC%80%E5%8F%91%E8%80%85%E6%8C%87%E5%8D%97/%E6%95%B0%E6%8D%AE%E5%BA%93%E4%BD%BF%E7%94%A8/%E8%BF%9E%E6%8E%A5%E6%95%B0%E6%8D%AE%E5%BA%93.html)和[镜像许可挂载方式](https://docs.vastdata.com.cn/zh_CN/VastbaseG100/V2.2.14%20%28DMR%29/1/8e6e35101302438caf6008011852c41f)。实际配置与兼容性以本次 Build 9 证据为准。

## 发布阻断用例

| 路径 | 预期 |
| --- | --- |
| 正确 CA、主机名和只读凭据 | TLS 查询成功，保留 Agent 身份和持久 allow 审计 |
| 错误 CA、错误主机名、显式信任未验证证书 | 连接拒绝；无明文回退 |
| `sslmode=disable` 的只读账号 | 服务端 HBA 拒绝 |
| 无授权对象、写语句和越界查询 | AgentSQL 拒绝并记录 deny |
| 手机号等敏感列 | 返回脱敏值，不泄露原文 |
| 审计库断开、客户端取消、数据库断开 | 失败关闭，并可解释终态 |
| 证书及密码轮换 | 旧凭据/旧信任失败，新配置恢复；只按实测宣称 |
| 主备切换 | 需要正式许可和真实主备拓扑；缺失时标记未验证 |

最终发布范围以验收记录和正式 Release 为准。
