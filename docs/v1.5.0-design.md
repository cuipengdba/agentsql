# AgentSQL v1.5.0 指定国产数据库深度验收与默认入口切换设计

**语言 / Language:** [简体中文](v1.5.0-design.md) | [English](en/v1.5.0-design.md)

## 用户场景与范围

面向已经使用国产数据库、需要让 Agent 读取受控数据的团队，本版把现有的“指定实例基础闭环”验证为可重复的权限、执行、脱敏、审计和故障关闭证据。真实客户试点仍待用户找到合作方后单独排期；本版仅使用隔离实例与合成数据。

验收对象严格限定为：达梦 DM8 Pack3 `dm8_20241022_x86_rh6_64_single`（COMPATIBLE_MODE=0）；金仓 KingbaseES V009R001C010B0004（PG 模式）；Vastbase G100 V3.0 Build 9 commit 30156（PG 模式）。分别记录镜像或安装包摘要、服务器返回版本、模式、许可证状态、账户权限及测试时间。厂商临时许可的通过不等于生产授权。

## 必须交付

1. 每款数据库使用独立实例、最小权限业务账号、明确的表级允许策略和敏感列掩码。对同一合成数据验证允许查询、未授权表/列拒绝、危险 SQL 拒绝、敏感字段不泄漏、持久审计与结果关联。只在现有已证明 SQL 子集内测试，不由测试结果推导更广方言支持。
2. 分别注入策略撤销、业务账号权限撤销和库断连，恢复后复核可用性、掩码及审计；故障时不得交付敏感结果。逐库查询超时/取消和独立审计存储故障列为继续补测项；未在同一厂商环境稳定注入前明确记录“未验证”，不得用共享 Pipeline 测试或模拟结果替代真库证据，也不得宣称该故障场景已获完整生产支持。
3. 对每款数据库分别在 MCP Inspector 与 Dify 完成至少一次真实允许和拒绝工具调用，记录客户端版本、入口、请求 ID、审计 ID 和输出脱敏；保留客户端不能覆盖的能力边界。无 Claude 账号，Claude Desktop 不列为本版实测。
4. 从 v1.4.0 的正式发行包和数据备份执行 SQLite 与 PostgreSQL metadata/audit 分库升级、`migrate --check` 和成套恢复。若本版增加 schema，验证旧版本启动保护；若 schema 不变，验证旧版只读迁移检查仍为 current，并明确代码回滚仍需遵守服务停流与备份流程。两种情况都用正式包验证配置与持久数据兼容。
5. 通过同提交 Go/Web/安全 CI；构建、签名和验证双架构发行资产，推送并匿名拉取 GHCR 精确版本三类镜像，创建独立 GitHub tag 与正式 Release。上述全部通过后，把官网、下载/PDF、GHCR `latest` 和公网 Demo 从 v1.0.0 直接切换至 v1.5.0，并做公网版本、允许/拒绝/脱敏/审计及下载校验，保留可恢复快照。

## 数据库支持声明

验收报告使用“指定版本、指定模式、指定只读子集已通过”表述。达梦、金仓和 Vastbase 不因本版自动升为全场景完整生产支持。正式生产许可、TLS、厂商 HA、长时间负载、更多 SQL 方言、跨版本兼容与真实客户环境均需另行证据；未完成项在支持矩阵和官网明确写明。

## 失败关闭检查表

| 边界 | 允许交付条件 | 失败时行为 |
| --- | --- | --- |
| 身份与租户 | Agent Key、租户、数据源与授权一致 | 拒绝且无业务查询 |
| 表/列权限 | SQL 对象和列用途均在已证明子集及有效策略内 | 拒绝，不回退至宽松策略 |
| 业务只读执行 | 最小权限账号、行数与时限内返回 | 拒绝/中断，不交付部分敏感结果 |
| 掩码 | 敏感列在输出前按策略转换 | 拒绝，不输出原文 |
| 审计与最终 fence | 持久审计和控制面快照有效 | 拒绝交付；记录可核查故障 |
| 断连与恢复 | 实际数据库和审计后端恢复且链校验可用 | 恢复前继续拒绝，不自动改写历史审计 |

## 发布门槛

三款真库的基础授权、受控查询、脱敏、拒绝、持久审计、已注入故障的关闭与恢复、两个客户端任一关键链路失败，或官网/Demo 候选在公网复验失败，均不得宣称 v1.5.0 完成。未验证的超时/取消与独立审计存储故障不得进入通过清单或完整生产支持声明。分阶段正式 Release 的 v1.1.0–v1.4.0 保留可直接下载的精确版本；默认入口只在本版完成后提升。
