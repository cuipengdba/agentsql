# AgentSQL v4.10.0 查询表达与会话闭环

> 开发合同；目标场景在同一精确签名包完成全部正负验收前，均不计为已通过或已发布。

## 用户问题与范围

AgentSQL 是独立 AI 问数 Agent 与独立 MCP Server 数据库安全网关，SQLBot Community v1.10.3 仅是固定的可选客户端。v4.9.0 修复了受权向量预热期间的短写锁身份审计超时，并以严格 25 场景合同建立 **2/25** 基线。已有切片证明多轮、重启历史、导出和嵌入的一部分路径，但尚未在同一签名包下满足各场景完整合同。v4.10.0 聚焦让自然语言查询的过滤、分组、排序和限量，以及会话历史的继续、重开、导出和基本嵌入形成可复核的用户闭环。

候选计分项为 Q2、H1、H2、H3、I3；全部通过时目标为 **7/25**，不是预先承诺的覆盖率。其余场景沿用 0 分，不能把 API 返回、页面载入、旧版签名包或模拟模型算作通过。v4.10.0 不扩张任意数据库连接创建、云模型、第三方目录或未验 SQL 方言的支持范围。用户真实业务系统尚未验证。

## 实现与安全合同

| 路径 | 必须完成 | 安全负向 |
| --- | --- | --- |
| Q2 单表查询表达 | 未修改原版问数页和 AgentSQL 自有页面接相同受控网关、真实模型与 PostgreSQL，以固定合成数据分别核对过滤、分组、排序、限量的 SQL、行值和顺序 | 未授权列或表、越界限量、模型输出非只读 SQL、行列规则变化均在返回前拒绝；受控审计与实际执行一致 |
| H1 上下文追问 | 同会话第二问准确引用第一问的受权表、筛选条件或时间范围，关闭重开后不丢失有效上下文 | 另一个用户不能读取会话；撤权后的旧 SQL、字段和结果不得进入模型上下文 |
| H2 重启历史 | 未修改原版页在 ChatBI 重启后重开历史，SQL 与结果按当下身份、绑定及行列规则展示 | 撤权、禁用、删除或更换绑定后旧值隐藏；不能通过缓存、详情或再次追问取回 |
| H3 历史导出 | 当前受权历史的 CSV 与原版 XLSX 从未修改页面或其原始 API 导出，文件行数与值一致 | 撤权后两种旧导出拒绝，网关没有新的受控查询；导出审计写入失败时不得流出文件 |
| I3 基本与页面嵌入 | 未修改原版基本助手和 Type 4 页面嵌入各完成真实问数、刷新历史和来源约束 | 错误 Origin、伪造消息、游客禁用、数据源撤权后不能取令牌或旧结果，且不得新增网关查询 |

身份、工作空间和数据源绑定必须由服务端当前记录确定。模型候选 SQL、历史 SQL、导出内容和嵌入消息都不是授权来源。每次执行前和返回前复核当前权限，审计提交失败时故障关闭；既有 Type 1、高级嵌入、角色扩张与任意云模型不因本版计分而扩大支持声明。

对 PostgreSQL 中明确引用上一轮结果的追问，只在上一轮仍可见且两轮均为同一张 schema 限定的单表查询、上一轮 WHERE 是有界简单谓词时，才在模型生成 SQL 后用 AST 保留该筛选。复杂筛选、别名、子查询或无法证明同表的形态在网关前失败关闭；不能把模型偶然保留筛选的单次结果当成确定性支持。新 SQL 仍走完整实时授权与审计。

## 发布门槛

1. 五项 GitHub CI 对应同一最终提交；新增或修复的行为有确定性正负测试，未修改原版客户端、真实模型/数据库/网关测试留原始日志和精确提交。
2. 固定 25 场景评分逐项列出通过或 0 分、正负证据与限制，不修改分母；任一安全越权、审计丢失或旧结果泄漏阻断发布，即使目标分数已达。
3. 从最终源码生产构建预期数量的正式双架构资产和外层离线包，独立可信公钥验签；AMD64 与 QEMU ARM64 断网 real-systemd 新装、正式 v4.9.0 升级、注入启动故障回滚并检查服务、模型、元数据与旧文件。
4. 合并、正式 GitHub Release、GHCR 多架构匿名回下载、官网和仅模拟模型且明示的 Demo、公网 allow/deny/脱敏/审计烟测完成后，规范仓库 main 与 origin/main 同步且干净。

发布说明不得宣称 100% SQLBot 兼容、零改动切换、ARM 实机或生产 SLA。若计分目标未达但范围内行为仍安全，应准确公布实际分数及未通过项，不得降低评分条件伪造结果。
