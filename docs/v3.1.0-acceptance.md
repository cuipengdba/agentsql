## 环境与实测

Windows 宿主机上使用 Docker Linux 隔离网络及命名卷、AgentSQL 候选镜像 `agentsql:v3.1.0-acceptance3`、固定 SQLBot v1.10.2、PostgreSQL 16 合成订单和商品数据、本地 Qwen3-4B 模型。SQLBot 数据源的直连地址故意无效，业务请求必须经过 AgentSQL。两个 SQLBot 工作空间及人员分别映射独立 AgentSQL 人员和只读 Agent，未触及公网 Demo。

| 场景 | 结果 | 本地证据 |
| --- | --- | --- |
| 自然语言生成 SQL、返回真实数据和数值纵轴图表 | 最终候选通过，六项检查均真，返回 3 行；用时 145.593 秒 | `sqlbot-data/qa-a-ask-final.json` |
| 显式关闭 B2 的审批申请、管理员批准、原用户一次执行 | 通过，返回商品 ID 1，执行审计 ID 348；再次执行被 HTTP 400 拒绝 | `sqlbot-data/approval-request.json`、`approval-status.json`、`approval-execute.json`、`approval-replay.json` |
| B2 开启时申请审批 | 关闭失败，HTTP 400，未自动关闭 B2 | `sqlbot-data/approval-b2on.json` |
| 跨工作空间/用户、Agent 和数据源范围、撤权、审计故障及恢复 | 17 项全部通过，审计故障时不返回查询结果或新身份 | `live-security.json` |

实测脚本为 `scripts/v3.1.0-sqlbot-business-acceptance.py`、`scripts/v3.1.0-gateway-acceptance.py`、`scripts/v3.1.0-live-security-acceptance.py`。审批提交本身不执行 SQL，批准后仅原用户可一次领取封存 SQL；拒绝不会触发模型自动改写重试。

## 边界与环境观察

- PostgreSQL B2 列级授权执行器当前不支持审批执行。启用 B2 的部署中审批申请由网关拒绝；完整审批验收仅覆盖显式关闭 B2 的隔离配置，不能以此代替 B2 生产部署。
- B2 执行器要求允许函数使用显式 `pg_catalog` 限定名。模型生成未限定的 `COUNT(*)` 会被拒绝并审计，适配器不改写原 SQL。
- 本机 Docker 普通存储上的 50 并发请求测试因审计链写入超时失败；v3.0.2 对照版也复现，同一断言在 Docker 内存盘连续三次通过。仍须以发布 CI 为准。
- 最初的 Windows 绑定卷跨系统写入损坏了隔离 SQLite 样本。样本已从备份恢复，随后全部使用 Linux 命名卷；未涉及生产数据。
