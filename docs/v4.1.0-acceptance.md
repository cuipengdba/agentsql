## 正式发布实证

- Git 标签 `v4.1.0` 指向 `6892cbc98047ce3b71f7bfe29d458720277f154a`；正式资产的 `SHA256SUMS`、SPDX、provenance 均经 Ed25519 签名验证，15/15 资产检查通过。
- 三个精确镜像标签 `v4.1.0`、`v4.1.0-demo`、`v4.1.0-quickstart` 均可匿名读取 `linux/amd64` 和 `linux/arm64` 清单；主镜像及 `latest` 指向同一摘要 `sha256:ee746069b3415c58cc31208b026b51926bbb3a91de6bccf9d08d64a09a2fe13d`。
- 公网 Demo 使用 `v4.1.0-demo` 且健康；内外网的合成数据允许查询、脱敏、拒绝及审计检查通过。官网中英文首页、Demo 落地页、中英文模拟问数页均返回 HTTP 200，静态网站公开校验 27/27 通过。
- 线上模型功能只显示明确标注的模拟交互。发布后云主机保留网关、MySQL、PostgreSQL 三个健康容器，根分区约 8.2 GiB 可用。

最新本地候选还完成 MySQL 邮箱查询：3 行均脱敏，审计编号 422。后续版本的真实模型功能只在本机验证；公网仅展示明示的模拟界面，不再要求云端模型容量验收，也不在云上运行模型。

## 失败尝试与限制

小模型 Qwen3 0.6B Q8_0 完成过两个库的受控查询，但一次“前 3 条”请求生成 `LIMIT 20`；该用例的语义验收失败，不计入模型正确率通过。真实模型的受控执行与业务回答准确性分别评价。

最初一次审计故障注入从 Windows 直接访问正在 Linux 容器中使用的绑定目录 SQLite 文件，触发器未按预期生效，随后该测试副本出现损坏。已保留失败副本，停止测试服务，从原先停止运行的合成测试基线恢复到 Linux 原生卷，并在相同 Linux 文件系统中重跑审计故障。该次失败不计为安全通过；未操作公网或真实业务数据库。

所有数据库与客户数据均为合成测试环境。尚未获得用户实际业务系统测试环境；当前不能声明真实业务代码和配置零改动替换已经验收。SQLBot 的完整功能、动态路由、嵌入、MCP 和全量迁移仍按[五版计划](v4.1.0-design.md)推进。
