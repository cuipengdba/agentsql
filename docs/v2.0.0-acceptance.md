# AgentSQL v2.0.0 候选环境验收

状态：功能候选已完成双节点演练；正式封版 CI、签名发行资产、GHCR、官网与公网 Live Demo 以独立发布证据记录为准。本文件不代表 v2.0.0 已发布。

测试环境：2026-10-18 至 2026-10-19，Windows 宿主机上的 kind v0.33.0，Kubernetes v1.37.0，1 个控制节点、2 个 Ready 工作节点。metadata、audit 和只读业务库均为隔离的 PostgreSQL 18 容器；业务库只有合成 `public.customers` 和未授权 `public.internal_notes`。双网关使用独立 RWO PVC、同一 32 字节密钥、PostgreSQL 分库存储和最小权限运行账号。测试网络未配置 TLS，也未模拟 PostgreSQL 自身主备故障。

| 验收项 | 候选环境实测 |
| --- | --- |
| 基线、迁移和备份 | 从正式 `v1.9.0` 镜像启动双节点；metadata 21、audit 6。成套 `pg_dump -Fc` 备份在两套独立 PostgreSQL 实例中恢复，v1.9.0 与 v2.0.0 候选二进制分别执行双库 `migrate --check`，均为 `current`。v2.0.0 独立迁移 Job 与只读 schema Job 通过。 |
| 双节点配置 | 部署前检查返回 `KUBERNETES_PREFLIGHT=PASS namespace=agentsql nodes=2`。两 Pod 分布于不同工作节点，独立 PVC 和不同 B2 实例 ID；同版二进制摘要一致，B2 协议 3 active。 |
| 并发启动 | v1.9.0 首次双 Pod 初始化出现 RBAC 唯一键竞态；候选版加有界重试。数据库恢复后同时重启还发现 B2 控制栅栏 ETag 竞态；候选版只对该启动冲突重读并有界重试。修复后两 Pod 同时就绪，持续不兼容仍保持降级。 |
| 管理端 PostgreSQL 列绑定 | 候选版通过 API 新建列策略，再调用 `bind-postgres`。错误对象和多语句 SQL 均返回 409；正确的单表闭合绑定模式登记 3 列、6 条 output/reference 用途权限，策略修订为 2、绑定状态 `healthy`；旧 ETag 返回 412。真实 SQL 执行只由后续 MCP 请求触发。登记后重建一个 Pod，B2 仍为 active，允许/拒绝与审计 ID 54/55 通过。 |
| 双节点 MCP 安全链路 | 候选版两节点各自执行允许查询、未授权表 R010 拒绝和手机号脱敏，审计库持久记录 ID 49–52：`allow,deny,allow,deny`，每次允许响应脱敏 2 个单元格。无状态 MCP 响应不发会话 ID。 |
| 合成短时容量与审计一致性 | 两节点各接收 8 条并发度 4 的允许查询，16/16 返回 `allow`、每条脱敏 2 个单元格，合计 1.88 秒、观察吞吐 8.53 QPS、p50 437.0 ms、p95 547.0 ms。响应的审计 ID 72–87 全部唯一；独立 audit 库查得 16/16 唯一记录，决策均为 `allow`。原始记录保存在验收主机 `D:\CodexLS\outputs\agentsql-v200\capacity-*.log`。这是单次短时合成观测，不是持续负载或生产容量承诺。 |
| 单节点故障 | cordon 一个工作节点并停止其 Pod 后，EndpointSlice 仅保留另一个 Ready Pod；经 Service 的允许/R010 拒绝、脱敏及审计继续通过（ID 19/20）。恢复节点后原 Pod 用原 PVC 重新就绪。 |
| 依赖故障关闭 | 停止独立 audit 库时受控查询返回 `error` 且不交付结果；恢复后再次允许/拒绝并写入审计 ID 22/23。停止 metadata 库时初始化返回 HTTP 401，B2 租约降级；恢复库后重建两个 Pod，双节点重新就绪。 |
| 身份与租户 | 轮换测试 Agent Key 后，旧 Key 在两节点均 HTTP 401；新 Key 在两节点均通过安全链路（审计 ID 43–46）。另一个租户的管理员读取原租户数据源返回 404，其 Agent 借用原数据源的 MCP 查询未得到数据。 |
| 升级和回退 | 由于 B2 严格比较二进制摘要，混合 v1.9.0/v2.0.0 的滚动更新会挡住新 Pod；清单已改 `OnDelete` 并采用维护窗口停双副本、等待租约到期。正式 v1.9.0 镜像回退后两 Pod 均通过安全链路（审计 ID 35–38），再切回 v2.0.0 候选并通过（ID 41/42）。 |

边界：固定两个网关和指定 PG18/kind 拓扑；业务库是合成数据，未取得客户真实并发负载、生产网络、外部 TLS 或 PostgreSQL HA 证据。B5 跨请求事务、状态会话和事件续传在此双网关配置关闭；QPS 是每节点预算，非全局强一致配额。PostgreSQL 原生扩展模式的管理端列登记仍不支持，登记 API 只覆盖闭合绑定模式的单张普通表。
