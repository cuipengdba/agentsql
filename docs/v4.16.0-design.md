# AgentSQL v4.16.0 · 行列授权、脱敏与并发隔离

**语言 / Language** [简体中文](v4.16.0-design.md) · [English](en/v4.16.0-design.md)

本版目标是在真实 PostgreSQL 上，将 AgentSQL 自有问数与独立 MCP Server 安全网关的行限制、列授权和结果脱敏放到同一个流程中验证。固定 SQLBot Community v1.10.3 问数矩阵新增验收 Q5、Q6。两个场景全部通过并复测此前场景后，目标为 16/25（64%）。[评分合同](sqlbot-community-chatbi-score-v1103.md)

## 授权边界

问数以当前用户、工作空间和个人数据源绑定确定可用范围。模型读取授权结构并生成 SQL，网关绑定真实数据库对象，检查当前列权限，执行受控查询，在释放结果前完成脱敏和审计。验收使用已激活的 B2 PostgreSQL 列授权及隔离合成库。

测试分别观察 ChatBI 行规则和网关列、脱敏策略的变化。权限收紧时核对在途响应、历史、导出和重启后的读取行为。对两个普通用户并行发起的请求，按各自授权比较结果、会话和审计。

## 验收场景

| 场景 | 验收条件 |
| --- | --- |
| Q5 行列权限与脱敏 | 真实模型询问合成订单。只允许当前地区和授权列，邮箱按当前规则脱敏。验证在途撤权以及旧结果重开和 CSV、Excel 导出的拒绝路径。 |
| Q6 并发问数与隔离 | 两个不同权限的普通成员通过固定原版客户端同时提问。各自结果、历史和当前授权一致。一方撤权时，另一方保持受其当前授权约束。重启后复测。 |

记录数据库和模型版本、实际列授权模式、通过的入口、审计编号和测得延迟。正式验收以同一发布提交、同一签名包的结果为准。ARM64 仿真和用户真实业务系统的验证状态须在发布说明中明确。[发布流程](RELEASE_ROUTINE.md)
