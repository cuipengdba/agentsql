# AgentSQL v4.12.0 历史与导出的当前授权闭环

## 目标

AgentSQL 继续提供独立 AI 问数 Agent 与独立 MCP Server 数据库安全网关。本版以正式 v4.11.0 为基线，聚焦历史重开、文件导出和会话生命周期，减少已有正向能力与完整验收之间的缺口。固定 SQLBot Community v1.10.3 的 25 场景合同保持不变；v4.11.0 的严格基线为 Q1、H1、I1，共 3/25（12%）。

## 交付范围

- CSV/XLSX 导出在受控重查、文件编码和持久收据写入之后，再复核当前身份属性、行列权限、数据源绑定和会话修订。任何变化或验证故障均不发送文件字节；收据表示准备导出的尝试，不证明客户端收到文件。
- 使用未修改原版中文页面和 AgentSQL 自有中文页面验证历史、下载与会话删除。错误后不保留可继续操作的旧结果；可读结果始终来自当前受控网关。
- 在最终同一签名包复验真实本地模型、PostgreSQL 和受控网关的 Q1/H1/I1，并完成 H2/H3/H4 的适用正负矩阵。只有完整通过的场景计分；未完成项继续为零。

## 安全与验收

1. 确定性回归覆盖导出收据提交时行规则、列规则、身份属性变化，CSV/XLSX 均不得释放旧文件；审计或收据写入失败同样关闭。公式样式文本保持字面值。
2. 重启后首个历史和首个导出分别记录；两种页面的行值、文件内容、受控审计一致。另一用户、另一工作空间、成员禁用、规则变更、数据源撤销、会话删除后拒绝旧历史、导出或追问。
3. 记录真实模型/数据库版本、资源和原始退出码；不把单次耗时称为生产 p95。原版 SDK、基本与 Type 4 嵌入保留有界回归，不扩大数据库支持等级。
4. 最终精确提交五项 CI 成功，正式生产签名资产和外层离线包独立验签；AMD64 与 QEMU ARM64 分别断网新装、从正式 v4.11.0 升级和首次启动故障回滚。
5. 发布 GitHub Release、GHCR 精确标签并匿名回拉；官网和明示模拟的 Demo 更新、公开烟测通过后提升 latest。规范主仓库 main 同步 origin/main 且干净。

## 边界

本版不承诺 80% 兼容、复杂关联 SQL、云模型真实推理或任意数据源创建。未在用户真实业务系统验证，不宣称零改动切换。QEMU ARM64 不代表 ARM 实机；公网问数 Demo 使用模拟结果。
