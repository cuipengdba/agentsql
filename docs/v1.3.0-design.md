# AgentSQL v1.3.0 MySQL 列策略 SELECT 子集设计

## 目标与承诺边界

在 v1.0.0 已有的“列策略遇到不支持的 MySQL 路径即拒绝”基础上，为 MySQL 8.0 与 8.4 增加一个**默认关闭、明确限定语法**的列级授权执行路径。只有能在同一业务连接中证明对象、字段引用、列策略、脱敏计划和执行对象一致的语句才能放行。其他 MySQL SQL 继续失败关闭并写审计；不把本版称为 MySQL 全方言列级授权。

## 首批可执行语法

- 单条 `SELECT`，只引用当前数据源中一个显式命名的 InnoDB 基础表。可选单一表别名。投影必须是明确的基础列引用，可用唯一的输出别名。
- `WHERE` 限定为受支持列与常量的比较、`IS [NOT] NULL`、有界 `IN`、这些谓词的 `AND`/`OR` 组合；`ORDER BY` 只接受带表名或表别名限定的基础列，避免 MySQL 输出别名遮蔽；`LIMIT` 为有界非负整数。现有 MCP 查询入口没有 SQL 参数数组，首批不承诺外部绑定参数。
- 每个投影、谓词和排序列都进入统一的列使用集合。表权限、列权限、Agent 权限、规则、脱敏、行数/时间/响应预算、审计与最终控制面 fence 均照常执行。
- 不满足全部条件时执行前拒绝：`*`、跨表 JOIN、子查询、CTE、UNION、视图、派生表、生成列、表达式投影、函数/UDF、JSON_TABLE、用户变量、窗口/聚合、锁定读、优化器 hint、语句堆叠及未证明的方言扩展。后续扩大子集需要新的真库证据。

## 证明链

1. 只在 `column_authorization.enabled: true` 且新开关 `column_authorization.mysql_single_table_enabled: true` 时允许 MySQL 数据源进入新路径；静态 AST 检查先将语句归入可证明子集，未知 AST 节点拒绝。现有表级路径不因新功能自动升级。已有列策略但开关关闭时仍拒绝。
2. 为每次请求创建并关闭**新的物理连接**，避免历史会话临时表遮蔽基础表；使用业务只读凭据在该连接上开启只读事务，绑定目标基础表并读取精确列元数据。确认版本、存储引擎、对象类型、列定义及大小写模式；不依赖单独 inspector 的“看起来相似”的目录结果。必须通过并发 DDL 实验证实元数据锁覆盖从预绑定到执行、Fpost 的整个窗口；若不能证明，则本版不开放该语法形状。MySQL 的 `INFORMATION_SCHEMA.INNODB_TABLES.TABLE_ID` 可提供表 ID，但读取此表需要实例级 `PROCESS` 权限；不向业务查询账号静默授予此权限。若使用独立元数据账号，必须证明它读取的 ID 与业务事务持有 MDL 的对象相同，并把该账号与数据库实例身份纳入部署合同。
3. AST 中每个列引用须唯一绑定到当前基础表的普通列；未知列、歧义列、生成列和目录不一致均失败关闭。形成规范化的对象/列身份、使用位置、输出位置及 Fpre 摘要，交给列策略与身份脱敏计划。拒绝也必须在受控业务事务结束后留下持久审计。
4. 在同一连接和事务上执行**原语句**，限时限行，返回后重读目录形成 Fpost。Fpost 与 Fpre 不一致、事务关闭失败、控制面快照失效、审计失败或最终 fence 失败均不得把结果交付给客户端。提交数据前不释放锁；事务结束后才执行控制面审计与最终 fence。
5. 审计必须包含 SQL 决策、对象/列身份、拒绝原因、Fpre/Fpost 和最终交付状态，不保存原始敏感结果。单实例/多实例共享的控制面故障继续沿用既有 fail-closed 行为。
6. 为 MySQL 列策略提供可操作的两阶段登记：先从真库发现基础表和列，控制面在第二次真库复验通过后封存表 ID、目录指纹、列序号与类型；策略编辑和执行都必须读取同一租户下已登记的身份。现有通用列权限数据结构不能把人工填写的列名或旧 CSV 自动当成已登记权限。

MySQL 身份探针凭据按数据源 ID 在 `column_authorization.mysql_metadata_accounts` 中显式配置账号名与密码环境变量名。该账号只负责读取 `INNODB_TABLES.TABLE_ID`，业务查询继续使用数据源的只读凭据；启动探针必须验证两种凭据确实连接同一个 MySQL 实例 UUID。缺少凭据、缺少 `PROCESS`、实例不一致或账号误带业务写权限时该数据源失败关闭。配置不保存明文密码，不把元数据账号借给业务 SQL。

## 验收门槛

| 类别 | 必须通过 |
| --- | --- |
| 语法矩阵 | 支持的单表 SELECT 与所有列使用位置逐项通过；上述排除语法全部在业务 SQL 前拒绝。 |
| 策略登记 | 真库发现、二阶段复验、管理员配置、策略修订及吊销；同名表重建、列位置或类型变化后必须失效。 |
| MySQL 真库 | MySQL 8.0 与 8.4 的受限账号、列允许/拒绝、脱敏、真实 MCP 调用和持久审计；记录精确镜像 digest 与服务器版本。 |
| 竞争与故障 | DDL 与查询并发、列更名/删除、权限撤销、目录不可用、事务/连接失效、审计不可用、控制面最终 fence 失效均不得泄露数据。 |
| 兼容与升级 | 不含列策略的既有 MySQL 路径、PostgreSQL B2 与其他数据库保持既有行为；从 v1.2.0 正式包做 SQLite 与 PostgreSQL 分库升级/恢复。 |
| 交付 | Go/Web/安全 CI，签名发行物，GHCR 精确版本双架构匿名拉取，GitHub 正式 Release；官网、公网 Demo 与 `latest` 继续保持 v1.0.0。 |

任何一条真库证明或故障关闭门槛失败，就维持 MySQL 列策略原有拒绝状态，不以放宽语法或回退表级授权来换取发布。

MySQL 的只读事务及 metadata lock 设计依据：[MySQL 8.0 START TRANSACTION](https://dev.mysql.com/doc/refman/8.0/en/commit.html)、[MySQL 8.0 Metadata Locking](https://dev.mysql.com/doc/refman/8.0/en/metadata-locking.html)、[InnoDB TABLE_ID 与 PROCESS 权限](https://dev.mysql.com/doc/mysql-infoschema-excerpt/8.0/en/information-schema-innodb-tables-table.html)。能否满足本版证明链仍以真库并发实测为准。

2026-10-18 的隔离 MySQL 8.0.46 与 8.4.11 探针均确认：只读账号不能读取 `TABLE_ID`；持有 `SELECT ... LIMIT 0` 的显式只读事务令并发 `ALTER TABLE` 等待至事务结束；同名表重建产生新 `TABLE_ID`。这些只验证原语，尚未构成 AgentSQL 请求级安全链路。
