# v3.6.0 跨环境策略交付操作草案

**语言 / Language:** [简体中文](v3.6.0-policy-transfer.md) | [English](en/v3.6.0-policy-transfer.md)

此流程目前只适用于现有原子应用支持的精确表名、简单表级 allow/deny 规则。源快照若含通配表名、列授权、关系绑定、行过滤或旧版不可表达规则，签名命令会拒绝。交付包没有数据库凭据和业务数据，但包含资源标识与权限范围，应按敏感配置文件保护。

1. 在源环境以有权限的管理员身份调用 `GET /api/v1/policy-bundles/current`，将完整 JSON 响应保存为 `source-snapshot.json`。在网关以外生成专用 Ed25519 密钥：

   ```sh
   agentsqlctl policy-transfer keygen --private-seed-out transfer-seed.hex --public-key-out transfer-public.hex
   agentsqlctl policy-transfer sign --snapshot source-snapshot.json --source-environment staging --private-seed-file transfer-seed.hex --out transfer.json
   ```

   私钥只留在可信源操作端；目标操作端通过独立可信渠道核对 `transfer-public.hex` 的 SHA-256 指纹后获取公钥。不要复用 AgentSQL 正式发布签名密钥或审计 checkpoint 密钥。

2. 在目标环境保存新的 `GET /api/v1/policy-bundles/current` 完整响应为 `target-snapshot.json`。人工创建目标映射文件：

   ```json
   {
     "target_tenant": "target-tenant-id",
     "agents": {"source-agent-id": "target-agent-id"},
     "datasources": {"source-datasource-id": "target-datasource-id"},
     "policies": {"source-policy-id": "new-or-existing-target-policy-id"},
     "objects": {"source-policy-id": "target_schema.target_table"}
   }
   ```

   每个源策略都必须有唯一目标策略 ID 和显式目标表。已有目标规则只允许简单表级规则；没有提到的目标规则保持原状，不会被删除。管理员必须核实映射后的 Agent、数据源和业务表是预期资源。

3. 离线验签并生成现有管理 API 可用的提案输入：

   ```sh
   agentsqlctl policy-transfer plan --transfer transfer.json --target-snapshot target-snapshot.json --mapping mapping.json --public-key-file transfer-public.hex --source-environment staging --out proposal.json
   ```

   先将 `proposal.json` 送入目标环境 `POST /api/v1/policy-bundles/plan` 查看受影响范围，再送入 `POST /api/v1/policy-bundles/proposals`。随后按既有流程由另一位管理员审核，再由操作员应用。目标 API 会重新核对租户、资源存在性和当前策略摘要；离线结果不能代替实时检查。签名包默认 7 天有效，过期需重新导出。

4. 应用后重新下载目标快照，核对摘要和策略范围，并通过网关实际请求分别验证允许、拒绝、脱敏及持久审计。遇到错误应修正映射后重新规划；不要放宽规则来通过预检。

此操作草案不提供自动跨环境同步、列级规则迁移或静默策略删除。
