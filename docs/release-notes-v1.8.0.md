# AgentSQL v1.8.0 发布说明

v1.8.0 深化 Vastbase G100 V3.0 Build 9 的 PG 兼容、受限只读路径。控制台和管理 API 现在可以为独立的 `vastbase` 数据源保存 `verify-full`、CA 文件与证书主机名，在指定隔离实例验证服务端身份。该能力仅适用于验收记录中已测的 Build、协议模式、账号和单实例拓扑；不代表完整生产支持。

## 新增与改进

- 管理 API 为 Vastbase 显式 TLS 配置校验模式、CA 绝对路径与主机名，并拒绝未验证的服务端证书。控制台新建 Vastbase 数据源默认引导 `verify-full`，明确显示有界 SQL 与部署约束。
- 保持单条、显式 schema、单表、带有效 `WHERE` 和 `LIMIT` 的直接列投影 SELECT；数据库连接仍逐次校验 G100 Build 9、`sql_compatibility=PG` 和只读事务状态。表级授权、脱敏和持久审计仍按原安全链路执行。
- 指定隔离实例的 CA 和主机名校验通过；错误 CA、错误主机名以及通过 HBA 禁止明文连接的负向用例通过。证书轮换后重新连接成功；只读账号凭据轮换后旧密码被拒绝。
- 控制台数据库类型名称与真实验收范围一致，避免将已验收的指定版本标为完全未测。

## 部署要求与兼容边界

- 使用最小权限的只读数据库账号，在网关侧提供可信 CA 文件的绝对路径，并将证书主机名与服务端证书匹配。隔离实测采用 G100 `ssl=on`、证书和私钥 `0600` 权限，以及先于普通 `host` 规则的 `hostnossl ... reject` 规则。
- 指定 Build 9 在 `require_ssl=on` 时拒绝当前 pgx 驱动的协议 3.0 启动包，即使 TLS 握手已完成；本版验证的配置为 `require_ssl=off` 加账号专属明文拒绝规则。其他 Build 与驱动组合须重新验证。
- 旧数据源的空 TLS 模式仍可读取，以免无迁移地中断既有安装；管理员应显式改为 `verify-full` 后做证书和明文拒绝验收。显式 `disable` 只用于受控隔离环境。
- 实测许可为 BASIC/VECTOR 临时许可，有效期至 2027-01-12。正式生产许可、主备高可用、故障切换、厂商认证、其他 Build/模式与生产负载尚未验证，不纳入支持声明。PostgreSQL B2 列级绑定和 B5 跨请求事务也不扩展到 Vastbase。
- 本版无 metadata/audit schema 迁移；从 v1.7.0 正式包升级时仍须备份 metadata、audit 与密钥，并按[发布验收](v1.8.0-acceptance.md)复核恢复。

设计与负向用例见[设计说明](v1.8.0-vastbase-design.md)。最终封版、真库客户端、正式资产、官网和 Demo 证据见[验收记录](v1.8.0-acceptance.md)。
