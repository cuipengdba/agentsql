# v4.5.0 页面与定位验收矩阵

[中文](v4.5.0-page-parity.md) | [English](en/v4.5.0-page-parity.md)

状态：验收范围，尚未完成。以下大部分浏览器证据以 [SQLBot 社区版 v1.10.2](https://github.com/dataease/SQLBot/releases/tag/v1.10.2) 的未修改本机镜像为固定基线；[v1.10.3](https://github.com/dataease/SQLBot/releases/tag/v1.10.3) 已于 2026-10-29 发布，已开始该版本的原版客户端与行为差异验收，但还不能形成“最新版全面兼容”结论。以下记录的是 2026-10-26 起实际可见入口和流程；每个入口仍须继续补齐操作、响应、权限和错误行为的对照用例。AgentSQL 界面独立设计和实现，不复制原产品的页面代码、图标或品牌。

### 最新社区版增量：v1.10.3

本机获取的原版 tag 为 `96f06c7`，原版镜像摘要为 `sha256:ff9012a95e6ac0e7921aa74e96c73de33550af61615fe850edb27b322c342288`。相较 v1.10.2，源码差异未增加或删除公开 API 路由装饰器，但改变了现有接口与页面行为。X-Pack 独有内容单独记录，不计入社区版对照。以下各项仍须独立验收，不继承 v1.10.2 的通过状态。

| 变化面 | v1.10.3 公开变化 | AgentSQL 需要复核 |
| --- | --- | --- |

| 其他社区能力 | Hive SparkThriftServer 元数据、Doris/StarRocks 连接参数、SQL Server 字符编码及语言提示改动 | 各数据库真实连接/结构/查询与原版多语言页面；只按真实通过组合声明支持 |

对照 v1.10.3 的 `extract_nested_json` 修复后，候选版的 OpenAI 兼容模型 SQL 生成路径现在从附带说明或 Markdown 代码块的输出中取**第一个完整且有效的外层 JSON**；字符串里的花括号与转义引号不破坏边界。无效外层对象内的子对象、截断对象和第一个有效但没有 `sql` 的对象都不能被提升为后续 SQL。官方 v1.10.3 未修改镜像内的原版 JSON 提取测试实际运行 34 项通过；候选版定向模型 HTTP 测试覆盖上述正反例，生成 SQL 仍进入现有受控查询校验。此变更只覆盖该模型 SQL 生成路径；原版浏览器中的其他 JSON 消费路径、真实模型异常输出与逐请求对照仍待验收。

独立启动官方 v1.10.3 镜像的原版 API 和空数据库后，运行时确认公开 `/system/parameter/login` 只有 `login.initial_pwd_disabled=false` 与 `login.initial_pwd_hidden=false` 两项；管理员参数列表也只有这两项登录参数。原版管理员以完整表单记录保存禁用开关返回 200，公开读取变为 `true`；随后已登录 `/user/pwd` 和登录阶段 `/login/change-pwd` 尝试把密码设为配置初始密码都返回 400。候选版现把公开登录参数调整为同样的两项默认值，并以原版完整表单记录形态通过管理员保存、公开读回、两种改密拒绝和 MCP 凭据登录拒绝的本地服务端测试。该证据是原版 API 与候选版夹具的分别运行；下段另记原版登录页的浏览器测试。

随后使用**未修改的 SQLBot v1.10.3 登录页面**连接当前候选二进制与隔离控制库：管理员通过原版页面登录，候选 API 以原版完整表单记录开启初始密码禁用；新建一名合成普通用户。该用户以配置的初始密码登录时，原版页面弹出“修改初始密码”对话框，未发放登录令牌；再次把新密码填成初始密码，原版页面实际发出的 `/login/change-pwd` 返回 400 并显示拒绝提示。改填符合要求的新密码后，同一路径返回 200，页面显示修改成功，再次登录进入问数页。验收快照保存在 `D:\CodexLS\tmp\agentsql-v450-password-v1103\.playwright-cli`。此证据仅覆盖一名合成普通用户和一个本机密码策略；原版管理页没有展示该开关的操作控件，其他密码格式、账号状态、错误文案、自助改密页面、原有业务账号与 MCP 原版客户端对照仍待验收。

2026-10-30，从上述原版 v1.10.3 镜像直接提供未修改的前端静态文件，通过仅用于验收的本机代理连接 AgentSQL 候选 API 和隔离控制库副本。原版页面完成管理员登录、本地 CSV 上传、两行预览、单表选择、数据源保存、表结构与数据预览；列名 `123` 在导入预览、保存后的结构和读取结果中均保持原样，`amount` 显示数值类型，两行值为 `east/10` 和 `west/20`。数据由本机真实受控 PostgreSQL 网关读取；测试数据源随后经受控删除接口移除。原版页面快照保存在 `D:\CodexLS\tmp\agentsql-v450-sqlbot-v1103\.playwright-cli`。这只验收 CSV 和一个数字列名；不等于 v1.10.3 的 Excel 备注导入、`.xls`、50 MiB、所有页面、真实模型或业务系统零改动切换已通过。

针对 v1.10.3 的 Excel 数字字段名修复，先以真正的数值单元格 `123` 构造 XLSX 备注文件，经原版形态的 `uploadDsSchema` 接口导入后，当前网关可见字段 `123` 的备注保持为 `Numeric field`；随后补做以下原版页面对照。针对 MCP 工作空间变更，新增服务端负向回归：在成员可访问空间 2 时创建 MCP 会话，然后撤销该成员身份，旧会话提问返回 `404`，且网关结构和查询调用均为零。两项 Go 定向测试均通过。另补同一空间的跨用户旧会话负向测试：另一个有效用户以原版 `mcp_question` 请求形态分别请求 JSON 和流式回答，均返回 `404`，网关结构与查询调用仍为零，响应未包含问题或数据。这些是合成服务端夹具，原版 MCP 客户端的流式、跨空间、跨用户及撤权对照仍待完成。

对照 v1.10.3 原版 `mcp_question` 的非页面流式代码后，候选版把受审计查询结果由原先的 JSON 文本行改为按字段顺序输出 Markdown 表格；空结果给出明确提示。服务端定向测试验证两列真实形态数据的表头和行，并检查带链接、竖线、HTML 与换行的网关值不会变成可执行 Markdown/HTML；返回仍须先通过当前身份、网关审计和本地持久化。这里是源码形态对照与合成夹具测试，尚未取得 v1.10.3 原版 MCP 客户端逐字节流事件、图像与错误分支的运行证据。

用官方 v1.10.3 镜像启动独立原版 API 与空 PostgreSQL 数据库，实测 MCP 辅助接口发现此前兼容响应形态有误：`access_token`、`mcp_start`、`mcp_ds_list`、`mcp_model_list` 和 `mcp_ws_list` 的成功 JSON 均由原版中间件封装为 `code/data/msg`，`mcp_question` 则直接返回 JSON 或事件流。原版 `mcp_ws_list` 的令牌是 URL 查询参数，放在 JSON 字符串请求体返回 422；使用查询参数返回 200。候选版现为上述辅助接口使用原版成功封装，同时在 `mcp_ws_list` 接受原版查询参数和原有 JSON 字符串请求体；拒绝重复查询令牌、额外参数、畸形查询、同时携带查询令牌和实体或头凭证，并给查询参数响应设置 `no-store` 和 `no-referrer`。服务端夹具通过合法、撤销和冲突用例。随后用当前候选二进制、隔离控制库副本和真实本机网关运行 HTTP 对照：登录、会话开始、查询参数空间列表、数据源列表及模型列表均返回 200 的原版封装；测试副本读到 2 个工作空间、7 个可见数据源和 1 个模型，实体令牌旧形态也返回 200，冲突凭证返回 422，匿名模型列表返回 401。两侧测试容器均已停止，原版数据来自空实例，不能把列表内容视作逐条相同。查询令牌仍可能被前置代理记录，正式部署必须验证 HTTPS 和访问日志脱敏。原版空实例中匿名 `mcp_model_list` 可返回空目录，候选版坚持要求有效令牌；这是仍未关闭的零改动兼容差异，不能以匿名枚举代替安全验收。原版空实例没有模型和数据源，问数只得到错误分支，不能证明成功问数形态。

候选版另接入 SQLBot 原版 MCP 客户端所用的旧式 HTTP+SSE `/mcp` 传输；SSE 握手不授予数据权限，六个已实现工具逐次调用同一受控 ChatBI 路由。该次验收时 `mcp_assistant` 因原版内置虚拟用户无法安全映射而暂不暴露；后续单数据源受控实现见下文。MCP 会话数限制为 16，单连接最多 10 分钟，拒绝跨来源浏览器请求。Go SDK 的 SSE 客户端测试通过工具发现、登录态空间列表、受审计问数、无效令牌及缺失网关审计的拒绝。随后从**官方 v1.10.3 镜像直接运行未修改的 Python MCP 客户端库**，连接隔离候选服务与本机真实模型、受控 PostgreSQL 网关：发现六个工具，`mcp_start` 和空间／数据源／模型列表成功；无效令牌问数被拒绝；以数据源 `11` 分别做非流式和流式问数，两次均成功返回两行，流式内容含记录号和 Markdown 表格。原版客户端保持同一 SSE 会话时，注销令牌返回 HTTP 200，随后的问数及空间列表调用均返回 MCP 工具错误，证明已建立传输连接不能继续使用被撤销的登录态。同一隔离副本中新建验收用户并授予两个空间，在空间 1 建立会话后撤销其空间 1 成员资格；旧令牌问数、新令牌针对旧会话的 JSON 及流式问数均返回 MCP 工具错误。只输出汇总形态，未复制原版服务代码到产品。此证据覆盖一个管理员、一个验收成员、一个 PostgreSQL 合成表及两种问数传输，不覆盖 `mcp_assistant`、匿名模型列表、MCP 图像、其他跨空间／跨用户场景、其他数据库或业务系统零改动切换；SSE 部署端口及前置代理配置也须正式验收。

候选版新增可选的 `legacy_mcp_listen` 独立监听端口；发行示例给出回环地址 `127.0.0.1:8001` 的可选配置（默认不启用，避免占用本机模型端口），该端口只转发 `/mcp`。隔离服务用端口 8001 接入官方 v1.10.3 未修改 Python MCP 客户端，六工具发现、真实模型与 PostgreSQL 问数、跨用户、成员撤权和注销负向用例再次通过；同端口请求普通 API 得到 404。公网入口、TLS、反向代理、端口占用、正式离线安装及业务系统原有地址的直接切换仍须验收。

迁移基础路径现对 v1.10.3 单独固定源码提交、登录与密码策略文件哈希、用户和安全模块哈希、聊天模型哈希及 X-Pack 依赖版本。官方原版隔离空实例实测导出一名用户；未修改的原版浏览器完成登录后，Go 预检、身份导入、加密凭据解密、本地登录及原版令牌验证均通过。原版历史导出脚本在只读事务中可运行，但该空实例没有会话；真实用户历史和完整资源迁移仍待验收。私有导出文件和登录夹具在测试后已删除。

另在一次性官方 v1.10.3 原版实例中，使用原版 ORM 写入一条明确标记的合成会话及问题；只读历史导出器得到 1 个会话、1 个问题、零跳过。Go 私有夹具测试完成版本预检、导入、当前授权读取，确认旧 SQL、结果行和模型请求均未重放。原版容器与私有导出文件已删除。该结构验收使用合成数据库记录，尚不能证明真实业务历史、图表或权限关系迁移。

同一原版 MCP 客户端和 SSE 会话中，空间 1 的第二用户尝试读取管理员已有会话，JSON 与流式 `mcp_question` 均返回 MCP 工具错误。该负向验收只覆盖同一工作空间的跨用户旧会话，其他会话共享和跨空间组合仍待逐项对照。

同日补做 v1.10.3 原版页面对照：使用隔离控制库副本与真实受控 PostgreSQL 网关，通过兼容 API 准备数字列名 `123` 的测试数据源，然后在**未修改的原版“导入备注”页面**选择真正把字段名单元格存为 Excel 数值 `123` 的 XLSX。页面请求 `uploadDsSchema` 返回 200 并显示“Import Successful”；打开表结构后，表备注显示 `Numeric header table`，字段 `123` 的备注显示 `Numeric field from original page`，整页刷新并重新进入后两项仍存在。测试源随后经受控删除接口移除。原版页面快照保存在 `D:\CodexLS\tmp\agentsql-v450-sqlbot-v1103\.playwright-cli`。该证据关闭一个数字字段名的原版页面路径，不覆盖其他备注模板、`.xls`、备注导入中途撤权、并发导入或所有数据源类型。

另一个 v1.10.3 原版页面负向对照使用独立控制库副本：先打开已绑定 PostgreSQL 数据源 `11` 的真实预览，显示 `east/10`、`west/20`；再仅在副本中移除该数据源别名。旧页面再次切换表结构与数据预览时，服务端 `fieldList` 和 `previewData` 均返回 `404`、未发出新的数据行，但**原版浏览器仍把先前缓存的两行预览留在页面上**，只显示短暂的“Resource not found”提示。整页刷新后，该数据源卡片及缓存行消失。此结果证明新请求在服务端故障关闭，也明确暴露原版客户端的已渲染数据清理缺口；不能声称撤权后客户端即时清屏。测试只改变隔离副本，规范验收实例和真实网关保持原状。

AgentSQL 自有双语数据源页面据此调整：每次重新进入数据源列表时，先清除旧卡片、详情、字段和预览 DOM，再请求当前授权列表；请求失败只显示错误状态。用新构建候选服务和另一份隔离 PostgreSQL 控制库先展示两行真实预览，随后在副本中移除该数据源别名并停止**仅供验收的候选 API 容器**，模拟列表请求无法完成。点击“Datasources”后，旧数据源名和 `east/10`、`west/20` 均从页面消失，状态提示请求未完成。该结果验证下一次导航/刷新时的清理，不代表服务端能主动抹去用户已经看见的像素，也不改变原版 SQLBot 客户端的缓存行为。快照在 `D:\CodexLS\tmp\agentsql-v450-own-ui-revocation\.playwright-cli`。

## 两种产品形态

| 形态 | AgentSQL 的责任 | 对外表述的验证条件 |
| --- | --- | --- |
| SQLBot 安全网关 | 保留现有 SQLBot 问数界面，业务数据库只经 AgentSQL 做身份映射、表列/行规则、只读执行、脱敏与持久审计 | 原版 SQLBot 与真实数据库在隔离环境通过允许、拒绝、撤权、脱敏、故障关闭和审计链；说明适配版本与已验证数据库 |

官网、GitHub 和 AgentSQL Web 应用同一套准确说明：AgentSQL 是独立实现的数据库安全与问数产品，可作为 SQLBot 的安全网关，也可独立提供问数能力。只有上述两种形态分别通过验收，才能宣称对应能力；“现有业务系统零改动替换”另需用户实际隔离环境的前后对照证据。页面、代码和素材保持 AgentSQL 自有品牌，当前发行版授权说明只呈现 Apache-2.0。

原版源码标为未使用的 `POST /api/v1/datasource/fieldEnum/{ds_id}/{field_id}` 现有受控兼容入口：字段 ID 只从当前网关可见且已启用的表字段推导，执行带模式限定的只读有界查询，最多返回 100 个值，并要求审计号与返回前绑定复核。PostgreSQL 由网关执行 `DISTINCT`；MySQL 列级闭合授权不接受该查询形状，改为读取最多 100 行授权列，再在服务端去重，因此可能遗漏前 100 行之外的值。合成网关定向测试覆盖 PostgreSQL/MySQL 引号、MySQL 去重、错误数据源及字段 ID、字段从实时结构消失、网关故障、审计缺失和查询期间撤权。独立候选服务连接现有本地 PostgreSQL 网关，在合成 `sqlbot_parity_sales.region` 字段实际返回两个去重值，HTTP 200；服务端要求网关响应携带正数审计号。MySQL 隔离副本最初缺少测试 Agent 的数据源策略，`list_schema` 被拒绝；通过管理 API 配置 `agentsql_demo.orders` 的表列策略并绑定真实列后，表结构读取通过。旧版候选的 `SELECT DISTINCT` 在实际查询时返回 `AUTH_COLUMN_SHAPE_UNSUPPORTED`；重建候选使用有界单列投影，HTTP 200，返回 4 个去重值，网关 `query` 决策为 allow 且附带正数审计号。这只证明本机合成 MySQL 表的一个字段；原版客户端调用和更广范围的 MySQL 行为仍待对照。原版接口无此 100 值上限；此安全边界属于待记录的行为差异。

隔离 MySQL 撤权负向验收还发现：旧网关在删除列策略、保留表级 allow 后会回退到表级授权，旧 `fieldEnum` 请求仍返回值。候选版在同范围表级 allow 存在时对列策略删除返回 409；先删表级 allow 再清理列策略后，原字段请求返回 403、不带值，网关最新审计为 deny。进一步复现旧网关通过 `PUT` 把列策略改为表策略同样扩大授权：更新返回 200，旧字段请求仍返回 4 个值。新候选对该危险更新返回 409，原列绑定仍可读取 4 个值；先删除表级 allow 后，字段请求返回 403、无值，最新审计为 deny，此时管理员可显式更新剩余策略。结果仅覆盖一个合成表的管理 API 删除与更新顺序；其他更新字段组合、多表撤权和原业务系统切换仍待验收。

### 原版小助手 SDK 的身份合同

固定基线的 SDK 会把 `assistant_id`、时间、网页来源、浏览器标志、User-Agent 和时区组成 JSON，用公开的 `/api/v1/system/config/key` RSA 公钥加密后提交 `SQLBOT-EMBEDDED-SIGN`。公钥加密只允许服务端读取请求内容；任何拿到公钥的人都能生成该请求头，网页 `Origin` 也可由非浏览器客户端自行填写。因此，解密、十秒时间窗、域名匹配和浏览器属性检查都不能证明业务用户身份，也不能单独作为发放问数令牌的依据。

接入实现分两种服务端授权模式。已有业务用户的私有数据模式必须通过可信宿主服务以应用密钥或已验证用户会话签发短期授权，绑定应用、工作空间、业务用户、数据源与令牌版本；浏览器传来的 `virtual` 或 `userFlag` 只作为显示参数。无需改动原版浏览器 SDK 的公开访客模式必须由管理员逐项显式开放数据源，并绑定无管理权限的专用访客身份及当前网关权限；该模式的数据应被视为对所有能发起网络请求的人公开，不能继承管理员或普通用户的私有绑定。当前管理 API 已可为基础型应用配置 `public_guest_user`，仅接受同空间启用的本地普通用户且该用户对应用列出的每个数据源都有独立绑定；创建时生成服务端密钥。内部验证器现可核验由该密钥签发、限定一小时内且含访客作用域的 `Assistant` 令牌，数据读取时还复核应用列表、访客身份、当前用户和数据源绑定；内部签发器现为每次调用生成随机访客作用域，并在令牌中绑定应用和访客账号版本；应用修改会令旧令牌失效。受限 `info` 现仅在应用显式指定公开访客、请求来源与原版 RSA 请求头通过校验时发放令牌；未配置访客的应用不会发放。此流程已有隔离服务端测试，并在本机未修改的原版 SDK 浏览器完成公开访客 `info` 握手；完整嵌入仍未验收。若部署没有安全的授权配置，`info` 必须拒绝发令牌。

每个访客会话由服务端生成不可猜测的独立标识，历史、图表和导出只对该标识可见。当前已给现有页面型嵌入令牌增加可选的 128 位访客作用域，并在会话读取、列表及最近问题中核验：同一应用、同一账号的两个作用域不能互读；旧版不含作用域的令牌保持原有隔离边界。公开访客的服务端标识生成与令牌发放已接入受限 `info`，但刷新后的安全会话延续和真实嵌入仍待验证。每次数据读取还须重新核验应用启用状态及版本、会话、用户或访客身份、当前数据源与表列行规则、网关执行和持久审计；撤销应用、用户、数据源或权限后旧令牌不能继续读取。高级型应用的宿主回调只能请求服务端预配置的 TLS 端点，带服务端凭证，拒绝浏览器指定地址和重定向。

验收需由未修改的 v1.10.2 SDK 分别完成公开访客与私有用户流程，并覆盖跨访客历史、伪造来源、过期或重放请求头、停用应用、撤权、模型或网关故障、审计故障及宿主回调失败。当前受限 `info`、公开访客令牌、数据源列表、展示设置和图片生命周期已有隔离 API 测试；访客停用或网关结构读取失败时，新增测试确认旧令牌无法继续列出数据源，网关故障前没有查询执行；令牌依据管理员显式发布的数据源与专用访客身份签发，RSA 解密结果本身不授予身份。原版 SDK 的 iframe 页面、刷新后历史、私有用户、回调与完整问数仍未验收，不能据此宣称 SDK 或业务系统零改动替换已通过。

本机另用未修改的 SQLBot v1.10.2 `assistant.js` 在隔离访客应用上完成浏览器对照：原版脚本实际请求公钥和 `info/{id}?virtual=...`，两次均返回 200，脚本创建了 `/#/assistant` iframe。随后浏览器因当前 AgentSQL 根页面的 `frame-ancestors 'none'` 安全策略拒绝加载该 iframe。这证明原版 SDK 的公开访客握手与令牌发放可以接通，但不证明页面嵌入可用。要保持管理页面防点击劫持，需为原版 SDK 所要求的根路径提供隔离的助手专用站点与受控嵌入策略，再完成 iframe 内的真实数据源、问数、历史和撤权对照；不能直接放宽管理页面的全站策略。

### v1.10.3 第三方数据助手 `mcp_assistant` 的安全兼容合同

因此仅增加同名路由或直接转发客户传入的 URL 和凭据，都无法成为 AgentSQL 的安全兼容实现。开发合同是：部署管理员先登记并批准精确的目录目标与其拥有者、工作空间、可用数据源及证书指纹；旧客户端请求形状保持不变，但入口凭据必须映射到可撤销的真实调用主体。出站只允许已登记的精确地址及其经批准的解析 IP/网段，禁止重定向、未经批准的内网或链路本地目标及 DNS 重新绑定；优先 HTTPS，现有业务确需私网 HTTP 时须由管理员显式批准并限制网络出口，不能为了兼容默认放行。限制响应大小、时间和目录字段。目录返回的数据库连接信息不得直接变成执行权限，必须逐项映射到已登记的 AgentSQL 受控绑定，由实时身份、成员资格、网关规则、审计和结果持久化决定能否问数。目录或映射不确定时拒绝，并且不得把凭据或原始连接信息写进日志、模型提示或响应。该合同仍需完整实现和原版业务客户端验证；候选已增加多已映射目录源的受审计模型选择；两个互斥选表范围的逻辑数据源已在本机验收，不同物理数据库之间的选择仍未验收。
