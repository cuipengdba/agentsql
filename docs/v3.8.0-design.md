# AgentSQL v3.8.0 设计：ClickHouse 资源预算与 Milvus 租户过滤

**语言 / Language:** [简体中文](v3.8.0-design.md) | [English](en/v3.8.0-design.md)

状态：开发中。本版只深化既有 ClickHouse 26.8.31.2 单节点与 Milvus 2.6.25 单机的指定受控只读路径，不扩大为完整生产支持。

## 用户任务与配置

管理员希望在不开放原生 SQL/表达式的前提下，进一步收紧分析查询的扫描预算，并在共享向量集合中按 AgentSQL 的权威租户 ID 限定命中。已有 `read_control_json` 元数据列承载两种可选配置，无需新增数据库迁移。

| 能力 | 合同 |
| --- | --- |
| ClickHouse `query_analytics` | `{"clickhouse":{"max_rows_to_read":1000,"max_bytes_to_read":262144,"max_memory_usage":33554432}}` 仅能收紧原有 10000 行、1 MiB 读取、128 MiB 内存上限；保留 2 秒、100 行输出和双线程上限，显式要求读取和结果溢出时抛错。表元数据最多读取 128 列。`{}` 保留旧版预算。 |
| Milvus `search_vectors` | `{"milvus":{"tenant_field":"tenant_id","filter_fields":["status","region"]}}` 为该数据源的每次单集合检索开启行级租户范围；租户值来自已重新认证的 Agent，不出现在 MCP 参数或管理员 JSON 中。调用者至多提交四个经管理员批准的 String/VarChar 等值过滤值，不可提交原生表达式。租户字段、向量字段、输出字段与过滤字段均须有当前精确列授权。网关生成固定布尔表达式，并重新核对每条命中的租户及过滤字段；内部校验字段不进入 MCP 结果。`{}` 保留旧版仅控制面租户隔离的路径，不能声明行级租户隔离。 |
| 管理与兼容 | 数据源保存时拒绝宽松预算、未知字段、跨数据库配置、凭据嵌入、未验证 TLS、Milvus `root` 账号。现有不带配置的数据源及 MCP 请求保持兼容。 |

ClickHouse 的自定义预算要求 DBA 在只读角色上为 `max_rows_to_read`、`max_bytes_to_read`、`max_memory_usage`、`read_overflow_mode`、`result_overflow_mode` 标记 `CHANGEABLE_IN_READONLY`，并用 `MAX` 约束前三项不得高于网关原上限。查询始终显式设置 `throw` 溢出模式；缺少角色约束时请求失败关闭。旧 `{}` 路径沿用旧版设置，不强制变更已有角色。Milvus 的租户 ID 和标量过滤值目前限 1–128 个 ASCII 字母、数字、点、下划线或短横线；超出范围直接拒绝，避免拼接原生表达式。

## 安全链与验收

`MCP 身份 → 当前 Agent/租户与数据源 → 精确表/列授权和管理员配置 → 参数校验 → 持久预检审计 → 验证 TLS 与最小权限账号 → 服务端生成有界查询/过滤表达式 → 返回结构与租户值复核 → 来源脱敏 → 持久终态审计 → 交付`。审计写入、业务数据库或证书不可用时失败关闭；审计不得写入原始向量、过滤值或未脱敏字段。

负向验收涵盖越权过滤字段、调用者伪造租户字段、缺失租户列、结果租户不符、表达式注入、撤权、ClickHouse 超额扫描及溢出模式、超时/取消、审计库与业务库故障。真库以指定版本和合成数据验证，MCP Inspector 与 Dify MCPClient 各执行允许/拒绝调用。从正式 v3.7.0 包升级并演练成套备份恢复；GitHub CI、签名资产、双架构 GHCR、官网和公网 Demo 均为发布门槛。公网 Demo 仍只展示合成 PostgreSQL/MySQL 数据。
