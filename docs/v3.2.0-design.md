# AgentSQL v3.2.0 设计：受控问数与列授权组合

**语言 / Language:** [简体中文](v3.2.0-design.md) | [English](en/v3.2.0-design.md)

状态：开发中。以下是交付目标，不构成已验证的支持声明。

## 用户问题与范围

v3.1.0 的 SQLBot 人员级接入只覆盖 PostgreSQL；PostgreSQL B2 列授权开启时，只读审批申请会关闭失败。v3.2.0 要让这两条路径在维持身份、权限、脱敏和持久审计约束的前提下组合，并把同等人员级边界扩展到指定的 MySQL 只读场景。

| 交付项 | 设计约束 | 验收证据 |
| --- | --- | --- |
| PostgreSQL B2 与只读审批 | 审批申请只封存 SQL、人员、Agent、数据源和期限，不触达业务数据；执行时重新进入实时 B2 快照、数据库对象绑定、计划约束、遮盖和持久审计；申请和批准都不是绕过列授权的凭证 | 申请前无业务读取；批准后授权列成功、越权列拒绝；策略变更、人员撤权、B2 租约失效、审计故障、重放均关闭失败 |
| SQLBot MySQL | 固定 SQLBot v1.10.2；服务端认证的用户映射到指定 MySQL 数据源与专用只读 Agent；适配器按真实方言进行 SQL 分类、元数据发现和结果处理，不接受自报身份或数据库直连回退 | 真 SQLBot、真模型和指定 MySQL 版本完成问数、表格及可用数值图表；跨用户/数据源拒绝，读写混杂和函数副作用拒绝 |
| PostgreSQL/MySQL 权限深化 | 针对 JOIN、子查询、通配列、表达式、聚合和视图梳理可证明的列授权边界；不以解析器通过代替数据库绑定证明 | 安全负向集、真实数据库对象变更与权限收缩复验；不能证明的语法明确拒绝 |
| 策略影响分析 | 在管理端提供只读预览：受影响 Agent、数据源、对象及授权列；基于当前策略修订号，展示不确定项而非给出虚假保证 | 跨租户不可见；策略修订变化使旧预览失效；预览不写策略、不访问业务行 |
| 派生结果保护 | 聚合、计算表达式及排序/筛选可能泄露受限列时，沿用底层列授权证明；脱敏后图表、导出、缓存不得重引入原值 | 受限列派生查询拒绝或有界遮盖；图表及错误信息无原值；审计失败不返回结果 |

## 安全调用链

```text
SQLBot 已登录用户 → 服务端身份上下文 → 租户内精确绑定与当前 revision
  → 短期人员令牌 + 独立只读 Agent Key → MCP 数据源范围检查
  → 当前人员权限、Agent、策略与数据库对象绑定
  → B2 快照 / MySQL 指定授权路径 → 只读执行 → 脱敏 → 持久审计 → 结果

只读审批：原用户申请 → SQL/身份/数据源封存与申请审计 → 管理员批准
  → 原用户单次领取 → 上述实时安全链完整重跑 → 执行与关联审计
```

审批申请可以说明“已受理、待执行时重新验证”，不能把尚未执行的 B2 绑定当作已通过。任何阶段无法证明当前用户、授权列、只读性、审计或执行结果时停止并记录失败；不会切换到旧版表级路径。

## 升级与边界

优先复用现有绑定与审批表。若新增字段或修订号，必须分别验证合库 SQLite/PostgreSQL、分库元数据与审计拓扑的升级和成套恢复。数据库支持级别仍按指定版本、驱动、TLS 模式、拓扑和实测场景陈述；MySQL 或 PostgreSQL 的单实例合成场景不自动成为完整生产支持。

正式发布前需完成 Go/Web/Python 测试、真实 SQLBot 与两类真库、撤权和审计负向集、上一正式版升级恢复、对应提交 CI、双架构签名资产、GHCR、官网及公网 Demo 验收。
