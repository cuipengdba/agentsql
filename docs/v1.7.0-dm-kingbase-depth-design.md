# v1.7.0 达梦与金仓部署边界深化：设计与验证门槛

状态：开发中。本文件对应已确定的 v1.6.0–v3.0.0 路线图中 v1.7.0 的达梦与金仓目标。主分支已合入的 HighGo 指定实例适配是附加能力，不替代本文件的验收门槛。

## 安全连接

| 数据库路径 | 当前事实 | 该能力的提升门槛 |
| --- | --- | --- |
| 达梦 DM8 Pack3，原生 Go 驱动 | 现有 `github.com/godoes/gorm-dameng/dm8` 的 TLS 握手调用 `security.NewTLSFromTCP`，该实现设置 `InsecureSkipVerify: true`；AgentSQL 当前拒绝显式 TLS 选项。厂商文档区分只加密、单向认证与双向认证。 | 找到许可证和再分发条件明确、能够实际验证服务端身份的驱动或接线方式；用指定真库证明正确证书通过、错误 CA/主机名拒绝、轮换后恢复。未完成前不开放达梦 TLS 选项，也不声明安全连接通过。 |
| 金仓 KingbaseES V9R1C10，PG 模式 | 当前经 `postgres` 协议路径连接指定实例；金仓官方手册支持 `sslmode=verify-ca` / `verify-full` 和服务端证书配置。 | 隔离实例上启用 SSL，使用信任根和精确主机名做真库查询、拒绝错误根/主机名、轮换证书并复核连接池新连接；在 AgentSQL MCP 链路核对授权、脱敏与审计。 |

## 查询与权限

只扩大经厂商真库及受控解析器共同证明的 SELECT 子集。每种分页、JOIN、表达式和元数据读取都须有对象授权、列来源、脱敏、负向语法和最小权限账号证据。未完成列来源证明的表达式保持拒绝；不得因金仓采用 PG 协议而自动继承全部 PostgreSQL B2/B5 能力。

## 故障切换与负载

主备验收需在独立测试拓扑中进行，记录版本、许可、同步方式、切换命令、客户端重连、请求终态和审计 ID。切换中的超时、取消与无法确定执行终态均不交付部分结果。单实例停库/重启只能证明故障恢复，不能代替主备验收。多 Agent 只读负载给出并发数、查询形状、时长、P50/P95/P99 延迟、错误率、CPU/内存和审计积压；此数据只描述测试机器，不外推生产容量。

## 发布规则

本版先交付已在 KingbaseES V9R1C10 PG 模式真库证明的 `verify-full`、证书轮换及账号密码轮换，并保留已合入的 HighGo 限定只读能力。达梦可验证 TLS 与两款数据库的正式主备切换需要驱动和许可/拓扑条件，延后验收且保持“未验证”；不以此版号提升其支持级别。v1.7.0 的最终 Release、支持矩阵、官网与 Demo 只能写入实测通过的精确版本和拓扑。每版仍需完成 CI、升级恢复、双架构签名资产、GHCR 匿名拉取与公网烟测。

资料：达梦[通信加密说明](https://eco.dameng.com/document/dm/zh-cn/pm/communication-encryption.html)；金仓[SSL 配置说明](https://help.kingbase.com.cn/v9/faq/faq-new/data-security.html)。
