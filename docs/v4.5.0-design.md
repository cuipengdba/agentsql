# v4.5.0 设计与发布验收合同

[中文](v4.5.0-design.md) | [English](en/v4.5.0-design.md)

状态：候选设计，尚未发布。正式对照基线是 [SQLBot 社区版 v1.10.3](https://github.com/dataease/SQLBot/releases/tag/v1.10.3) 的未修改客户端、服务端与公开接口；若发布前官方最新版变化，必须重新固定基线并补做变化面验收。v1.10.2 的旧证据只能定位回归，不算作 v1.10.3 通过。

## 用户目标

AgentSQL 以自己的 Go 服务、Web 页面和数据库安全网关实现完整问数产品。v4.5.0 对照 SQLBot 社区版的公开页面、API、MCP 与嵌入接入方式，并提供可离线下载、可信验签、一键安装的发行包。页面采用 AgentSQL 品牌与独立实现，原版静态资源只在隔离验收中使用。用户真实业务系统的切换与回退由用户在 v4.5.0 发布后推进，实际对接中发现的问题另行规划。

## 检索参数与知识召回的新增缺口

2026-11-02 以有效管理员会话对照原版 v1.10.3 与提交 `c3fd043c` 的 Go 候选 `GET /api/v1/system/parameter`：原版返回 18 个参数，该候选返回 9 个。该基线缺少 `embedding.enabled`、`embedding.table_enabled`、`embedding.terminology_similarity`、`embedding.terminology_top_count`、`embedding.data_training_similarity`、`embedding.data_training_top_count`、`embedding.table_count`、`embedding.table_alpha`、`embedding.keyword_enabled` 和 `embedding.datasource_count`。原版前端的系统设置页可编辑这些值；原版服务在每个问数任务开始时读取生效配置。对照记录位于 `D:\CodexLS\outputs\agentsql-v450\parameter-gap-v1103-20261102.md`。提交 `704d354a` 已加入其中五项，剩余五项仍未接入。

此项以实际行为验收：保存、重开、重启、参数边界与并发修改；开关及阈值真实影响术语、训练示例、数据表与数据源召回；同一输入在原版客户端和 AgentSQL 页面上对照。AgentSQL 只从当前身份仍可见的网关结构和知识项召回，撤权后不能继续使用旧向量或缓存提示；模型、向量库或审计故障时不得回退到未经授权的结构。仅补齐十个返回字段或展示控件不算完成。此缺口未关闭前，v4.5.0 不得声称完整问数功能对等。

进一步核查原版 v1.10.3 的术语和训练召回源码后确认：`embedding.enabled=false` 只停用向量搜索，词面命中的知识项仍返回；两个 `top_count` 只限制向量候选数。先前候选提交 `3482f54b` 与 `8085a63d` 把开关和数量限制施加到词面结果，虽然定向测试及 CI 通过，语义仍与原版不符，已在后续提交撤回。正确实现须保留当前受权词面匹配，同时加入真正的向量候选、相似度阈值和数量限制，并对原版与候选做同输入对照。此缺口仍阻断完整问数对等结论。

本机隔离原型又以 Apache-2.0 的 Hugot v0.6.0 原生 Go 后端加载原版镜像中同一 Apache-2.0 text2vec ONNX 模型。三句中文得到 768 维向量；“营业额是多少”与“销售收入是多少”的归一化余弦分数在 Go 为 0.816023、原版 Python 为 0.816024，与“今天的天气如何”的分数双方均为 0.313403。Go 首次加载约 6.2 秒，完整三句推理约 7.6 秒。模型 SHA-256、环境和命令见 `D:\CodexLS\outputs\agentsql-v450\embedding-go-prototype-v1103-20261102.md`。这证明向量推理方案可行，不是已接入的产品功能；仍须实现受权知识索引、参数生效、失效与撤权、并发、故障关闭和正式离线包的双架构模型交付。

## 本轮本地向量召回实现

候选分支现可从绝对路径 `embedding_model_path` 加载本机 ONNX 模型，不在运行时下载权重。术语和训练样例先按当前工作空间、数据源、启用状态筛选；训练 SQL 再按当前可见表列及只读解析结果筛选；词面匹配始终保留，随后才对剩余受权候选计算余弦相似度并去重。系统参数页新增五项已生效的 `embedding.enabled`、术语与训练的相似度及向量候选数量设置，保存使用原有管理员审计事务。模型故障拒绝此次召回。Go 的本地固定模型对照、参数越权和非法值、数据源隔离、不可见 SQL 与故障测试已通过；这是候选代码的局部验收。数据表和数据源的向量召回、其余五项设置、原版客户端全流程对照、生产索引性能与签名离线模型包仍待完成。

运行时加载推理会逐文件核对 SQLBot v1.10.3 固定模型目录的哈希，并拒绝缺失、改动或符号链接文件。这项校验不能代替离线包的外部公钥验签、安装校验与回滚。

历史记录接口现按本轮权限、数据库绑定与身份指纹检查旧回答。规则变化或旧记录缺少指纹时，仅保留用户原始问题和时间等状态，不返回旧 SQL、图表、模型分析或结果，也不会重新执行旧查询；同规则下的新记录仍可读取。返回前再次核对规则快照。

## 安全与部署边界

客户端给出的用户、工作空间、数据库配置、规则和模型输出都只是待校验输入。Go 问数服务以当前服务端身份与绑定为准，在模型提示、历史读取、预览、导出、API、MCP 和嵌入查询前后重新确认权限；实际 SQL 只经 AgentSQL 受控网关执行。授权、策略、数据库绑定或审计证明不足时停止返回结果，且不能把旧结果缓存当作授权。

本分支现在保留元数据发现时的数据权限快照，在向量知识检索结束、模型调用前，以及模型生成结束、受控查询前再次核对。权限在检索期间撤销时，旧表列不会传给生成模型；权限在生成期间撤销时，SQL 不会进入查询。历史轮次的 SQL 必须再次通过本轮可见表列检查，且其独立加密保存的权限、用户与绑定指纹必须与本轮相同；旧版没有指纹的轮次不会进入模型提示词。新增行权限后旧轮次消失、相同权限下新轮次保留和旧版记录保守排除的本地测试已通过；原版客户端和真实并发环境仍须验收。

离线包默认安装应用组件；PostgreSQL 原生绑定器位于数据库服务器，必须由受信任的数据库侧交付或明确预装。选择 PostgreSQL 时，安装命令要以实际读取角色连接目标库完成绑定器能力和权限预检后才改动应用安装。公网 Demo 只提供明示的模型模拟交互，不配置或调用真实模型；真实模型验收只在本机完成。

## 已证实的兼容缺口

SQLBot 社区版 v1.10.3 的一个模型 ID 可映射多个工作空间，管理员可列出、替换、追加和移除映射。隔离原版 API 实测：首次创建的模型自动成为**全局默认模型**，即使它没有任何工作空间映射；移除全部映射后，模型和全局默认标志仍保留。原版源码还将全局默认模型列入每个工作空间的可用模型列表。早期候选版曾把模型配置单独存于一个工作空间，拒绝跨空间映射；本分支现有全局目录和显式映射，仍须完成完整发布验收。正式兼容实现必须保留稳定模型 ID、共享配置和密钥、独立映射及管理员控制的全局默认指针；映射变更要在同一事务中完成身份、权限、审计与修订检查，运行时撤权后不得复用旧模型或返回旧结果。全局默认模型的可用性不授予任何数据库或数据访问权限。原版客户端的四种映射操作、模型编辑与密钥轮换、并发撤权和升级迁移均须通过对照验收。路径存在或静态路由数量不能替代行为证据。
