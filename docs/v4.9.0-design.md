# AgentSQL v4.9.0 问数可靠性与可核验兼容基线

> 规划中的版本；本文不是已发布或通过验收的声明。

## 产品与范围

AgentSQL 继续作为独立 AI 问数 Agent 和独立 MCP Server 数据库安全网关交付。SQLBot Community v1.10.3 是可选客户端的固定对照版本，不是 AgentSQL 问数能力的运行依赖。v4.9.0 优先解决 v4.8.1 签名包在 128 张受权表预热期间出现的偶发身份解析 HTTP 503、预热状态缺少失败类别，以及冷/热问数的可靠性证据不足。随后复核同一用户的多轮追问、历史重开与撤权。

本版不把原版浏览器的任意数据库连接输入变成可信网关凭据，也不宣称全部社区版页面、云模型或数据库方言兼容。受权身份、行列权限、执行前和返回前复核、持久审计失败关闭均保持发布阻断地位。

## 实施与验收

| 项目 | 完成条件 |
| --- | --- |
| 审计 503 归因与修复 | 使用安全的错误类别日志复现；区分审计超时、队列回压、提交结果不确定及其它原因。修复后同一 2 CPU/4 GiB ChatBI、2 CPU/2 GiB 网关、PostgreSQL 17、固定 ONNX 与本地 Qwen3-4B 夹具连续复核；不得靠跳过审计、放宽授权或吞掉错误消除 503。 |
| 预热可观测性 | 已验证用户仅能查看自己当前绑定的状态和固定失败类别；无表名、字段、提示词、SQL、凭据或原始下游错误。撤权或模型关闭不写入过期向量。 |
| 128 表问数 | 分别记录冷首问、后台预热、热首问与两路并发。至少三次独立冷预热达到 `ready`，每次 128 条加密向量及 SQLite 完整性通过；20 次连续热态完整问数记录 p50/p95/最大值与网关受控审计，异常样本不得从分母剔除。目标是已预热 p95 不超过 30 秒，但单机隔离测试不称生产 SLA。 |
| 多轮与历史 | 原版固定客户端和 AgentSQL 自有页面各以真实模型、网关与库完成至少两轮有上下文问数，重启后按当前权限读取；撤销数据源或行列权限后旧结果、导出和跨用户历史不得泄漏。 |
| 兼容评分 | 固定 SQLBot Community v1.10.3 可用社区版问数场景与权重；v4.8.1 的约 60% 仅为旧工程估算。每项必须注明精确签名包、客户端、真实模型/数据库、正负场景和未验边界，按实测公布本版分数，不用路由数或旧提交充数。 |
| 正式交付 | 精确提交 CI 全绿、生产资产/外层包签名与独立公钥验签、AMD64 和 QEMU ARM64 断网真实 systemd 新装、v4.8.1 升级与失败回滚；GitHub Release/GHCR 匿名回下载、官网与模拟模型明示的 Demo 公网烟测、规范主仓库 `main` 同步且干净。 |

发布说明必须写明未在用户真实业务系统验证，不宣称 100% 兼容、零改动切换、ARM 实机或生产 SLA。任何未归因的身份解析 503 或安全负向失败都阻断正式发布。
