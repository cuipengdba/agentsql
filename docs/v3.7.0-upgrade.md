# AgentSQL v3.7.0 升级与回退

**语言 / Language:** [简体中文](v3.7.0-upgrade.md) | [English](en/v3.7.0-upgrade.md)

## 升级前

1. 停止旧网关写入，对 metadata、独立 audit 库（如有）和 `AGENTSQL_SECRET` 做同一时间点的成套备份。不要只备份二进制。按[部署指南](DEPLOY.md#升级与回滚)核对运行账号与迁移账号权限。
2. v3.6.0 的 SQLite/PostgreSQL 合库 metadata 版本为 26；独立 metadata 为 24、audit-only 为 7。v3.7.0 分别迁移到 27、25、7，仅给 `datasources` 增加默认 `{}` 的 `read_control_json`。先在隔离环境核对 `agentsqlctl migrate --check`，再由迁移负责人执行 `agentsqlctl migrate`；所有流均为 `current=latest` 后启动新版。
3. 新拓扑必须显式填写 `read_control_json`。MongoDB 配置受信副本集成员及批准索引；Redis/Valkey 配置三个受信 Sentinel、允许的主节点和独立 Sentinel ACL 用户名。验证证书的 CA 文件必须是网关内绝对路径；副本集或 Sentinel 模式不能固定一个 TLS 主机名。

## Sentinel 凭据

管理员保存数据源后，在详情页查看 `sentinel_password_env`。运维把对应 Sentinel ACL 密码以该变量名注入每个网关，且数据节点账号使用数据源加密密码。环境变量名由租户和数据源 ID 计算，不接受配置覆盖。启用前逐一验证错误 CA、未知地址、ACL 撤销和审计库故障均拒绝读取。`{}` 保留原有单实例行为。

## 回退

停止 v3.7.0 网关，恢复升级前的 metadata、audit（如独立）、密钥及 v3.6.0 二进制/镜像，再检查迁移版本和 `/healthz`。旧二进制不能直接读取已迁移的新版 schema。恢复后新建的拓扑配置和审计事件不会自动回放，须按维护窗口记录处理。
