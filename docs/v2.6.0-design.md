# AgentSQL v2.6.0 设计：Redis / Valkey 受控读取

状态：实现中。上一版 v2.5.0 已完成正式发布和公网验收；本版须在真库、客户端、升级与公开交付全部通过后才标为已发布。

## 用户问题与目标

现有 Redis / Valkey 数据源只提供管理员连接、枚举及原生命令预览，Agent MCP 没有可证明的键级授权、脱敏和持久审计链。v2.6.0 为指定 Redis 与 Valkey 单实例构建开放窄形状的精确键读取，明确版本和拓扑边界。候选真库为 Redis Open Source 8.2.9 与 Valkey 8.1.10；最终以拉取的镜像 digest 和服务端返回版本为准。[Redis 8.2 发布记录](https://redis.io/docs/latest/operate/oss_and_stack/stack-with-enterprise/release-notes/redisce/redisos-8.2-release-notes/)与 [Valkey 官方下载页](https://valkey.io/download/)在 2026-10-20 核对。

2026-10-20 本机拉取：`redis:8.2.9` digest `sha256:66b7f4c2f3c6ef1b298bbd7b13c806bc6f71e61f1136a4f58710daf2cb053b21`；`valkey/valkey:8.1.10` digest `sha256:640c5e62cea04b6d6f2084232651d0cc70362d31f4f805e7be94dbed6855e8f2`。指定真库结果见[候选验收](v2.6.0-acceptance.md)。

## 候选安全合同

1. 新 MCP 工具 `read_key` 只接受数据源 ID 和精确键名。执行路径固定为 `TYPE` 后 `GETRANGE key 0 65536`，多读一个字节检测超出 64 KiB；只交付 UTF-8 字符串。禁止客户端传入原生命令串、通配符、脚本、写入、管理命令、SCAN 和跨 DB SELECT。其他 Redis 类型本版拒绝。
2. Agent 身份与租户每次重验；使用当前数据源配置和秘密建立严格 TLS + ACL 用户连接。数据库编号由数据源固定，禁止请求覆盖；源数据库改动、密钥与证书轮换须即时生效。匿名和未验证 TLS 不能进入受控路径。
3. 新策略类型 `key` 与 SQL 表策略分离，格式 `dbN:exact-key` 或 `dbN:bounded-prefix*`；`N` 为数据源固定的 0–15，键至少三个安全 ASCII 字符，拒绝规则优先。禁止无界 `*`、跨库前缀和 SQL 表授权替代键授权。测试服务端 ACL 只授予 `customers:*` 与 `PING`、`HELLO`、`INFO`、`TYPE`、`GETRANGE`。
4. 返回数据最大 64 KiB，执行超时不超过 2 秒，连接池受数据源限制。脱敏按 `dbN`、精确键和 `value` 来源执行；脱敏配置错误、审计预检失败、终态审计失败、结果结构不匹配时均不交付值。审计对象记录按部署密钥和数据源隔离的 HMAC-SHA256 标识，不写原始键值或凭据。
5. 管理端旧原生命令预览不计入 Agent 级生产链路。Redis / Valkey 仍只标记指定版本、指定单实例的受限功能，非完整生产支持。

## 验收矩阵

- 独立 Redis 8.2.9 与 Valkey 8.1.10 指定镜像 digest、TLS 测试 CA、最小 ACL 用户、合成手机号和秘密值。当前镜像已启动，最小 ACL 的授权与越界读取已由各自 CLI 核验。
- 真实 HTTP MCP 与 MCP Inspector、Dify 各允许/拒绝调用；键前缀越界、通配符、危险命令、跨库、错误证书/密码、策略撤销、ACL 撤销均拒绝。
- 持久审计预检/终态、脱敏和故障关闭；停独立审计库与业务库，再恢复，核对没有原值交付。
- v2.5.0 正式包数据的 SQLite 与 PostgreSQL metadata/audit 成套备份、显式迁移、旧版只读检查和恢复；双架构签名、GHCR、官网和 Demo 公网验收。

## 已落实的边界

- 管理策略 API 与控制台分别约束 `dbN:key-prefix*`，不复用 SQL 通配符授权。
- Redis / Valkey 服务端版本、ACL/TLS 行为、双客户端和故障恢复见[候选验收](v2.6.0-acceptance.md)。
- 键名可能含敏感数据；审计仅保留密钥摘要、决策和审计 ID，管理员以审计 ID 定位调用。
