Each version gets independent design, commits, testing, a formal Release, and website/Demo updates. Release notes describe only verified capabilities; route counts, version numbers and canned responses do not prove completion.

## Architecture and boundaries

The Go Q&A service owns SQLBot interfaces, identity, sessions and model orchestration. A separate listener preserves the original `/api/v1` protocol without mixing identically named AgentSQL management paths or authentication namespaces. Server-side cutover takes over the original entry point; business applications keep their addresses. Browser code remains JavaScript/TypeScript.

Authenticated identities resolve explicit workspace/user/datasource/Agent mappings. Metadata and queries continue through the existing controlled gateway. Client-supplied user, tenant or datasource IDs are not authority. Models see only authorized metadata; generated SQL still passes parsing, authorization, execution, masking and durable audit. Model retries or SQL rewriting must not bypass denials.

The protocol inventory is extracted statically from pinned public source, with dynamic dependency routes, browser SDKs, MCP, error shapes, stream events and migration behavior tracked separately. Static inventory is not the complete runtime API. Some community paths depend on `sqlbot_xpack`; verify those with original clients rather than assuming its implementation is in the public repository.

New Go code independently implements protocol and business behavior. Do not copy upstream GPL/additional-term code into Apache-licensed files. Any required upstream assets or derivative code need itemized provenance, licensing, copyright markings and corresponding-source obligations; a language rewrite does not remove licensing requirements.

## v4.1.0 release blockers

- Reject unauthenticated, disabled, expired, revoked, cross-user and cross-workspace requests; preserve legacy identities and large integer precision.
- Compare login encryption, tokens, response envelopes and stream events with the pinned baseline; unverified paths remain pending.
- Use a real local model and synthetic PG/MySQL data to verify authorized metadata, SQL results, masking and durable audit. Fixed SQL and model stubs cannot substitute for live acceptance.
- Model timeout, cancellation, gateway denial, audit failure and storage failure produce explicit terminal states without upstream secrets or unmasked data.
- Migration preflight leaves the source unchanged; validate imports in an isolated target and retain the old service and backups. Releases do not automatically migrate customer production databases.
- Distinguish offline unpacking checks from actual disconnected installation and startup. Missing runtimes, models or database drivers prevent a claim of complete offline Q&A.

## Final replacement evidence

v4.5.0 requires a fixed actual customer version and integration inventory, preserving domains, ports, paths, credentials, application secrets, SDKs, callbacks and historical identifiers. Run before/after cutover tests with the same business application and record its code/configuration hashes. The user's business test environment is not yet available. Generic compatibility work can proceed, but cannot establish that their existing system has passed zero-change replacement.

## Additional v4.5.0 scope and public claims

- Independently implement every page capability and integration flow of the pinned SQLBot Community baseline. Compare Q&A, data sources, charts, dashboards, assistants, settings, administration, requests and permissions page by page. Use AgentSQL's own design, code, icons and branding; do not copy upstream frontend source or assets.
- Test both deployment modes: AgentSQL as the controlled database security gateway for an existing SQLBot deployment, and AgentSQL independently providing Q&A and all compatible entry points after SQLBot is stopped. Explain both modes and their acceptance scope on the website, GitHub and AgentSQL Web. Claim zero-change replacement only after the original client and actual business integrations pass.
- At v4.5.0 release, align website, GitHub front pages, current documentation and Web version descriptions with the actual release in Chinese and English, including the online Demo. Label cloud model interaction as a simulation that does not call a real model.
- Present Apache-2.0 as the only license for the current AgentSQL distribution on the website and GitHub. Remove other licensing marketing and links from current documentation. Preserve authentic historical-version licenses and third-party copyright and license obligations, and exclude upstream restricted code and assets from the Apache-2.0 deliverables.
