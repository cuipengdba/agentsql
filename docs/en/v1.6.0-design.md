# AgentSQL v1.6.0 Design: Domestic database failure shutdown retest

**Language:** [English](v1.6.0-design.md) | [Simplified Chinese](../v1.6.0-design.md)

## User issues and baselines

v1.5.0 has verified bounded read-only, permission revocation, database break recovery, masking, persistent auditing and real MCP clients on designated instances of Dameng DM8 Pack3, KingbaseES V9R1C10 PG mode and Vastbase G100 Build 9 PG mode. There is no evidence of the same environment for real query timeout/cancellation and independent audit storage failure on a database-by-database basis. Administrators therefore cannot consider these scenarios as having passed production failure acceptance.

This version only fills in these fault boundaries, fixes the actual problems found, and makes the final state identifiable in responses, logs, and audits. It does not extend SQL dialect, B2 column-level licensing, B5 session or vendor version coverage, nor does it automatically claim full production support based on passing failure testing.

## Execute the contract

`MCP 客户端 → Agent/租户认证 → 数据源与策略 → 解析/规则 → 受控数据库执行 → 脱敏 → 持久审计 → 结果交付`。

1. When a timeout or cancellation occurs before query creation, row reading, masking, or auditing, partial original values or partial results must not be delivered. Even if the driver returns a null error after reading a line, the executor must still check the operation context.
2. The final state audit of a single SELECT must be permanently recorded; when the independent audit library is unavailable, MCP will not return an allowed result. After the audit is restored, new permission requests must be written to the persistent audit and masked according to the rules.
3. Stateful legacy `/mcp` preserves the B5 session's independent deadlines and rollback constraints; stateless `/mcp/2026-07-28` passes client disconnects to executing read-only tools. The two paths verify server-side statement timeouts and real client cancellations respectively, and maintain safe and stable error classification without echoing original database errors, credentials, or sensitive data.
4. Fault injection uses synthetic data and independent test accounts, and does not modify production instances. To cancel the test, you must also confirm that the slow query on the database side has ended or the connection has been dropped. You cannot just use the client timeout as evidence.

## Delivery threshold

From v1.5.0 official package and data snapshot drill upgrade and complete recovery; Go/Web, SQL security negative set and real client retest passed; CI corresponding candidate submission; dual-architecture official package, signature, SBOM, GHCR accurate tag, official website and Live Demo are accepted under the same official version. Candidate evidence is retained when either required threshold is failed, and a supporting statement is not issued or promoted.
