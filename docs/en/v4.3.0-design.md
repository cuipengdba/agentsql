# v4.3.0 Design: Verifiable Q&A Presentation and Embedding

Status: in development. The fixed behavioral baseline is SQLBot Community v1.10.2. AgentSQL uses its own Go service, UI and branding. The following are delivery gates, not claims of completed functionality.

## Goals

| Workflow | Required behavior | Acceptance |
| --- | --- | --- |
| Charts | Produce tables, bar, line and pie charts from currently authorized query results; store only field mappings and controlled-query references | Compare original stream events and historical charts; revoked table, column or row access must suppress stale chart data |
| Analysis and prediction | Explain the data range, inputs, method and generation time; run real models locally and only an explicitly labeled simulation in the cloud | Compare synthetic cases and failure behavior; model, authorization or audit failures must not disclose data |
| Dashboards | Own canvas with resource tree, charts, text, tabs, layout, save, preview, delete and export; map original dashboard API | Create and edit through the original client, then verify restart persistence; reauthorize and audit each chart read |
| Assistants | Create, configure, enable and revoke basic and advanced applications; bind application identity to workspace and allowed data sources | Compare original pages and API; test cross-user access, origins, revocation, expiry, concurrency and replay |
| Embedding | Match the original SDK, web embedding, API and MCP entry points for login, token, callback, domain and session | Use the unchanged original SDK and embedded page locally; compare parameters, responses, errors, callbacks and revocation |

## Security and data flow

Charts, dashboards, assistants and embedded clients store configuration and references only. Each result read rechecks the current user or application identity, workspace, data source, table, column and row rules. The AgentSQL gateway executes the query, masks the response and writes durable audit records. Historical results are never a substitute for fresh authorization. Unknown SQL, data sources or identities are rejected. Model text, SQL and chart suggestions are untrusted input.

Web embedding, API and MCP share authorization semantics while retaining their protocol contracts. The public Demo shows clearly labeled simulated interactions, runs no real model and connects to no business database. Real-model functional acceptance uses local synthetic databases.

## Release gates

This version needs its own design record, code, feature and failure tests, original-client comparisons, Go/Web/docs CI, upgrade rollback, offline fresh install and failed-start rollback, signed dual-architecture packages, anonymous image pulls, GitHub Release and matching website/Demo versions. A workflow that has not passed these gates cannot appear in the supported-feature list. Complete SQLBot page coverage and zero-change replacement of an actual business system require separate v4.5.0 evidence.
