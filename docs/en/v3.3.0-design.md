# v3.3.0 design: depth for the pinned Dameng build

**Language:** [English](v3.3.0-design.md) | [Chinese](../v3.3.0-design.md)

Status: delivered as recorded in the [release evidence](v3.3.0-release-evidence.md). Evidence is scoped to DM8 Pack3 `dm8_20241022_rev244896_x86_rh6_64` with `COMPATIBLE_MODE=0`; it does not extend to other builds, compatibility modes, or HA topologies.

## Secure connection

The current `godoes/gorm-dameng` v0.7.2 TLS handshake sets `InsecureSkipVerify: true`. Encryption alone therefore does not establish server identity. Explicit TLS must require a CA file and expected server name and must reject verification bypass. The certificate chain, validity period, and name must be verified before any business query. Plaintext servers and connections that cannot prove encryption fail closed. Test the valid certificate, wrong CA, wrong name, certificate rotation, and rejection of the old certificate against the pinned database. Existing data sources without TLS configuration retain their compatibility behavior, while UI and documentation identify them as lacking verified connection security.

Dameng's communication encryption manual defines `ENABLE_ENCRYPT=5` as encrypted communication with client verification of the server, but this pinned 2024 build rejects value `5`. On the isolated instance, `ENABLE_ENCRYPT=1` and `MIN_SSL_VERSION=771` (TLS 1.2) passed an AgentSQL client certificate-verification probe: the correct certificate allowed a query, while wrong CA and hostname failed during the handshake. Final acceptance still requires the full MCP path. The server mode name alone does not prove mutual authentication.

## Queries, cost, and resources

Expand read-only SELECT only where parser, object and column lineage, and a least-privilege live database test jointly prove the boundary. State accepted and rejected projection, filtering, pagination, and multiple-source forms individually. Reject unproved expression lineage, comments, writes, multiple statements, and system catalogs. Unknown EXPLAIN structures and out-of-budget estimates fail closed before execution. Keep upper bounds for the R004 scan-row threshold, rows per request, timeout, connections, and concurrency. After execution, enforce cancellation, result budgets, masking, and durable audit.

## Live database and recovery acceptance

Use the supplied local image and a read-only license mount in an isolated DM8 Pack3 container. Check allowed queries, policy denials, least-privilege accounts, bad TLS settings, timeout/cancellation, bounded concurrent load, and fail-closed recovery after a database restart through MCP with audit IDs. Record build, mode, license expiry, load shape, P50/P95/P99, error rate, and resource observations. A single-instance restart is not HA failover. Complete the upgrade/recovery, CI, signed dual-architecture artifacts, anonymous GHCR pulls, website, and public Demo gates in `docs/RELEASE_ROUTINE.md` before publishing.
