## Pinned environment

| Item | Tested configuration |
| --- | --- |
| Database | User-provided `dm8_20241022_x86_rh6_64_single` image, DM8 Pack3 `dm8_20241022_rev244896_x86_rh6_64`, single instance, `COMPATIBLE_MODE=0`, synthetic data. The local read-only license expires on 2027-06-25. |
| Transport | `ENABLE_ENCRYPT=1`, `MIN_SSL_VERSION=771` (TLS 1.2); AgentSQL explicitly uses `verify-full` with a CA and certificate name. This build rejects `ENABLE_ENCRYPT=5` from the vendor manual, so that mode is not claimed. |
| Resources | Isolated container and temporary SQLite metadata. The DM reader has only `CREATE SESSION` and `SELECT` on the test table; datasource pool limit 2, row limit 10, statement timeout 20 seconds. |

## Completed live database checks

| Check | Result |
| --- | --- |
| TLS verification | A matching CA and name allow queries; wrong CAs and names fail at handshake. Unit tests also cover fail-closed plaintext/handshake-only modes, missing configuration, and bypass requests. |
| Certificate rotation and process restart | The isolated DM instance was given a new CA and server certificate and restarted. The old CA failed with `unknown authority`; a direct query using the new CA passed. The full MCP permission, masking, audit, load, and failure/recovery checks passed again afterward. |
| Queries and plans | Types, samples, pagination, truncation, least privilege, and error classification passed on 2505 synthetic rows. Indexed and sequential EXPLAIN estimates were normalized; bounded `TOPN2` from `LIMIT` was recognized. Unit tests cover scan-node aggregation and overflow rejection. |
| MCP security chain | Real HTTP MCP allowed a masked query with an audit ID. Writes and an ungranted object were denied; allow/deny records were retrieved from durable audit storage. |
| Bounded load | Twelve real MCP queries at concurrency 2 with a database pool limit of 2: 12 successes and zero errors. Each returned masked data and an audit ID. One isolated run measured P50 2.19 seconds and P95/P99 2.79 seconds; this small sample is not a production SLA. |
| Failure and recovery | A TCP fault proxy dropped active and new connections. MCP denied the query without exposing the raw phone number. After recovery a new verified connection returned masked data with an audit ID. |
| v3.2.0 upgrade and rollback | Two independent copies of an online v3.2.0 SQLite backup were used. The v3.3.0 candidate and the v3.2.0 rollback image each started and passed health/readiness checks; both retained 350 historical audits, and SQLite `quick_check` and migration-table checks passed. The running source instance was untouched. |
| Isolated demo MCP acceptance | The v3.3.0 candidate image seeded a separate demo directory. A real HTTP MCP allowed query returned two masked cells and a durable audit ID; `SELECT *` triggered R010 denial and a second audit ID. The integration guide now uses this executable fixture. |

## Outstanding gates and limits

Formal release gates are recorded in the [release evidence](v3.3.0-release-evidence.md). Exploratory four-way load above the datasource pool limit encountered SQLite metadata lock waits and timeouts; this release records only the bounded two-way result. Higher concurrency and PostgreSQL metadata deployment need separate capacity acceptance. Evidence covers only the pinned build, one instance, and synthetic data. It does not establish complete Dameng production support.
