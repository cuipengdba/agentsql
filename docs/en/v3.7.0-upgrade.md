# AgentSQL v3.7.0 Upgrade and Rollback

**Language:** [English](v3.7.0-upgrade.md) | [Simplified Chinese](../v3.7.0-upgrade.md)

## Before upgrading

1. Stop writes to the old gateway. Take a consistent, paired backup of metadata, a separate audit store if used, and `AGENTSQL_SECRET`. Backing up only the binary is insufficient. Check runtime and migration-owner privileges against the [deployment guide](DEPLOY.md).
2. In v3.6.0, combined SQLite/PostgreSQL metadata is at version 26; separated metadata is at 24 and audit-only at 7. v3.7.0 advances these to 27, 25, and 7 respectively, adding `datasources.read_control_json` with a `{}` default. Check `agentsqlctl migrate --check` in isolation, have the migration owner run `agentsqlctl migrate`, then start the new version only after every stream reports `current=latest`.
3. New topologies require explicit `read_control_json`. MongoDB needs trusted replica members and approved indexes. Redis/Valkey needs three trusted Sentinels, approved masters, and a separate Sentinel ACL username. The verified CA file must be an absolute path inside the gateway. Do not set one fixed TLS hostname for replica or Sentinel mode.

## Sentinel credentials

After saving a datasource, the administrator can read `sentinel_password_env` in its details. Operations must inject the corresponding Sentinel ACL password under that name into every gateway; the data-node credential remains the encrypted datasource password. The environment variable name is derived from tenant and datasource IDs and cannot be overridden. Before enabling the topology, verify that wrong CA, unknown addresses, revoked ACL, and audit-store failure all deny reads. `{}` retains the existing standalone behavior.

## Rollback

Stop the v3.7.0 gateways. Restore the pre-upgrade metadata, separate audit store if used, secret, and v3.6.0 binary/image together, then check migration versions and `/healthz`. The older binary must not be pointed directly at the migrated schema. New topology settings and audit events created after the backup are not replayed automatically; account for them in the maintenance window.
