# AgentSQL v3.8.0 Upgrade and Rollback

**Language:** [English](v3.8.0-upgrade.md) | [Simplified Chinese](../v3.8.0-upgrade.md)

## Before upgrading

1. Stop writes to the old gateway and take a paired backup of metadata, the separate audit database if present, and `AGENTSQL_SECRET`. Run `agentsqlctl migrate --check` with both the formal v3.7.0 package and the v3.8.0 candidate in isolation. This release adds no migration: the combined SQLite schema remains at 27, separate PostgreSQL metadata at 25, and audit-only at 7.
2. Configure optional `read_control_json` as described in the [design](v3.8.0-design.md). Before enabling a ClickHouse budget, the DBA must mark the three budgets and two overflow modes `CHANGEABLE_IN_READONLY` on the readonly role. The three budgets also need `MAX` constraints no higher than the previous gateway ceilings. Test a normal query, an over-budget rejection, and incorrect role constraints before using a business datasource.
3. Before enabling Milvus tenant filtering, create a static String/VarChar tenant field in each target collection, populate it with values exactly matching AgentSQL tenant IDs, and grant exact columns for the tenant, vector, output, and filter fields. Verify zero cross-tenant hits, rejected unauthorized filters, and masked output with synthetic data first.

## Rollback

Stop the v3.8.0 gateway and restore the paired pre-upgrade metadata, audit, key, and formal v3.7.0 binary or image. Check the schema and `/healthz`. Although the schema is unchanged, restore the paired snapshot to keep audit and metadata at the same point in time. New v3.8.0 configuration and audit events are not replayed automatically after rollback; record their handling in the maintenance window.
