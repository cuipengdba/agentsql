# AgentSQL v0.6.0 Release Notes

**Language:** [English](release-notes-v0.6.0.md) | [Simplified Chinese](../release-notes-v0.6.0.md)

## This update

- The console adds users, roles, tenant management portals and first-time access wizard. The management API continues to read and write according to the caller's tenant and role constraints, and permission delegation cannot exceed the caller's existing permissions.
- Ordinary SQL approval adds archiving, validity period and single execution. Bind the tenant, Agent, data source configuration, SQL and reason when applying; after approval, the original Agent calls MCP `execute_approved` and rechecks the current identity, permissions, risk rules and database connection before execution. Execution results, audit IDs, and failure status can be tracked in the approval record. Unsealed approval records in the old version are not executable; B5 transaction approval remains an independent contract. The restricted account real database test of PostgreSQL 18 and MySQL 8.4 confirmed that the application is not written, is only written once after approval, and is rejected after repeated calls.
- Add an independent `vastbase` data source type to provide bounded single-table read-only query for the PG compatibility mode of Vastbase G100 V3.0 Build 9. Connections are forced read-only and validate product, version, and schema; SQL writes, DDLs, JOINs, functions, etc. outside the measured subset are rejected. Real G100 synthetic data testing covers MCP query, table authorization, masking, application and single execution and persistent auditing. For detailed boundaries, see [G100 verification record ](vastbase-g100-v060.md).
- Base MCP tools increased from 7 to 8. Added execution status field to approval schema for SQLite combined, PostgreSQL combined and separated metadata. The SQLite→PostgreSQL migrator supports new fields and correctly recognizes the built-in permission list preset when PostgreSQL tables are created.

## Upgrades and Security Boundaries

Stop writes and back up the control plane database, configuration, and `AGENTSQL_SECRET` before upgrading. Check migration version, management login, MCP tool discovery, old Agent Key and audit query after upgrade. There is already an approval document that can be viewed and made, but there is no storage information for v0.6.0, so it cannot be used as execution credentials; a new application is required.

G100 verification uses a temporary license generated by the installer, which is valid until 2027-01-12; it only supports this isolation test. Formal production licensing, TLS, HA, other builds, long-term loads, and vendor certifications are not complete and cannot be used to claim full production support for the G100. Dameng and KingbaseES continue to use specified version evidence as described in their respective documentation, and this release does not expand their dialect or production support commitments.

The actual client acceptance targets for this release are the Dify and MCP Inspector graphical interfaces; the Inspector can verify MCP tool calls, but not the AI Assistant. Claude Desktop has not yet been tested due to the lack of an account, and its access instructions are reserved as a configuration guide and are not used as a conclusion for the compatibility acceptance of this version. The SDK and protocol tests in the repository only prove the corresponding automated paths and cannot replace actual client records. Release assets and deployment instructions are subject to the official [GitHub Releases](https://github.com/cuipengdba/agentsql/releases) page.
