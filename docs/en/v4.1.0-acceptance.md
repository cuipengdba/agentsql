## Official release evidence

- The `v4.1.0` Git tag resolves to `6892cbc98047ce3b71f7bfe29d458720277f154a`. Ed25519 signatures for `SHA256SUMS`, SPDX and provenance were verified; all 15 asset checks passed.
- The exact image tags `v4.1.0`, `v4.1.0-demo` and `v4.1.0-quickstart` anonymously expose both `linux/amd64` and `linux/arm64` manifests. The main image and `latest` share digest `sha256:ee746069b3415c58cc31208b026b51926bbb3a91de6bccf9d08d64a09a2fe13d`.
- The public Demo runs `v4.1.0-demo` and is healthy. Synthetic allow, masking, denial and audit checks passed from local and public endpoints. Chinese/English home pages, Demo landing page and both simulated Q&A pages returned HTTP 200; the public static-site verifier passed 27/27 checks.
- Cloud model features are explicitly labelled simulations. After publication, the cloud host has only the healthy gateway, MySQL and PostgreSQL containers, with about 8.2 GiB free on the root filesystem.

The latest local candidate also completed a MySQL email query: all three rows were masked, audit ID 422. Future live-model functionality is validated on the local PC. The public site displays only an explicitly labelled simulation, requires no cloud model-capacity acceptance, and does not run a model in the cloud.

## Failed attempts and limitations

The small Qwen3 0.6B Q8_0 model completed controlled queries on both databases, but generated `LIMIT 20` for one request asking for the first three rows. That semantic acceptance case failed and is not counted as a model-correctness pass. Controlled execution and business-answer accuracy are evaluated separately.

The initial audit-failure injection accessed a bind-mounted SQLite file directly from Windows while Linux containers used it. The trigger did not take effect as expected, and that test copy subsequently became corrupt. The failed copy was retained, test services stopped, and the previously stopped synthetic baseline restored into Linux-native volumes. Audit-failure cases were rerun within the same Linux filesystem. The failed attempt is not counted as a security pass; no public or real business database was modified.

All database and customer data is synthetic. The user's actual business test environment is still unavailable; unchanged real business code and configuration have not been accepted. Full SQLBot functionality, dynamic routes, embedding, MCP and full migration continue under the [five-release plan](v4.1.0-design.md).
