## Failed attempts and limitations

The small Qwen3 0.6B Q8_0 model completed controlled queries on both databases, but generated `LIMIT 20` for one request asking for the first three rows. That semantic acceptance case failed and is not counted as a model-correctness pass. Controlled execution and business-answer accuracy are evaluated separately.

The initial audit-failure injection accessed a bind-mounted SQLite file directly from Windows while Linux containers used it. The trigger did not take effect as expected, and that test copy subsequently became corrupt. The failed copy was retained, test services stopped, and the previously stopped synthetic baseline restored into Linux-native volumes. Audit-failure cases were rerun within the same Linux filesystem. The failed attempt is not counted as a security pass; no public or real business database was modified.

All database and customer data is synthetic. The user's actual business test environment is still unavailable; unchanged real business code and configuration have not been accepted. Full SQLBot functionality, dynamic routes, embedding, MCP and full migration continue under the [five-release plan](v4.1.0-design.md).
