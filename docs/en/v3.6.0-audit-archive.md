# v3.6.0 Audit archive chain verification draft

**Language:** [English](v3.6.0-audit-archive.md) | [Simplified Chinese](../v3.6.0-audit-archive.md)

Existing `audit report --format archive` creates a ZIP, and `audit checkpoint-create` signs it with an Ed25519 seed held outside the gateway. v3.6.0 adds verification of a sequence of archives: content, signatures, chain ID, predecessor digests, order, and an externally pinned final digest. It cannot prove that exports include every source audit record and does not provide immutable object-store retention.

## Create and retain

1. Export archives for explicit tenant and time windows, checking the audit-chain head sequence, hash, and filters. Store archives, signatures, trusted public key, window descriptions, and predecessor checkpoint digests in controlled storage independent of AgentSQL gateways and databases.
2. Sign each ZIP with the existing `agentsqlctl audit checkpoint-create`. The first checkpoint has an empty `--previous-sha256`; subsequent checkpoints use the preceding checkpoint digest. Keep the seed out of gateway containers and both databases.
3. Create an ordered `catalog.json` beside the archives:

   ```json
   {
     "schema_version": "agentsql.audit-chain-catalog/v1",
     "entries": [
       {"archive": "2026-10-01.zip", "checkpoint": "2026-10-01.checkpoint.json"},
       {"archive": "2026-10-02.zip", "checkpoint": "2026-10-02.checkpoint.json"}
     ]
   }
   ```

   Entries must use distinct local relative paths; one invocation accepts at most 1,000 entries. Pin the last checkpoint digest through an independent trusted channel, not by reading it only from the directory being verified.

## Verify

```sh
agentsqlctl audit checkpoint-chain-verify \
  --catalog catalog.json \
  --public-key-file checkpoint-public.hex \
  --chain-id trusted-chain-id \
  --expected-head externally-pinned-64-character-sha256 \
  --max-age 87600h
```

When verification starts in the middle of a history, also provide the externally pinned preceding checkpoint digest with `--trusted-predecessor`. Select `--max-age` explicitly; the ten-year example is neither a default retention policy nor a freshness guarantee. The current checkpoint format does not sign window start and end times, so operators must independently verify window continuity, the source audit-chain head, and actual object-store retention.

Missing middle archives, tampering, invalid signatures, wrong chain IDs, reversed order, predecessor mismatch, or final-head mismatch fail verification. Do not delete source audit records or mark that catalog archived after a failure.
