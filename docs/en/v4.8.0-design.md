# AgentSQL v4.8.0 broad compatibility and connection contract

> Released. The actual scope is determined by the exact commit, per-entry evidence, and signed-package acceptance in the v4.8.0 Release. The table below retains the original acceptance goals; unverified combinations are not supported claims.

## Product boundary

AgentSQL provides both an independent natural-language Q&A agent and an independent MCP Server security gateway. SQLBot Community v1.10.3 is an optional original client and protocol reference, not the source of AgentSQL's Q&A capability. v4.8.0 addresses the remaining usable Community pages/APIs, database connection creation and editing, cloud models, and production-scale behavior. An itemized matrix separates "verified support", "configuration only", "explicit denial", and "unverified". A registered route or visible page is not functional acceptance.

Actual database targets and credentials are created only through the controlled gateway management API or private operator configuration. The public AES envelope submitted by the SQLBot browser may edit display metadata, but cannot create or replace a gateway target. v4.8.0 adds operator-side rotation of a personal datasource mapping: create the new gateway binding first, preflight its authorized schema and row and column rules using a private file, then compare the old binding ID and store revision before committing the encrypted local mapping and management audit. Old queries recheck the revision before returning data. Repeat a live Q&A check, then revoke the old gateway binding. Browser-direct database access and browser-submitted database keys are outside this flow.

## Itemized matrix and release gate

| Area | Positive evidence | Required negative or boundary evidence |
| --- | --- | --- |
| Original pages and APIs | Operate every page under the unmodified fixed official v1.10.3 client; record requests, responses, screenshots and workspace state | Identity, permission, disabled/deleted resources, upload and concurrent revision conflicts; mark uncovered entries "unverified" |
| Original MCP and embedding | Verify the official SDK, basic/advanced assistants and Type 4 page embedding separately with a real model, gateway and database | Cross-user/origin access, token revocation, rule changes, history/export, forged messages and failure closure |
| Connection creation, editing and rotation | Create/edit and check reachability through the gateway management API, then bind to personal Q&A; rotate old local mapping with version comparison | Wrong new credentials, stale ID, concurrent change, audit failure, old-result release and old gateway binding revocation |
| Model suppliers | Complete real requests and recovery with credentials for every claimed supplier; without credentials, verify configuration shape only | Wrong key, timeout, model interruption, secret disclosure and unauthorized edits |
| Scale and resources | Record cold/warm first question, throughput and p95 at stated CPU, memory, authorized table count and concurrency | Revocation during prewarm, queue bounds, model/database/storage/audit failures; warm results cannot stand in for cold results |
| Formal delivery | Five exact CI checks, independent verification of 17 production-signed assets and the outer bundle, disconnected dual-architecture real-service install/upgrade/rollback | Upgrade from formal v4.7, anonymous GHCR pull, public website/Demo smoke and canonical checkout sync |

Direct migration of original permission databases, arbitrary third-party role IDs, all database protocols and all cloud models do not become supported merely because they appear in this plan. Unsafe entries stay fail-closed and are identified in the matrix. QEMU ARM64 is not physical ARM hardware. The Demo model is explicitly simulated. Release notes state that the user's real business system has not been validated and do not claim 100% compatibility or zero-change cutover.
