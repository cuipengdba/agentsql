# v3.6.0 Cross-environment policy delivery draft

**Language:** [English](v3.6.0-policy-transfer.md) | [Simplified Chinese](../v3.6.0-policy-transfer.md)

This workflow currently supports only simple table-level allow/deny rules with exact table names handled by the existing atomic apply path. Signing rejects snapshots containing wildcard table names, column grants, relation bindings, row filters, or unrepresentable legacy rules. The package contains no database credentials or business rows, but it does reveal resource identities and grant scopes, so protect it as sensitive configuration.

1. As an authorized source administrator, save the complete JSON response from `GET /api/v1/policy-bundles/current` as `source-snapshot.json`. Generate a dedicated Ed25519 pair outside the gateway:

   ```sh
   agentsqlctl policy-transfer keygen --private-seed-out transfer-seed.hex --public-key-out transfer-public.hex
   agentsqlctl policy-transfer sign --snapshot source-snapshot.json --source-environment staging --private-seed-file transfer-seed.hex --out transfer.json
   ```

   Keep the seed only with trusted source operators. Obtain the public key in the target through an independent trusted channel and check the SHA-256 fingerprint of `transfer-public.hex`. Do not reuse the AgentSQL release-signing or audit-checkpoint keys.

2. Save a fresh target response from `GET /api/v1/policy-bundles/current` as `target-snapshot.json`. Create an explicit mapping:

   ```json
   {
     "target_tenant": "target-tenant-id",
     "agents": {"source-agent-id": "target-agent-id"},
     "datasources": {"source-datasource-id": "target-datasource-id"},
     "policies": {"source-policy-id": "new-or-existing-target-policy-id"},
     "objects": {"source-policy-id": "target_schema.target_table"}
   }
   ```

   Each source policy needs a unique target policy ID and an explicit target table. An existing target rule must be a simple table rule. Unmapped target rules remain unchanged. Verify that each mapped Agent, datasource, and business table is the intended resource.

3. Verify the package offline and prepare input for the existing management API:

   ```sh
   agentsqlctl policy-transfer plan --transfer transfer.json --target-snapshot target-snapshot.json --mapping mapping.json --public-key-file transfer-public.hex --source-environment staging --out proposal.json
   ```

   Submit `proposal.json` to target `POST /api/v1/policy-bundles/plan` for an impact review, then to `POST /api/v1/policy-bundles/proposals`. A different administrator reviews the proposal before an operator applies it. The target API rechecks tenant, resource existence, and current policy digest; offline planning never substitutes for live validation. Transfers expire after seven days.

4. Download a fresh target snapshot after apply, compare digest and scopes, and send real gateway requests to verify allow, deny, masking, and durable audit. Correct mapping errors and re-plan instead of broadening grants to pass preflight.

This draft does not offer automatic cross-environment synchronization, column-rule transfer, or silent policy deletion.
