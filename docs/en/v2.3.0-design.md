# v2.3.0 SQL Server designated instance in-depth design

**Language:** [English](v2.3.0-design.md) | [Simplified Chinese](../v2.3.0-design.md)

Status: v2.3.0 has been officially released; this document records the design scope, and the final results can be found in [, the official release evidence ](v2.3.0-release-evidence.md).

## User problems and goals

Allow enterprise pilots using SQL Server 2025 to complete Agent queries using TDS connections with verified certificates and minimum privilege accounts, while ensuring that the original results are not delivered in the event of rule rejection, database revoking, disconnection, and audit database failure. Maintain three levels of distinction between registration database, narrow read-only verification and full production support.

## Specify environment

- Official image `mcr.microsoft.com/mssql/server@sha256:742481d1b1186cccc81220a1eaacef244ca8d0f7d19c8e5c70df8ae541ffbab2`, SQL Server 2025 Developer, 17.00.5015 log build, isolated x86_64 test instance.
- The server certificate is signed by a local test CA and includes DNS/IP SAN and serverAuth EKU. The image reads the private key in the dedicated volume as a non-root user. Correct CA strict TLS query passed; incorrect CA rejected, correct CA passed differential preflight see `D:\CodexLS\outputs\agentsql-v230\preflight.md`.
- Pre-check uses the SA management account, which only proves the underlying driver and certificate path; formal acceptance must create a random synthetic table and a read account that only obtains the target table SELECT and necessary SHOWPLAN permissions. Microsoft documentation requires SHOWPLAN_XML to be granted SHOWPLAN to the referenced database; without this permission it should fail and close without switching to an administrative account.

## Acceptance must be delivered

1. Create a random synthetic library/table, read-only login and user; check that the SQL Server server rejects INSERT and the read account does not have db_owner/db_datareader; clean up the test objects and accounts.
2. The connection difference between the correct CA and the incorrect CA and certificate host name does not match; keep the default strict certificate verification and do not set TrustServerCertificate as the production default.
3. Complete Agent identity, table-level allow, unprivileged table R010, narrow SELECT, mobile phone number masking and persistent auditing through real HTTP MCP; write, multi-statement, dynamic source and stored procedure rejection.
4. Revoke the SELECT, SHOWPLAN and Agent policies respectively to verify that no original rows are delivered; retest after restoring permissions to confirm that the SHOWPLAN_XML session state is cleared.
5. SQL Server shutdown, independent audit library shutdown and recovery; original rows are not delivered when verification fails, and masked results are returned after recovery and can be reviewed and audited.
6. MCP Inspector and Dify have completed allowing and denying calls respectively; use the release package of the last official version v2.2.0 to practice SQLite and PostgreSQL metadata/audit upgrade and complete backup recovery.
7. Independent CI, dual-architecture signature assets, GHCR accurate tags, official website and Live Demo are delivered as `docs/RELEASE_ROUTINE.md`.

## No expansion statement

x86_64 Docker Developer single instance testing does not constitute SQL Server versions, Windows/Always On, production certificate life cycle or vendor certification; complex SQL, B2/B5, writing and full production support are subject to separate acceptance. The Live Demo continues to use synthetic PostgreSQL data and does not purport to showcase a real SQL Server library.
