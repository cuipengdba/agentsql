# AgentSQL v3.8.0 Design: ClickHouse Budgets and Milvus Tenant Filters

**Language:** [English](v3.8.0-design.md) | [Simplified Chinese](../v3.8.0-design.md)

Status: in development. This release deepens only the existing controlled read paths for a specified ClickHouse 26.8.31.2 single node and Milvus 2.6.25 standalone instance; it does not claim full production support.

## User task and configuration

Administrators need tighter scan budgets for analytical reads and an authoritative AgentSQL tenant scope in a shared vector collection, without exposing native SQL or expressions. Two optional profiles use the existing `read_control_json` metadata column, with no new database migration.

| Capability | Contract |
| --- | --- |
| ClickHouse `query_analytics` | `{"clickhouse":{"max_rows_to_read":1000,"max_bytes_to_read":262144,"max_memory_usage":33554432}}` can only tighten the previous limits of 10000 rows read, 1 MiB read, and 128 MiB memory. The two-second deadline, 100 output rows, and two-thread limit remain. Read and result overflow explicitly throw errors. Table metadata is limited to 128 columns. `{}` keeps the previous budget. |
| Milvus `search_vectors` | `{"milvus":{"tenant_field":"tenant_id","filter_fields":["status","region"]}}` enables row-level tenant scope for each single-collection search through this datasource. The tenant value comes from the reauthenticated Agent, never an MCP argument or administrator JSON. The caller may submit at most four approved String/VarChar equality filters, never a native expression. Current exact column grants must cover the tenant, vector, output, and filter fields. The gateway builds a fixed Boolean expression and rechecks every hit's tenant and filter values; internal verification fields are omitted from the MCP result. `{}` retains the legacy control-plane tenant isolation path and does not imply row-level tenant isolation. |
| Management and compatibility | Saving a datasource rejects looser budgets, unknown fields, cross-database profiles, embedded credentials, unverified TLS, and a Milvus `root` account. Existing unconfigured datasources and MCP requests remain compatible. |

Custom ClickHouse budgets require the DBA to mark `max_rows_to_read`, `max_bytes_to_read`, `max_memory_usage`, `read_overflow_mode`, and `result_overflow_mode` as `CHANGEABLE_IN_READONLY` on the readonly role, with `MAX` constraints on the first three at or below the existing gateway ceilings. The query explicitly sets both overflow modes to `throw`; without the role constraints it fails closed. The legacy `{}` path keeps the prior role contract. Milvus tenant IDs and scalar filter values currently allow 1–128 ASCII letters, digits, dots, underscores, or hyphens; other values are denied rather than interpolated into a native expression.

## Security chain and acceptance

`MCP identity → current Agent/tenant and datasource → exact table/column grants and administrator profile → input validation → durable preflight audit → verified TLS and least-privilege account → server-built bounded query/filter → result shape and tenant-value recheck → source-aware masking → durable terminal audit → delivery`. Missing audit writes, business database, or certificates fail closed. Audits must not contain original vectors, filter values, or unmasked fields.

Negative acceptance covers unauthorized filters, caller attempts to supply a tenant field, missing tenant columns, mismatched tenant results, expression injection, revocation, ClickHouse over-budget scans and overflow modes, timeout/cancellation, and audit or business outages. Real databases use the specified versions and synthetic data. MCP Inspector and Dify MCPClient each perform allowed and denied calls. Upgrade from the formal v3.7.0 package and paired-backup restore are rehearsed; GitHub CI, signed assets, dual-architecture GHCR, website, and public Demo are release gates. The public Demo continues to use synthetic PostgreSQL/MySQL data only.
