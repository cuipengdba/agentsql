## Pending Release Threshold for Candidate Stage

In the first Go full-package short test, the storage package timed out at the default 10-minute upper limit; the stack stopped at `fsync` submitted by SQLite WAL, and no assertion failed. After switching to container executable tmpfs, the storage package passed alone in 22.6 seconds, and the full package rerun passed; the Go, Web, and govulncheck CIs of PR #42 initially submitted `a96fc3b` all passed. `audit unavailable` appeared in the previous 50 concurrent HTTP tests of this machine, and the v2.4.0 baseline can also be reproduced after repeated runs; this time, after reducing the packet parallelism, the MCP packet passed. The merge submission CI, formal package upgrade re-verification, dual-architecture signature assets, GHCR, official website and public network Demo that have not been completed in the candidate stage have all been separately recorded in [, the official release evidence ](v2.5.0-release-evidence.md); unverified MongoDB topology or capabilities must not be described as supported.

This conclusion only covers the above-mentioned MongoDB 7.0.43 single instance, test CA, minimum privilege account and controlled reading of synthetic data. Replica sets, sharding, production certificate rotation, large data volumes, long term loads, temporary authorization of tasks, approvals, writes and full production support are not verified. The public Live Demo still uses synthetic PostgreSQL data.
