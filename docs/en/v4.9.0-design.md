# AgentSQL v4.9.0 reliability and measurable compatibility baseline

> Planned release. This document does not claim that the work has shipped or passed acceptance.

## Product and scope

AgentSQL remains an independent AI data-question agent and an independent MCP Server database security gateway. SQLBot Community v1.10.3 is a pinned, optional client baseline, not a runtime dependency for AgentSQL's own questioning. v4.9.0 first addresses the intermittent identity-resolution HTTP 503 seen during 128-authorized-table prewarming on the signed v4.8.1 package, adds privacy-safe prewarm failure classes, and rechecks cold and warm questioning, follow-up questions, restarted history, and revocation.

The release must retain live identity and row/column authorization, controlled execution, return-time rechecks, durable audit, and fail-closed behavior. Browser-supplied connection envelopes are not trusted gateway credentials. Broad Community page, cloud-model, or database-dialect compatibility is outside this release claim.

## Implementation and acceptance

| Item | Completion condition |
| --- | --- |
| Diagnose and fix audit 503 | Reproduce with safe error-class logs and distinguish audit timeout, queue backpressure, uncertain commit, and other causes. Then recheck on the same fixture: 2 CPU/4 GiB ChatBI, 2 CPU/2 GiB gateway, PostgreSQL 17, fixed ONNX, and local Qwen3-4B. Skipping audit, relaxing authorization, or swallowing errors does not count. |
| Observable prewarming | A verified user can see only status for their current binding and a fixed failure class. No table, column, prompt, SQL, credential, or raw downstream error is exposed. Revocation or model shutdown cannot write stale vectors. |
| Questions among 128 tables | Record the cold first question, background prewarm, warm first question, and two-way concurrency. At least three independent cold prewarms must reach `ready`, each with 128 encrypted vectors and passing SQLite integrity. Include every failure in a 20-question indexed warm run and report p50, p95, maximum, and controlled gateway audit. The provisional isolated-host warm p95 target is 30 seconds, not a production SLA. |
| Follow-up and history | The pinned original client and AgentSQL's own page each complete at least two contextual turns against a real model, gateway, and database. Reopen history after restart under current permission; revoked datasource or row/column access must not leak old results, exports, or another user's history. |
| Compatibility score | Freeze the usable SQLBot Community v1.10.3 question scenarios and weights. The previous approximate 60% is only an old engineering estimate. Each score needs exact signed package, client, real model and database, positive and negative paths, and limits; publish the measured score, not a route count or old-commit result. |
| Formal delivery | All exact-commit CI checks pass; production assets and outer archive are signed and independently verified; AMD64 and QEMU ARM64 pass offline real-systemd fresh install, upgrade from v4.8.1, and failure rollback. Verify anonymous GitHub Release/GHCR download, website and clearly simulated-model Demo, and a clean canonical `main`. |

Release notes must say the user's real business system was not validated. They must not claim 100% compatibility, zero-change migration, ARM hardware testing, or a production SLA. Any unexplained identity-resolution 503 or failed security-negative case blocks publication.
