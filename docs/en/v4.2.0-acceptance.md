## Cloud upgrade recovery and limits

On the first Demo switch, the new binary refused to start against old SQLite schema 27. The automated script restored the stopped-volume backup and v4.1.0 Compose configuration, and the old gateway became healthy again. The second attempt stopped traffic and backed up again, explicitly ran v4.2.0 `agentsqlctl migrate` and `migrate --check`, confirmed schema 29, started the new gateway, and repeated internal/external allow, masking, deny and audit checks. No real business database or cloud model was involved.

Evidence covers only the listed synthetic data, client version and local/Demo environments. Complete SQLBot functionality, every page, richer charts and zero-change replacement of the user's actual business system remain unverified; later versions and v4.5.0 retain separate gates. Public Q&A shows only clearly labeled simulations and deploys or calls no real model.
