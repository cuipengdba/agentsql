## Current authorization and model context

ChatBI reads the current gateway-authorized fields and the applicable row and column rules, then narrows the schema sent to the model for the question. It validates the saved relation graph against the full current authorization and only sends relationships whose endpoint fields are present in the selected schema. An unrelated authorized relationship can be omitted without blocking a single-table question. When the current authorized schema fits the table limit, or the first question explicitly names at least two authorized tables, SQL generation can use the confirmed schema without a separate keyword request. If the saved graph refers to a revoked table, join field, or binding, ChatBI rejects the question before model inference and gateway query execution. Relation configuration suggests equality joins. The controlled gateway still binds physical objects, enforces permissions, and records audit evidence.

Terminology and examples stay within their workspace and allowed data sources. Terminology supplies business definitions. SQL examples guide the model as it generates SQL for the current question. Each request checks configuration and the current authorized schema. Test new questions and applicable history behavior after configuration changes, binding changes, and permission changes.

## Acceptance scenarios

| Scenario | What to verify |
| --- | --- |
| Q4 two-table join | Join orders to a region lookup in isolated PostgreSQL. The orders table includes repeated region keys. Compare grouped results with independent SQL and check that the gateway audit names only the expected tables. Unrelated authorized relations stay outside the model context. |
| S1 terminology | Compare the same Chinese question before and after adding, disabling, and deleting a term. Inspect the stored values used by SQL, the returned rows, and data-source and workspace isolation. |
| S2 SQL examples | Compare actual model-generated results before and after enabling an example. Check that disabled examples, other data sources, and references to revoked fields are excluded from the model context. |
| S3 remarks and relations | Update remarks and relations separately and compare table choice, join fields, and results. Revoke a table or field used in a relation and verify that the failed request releases no data. |
