# AgentSQL v3.6.0: Policy delivery, reliable notifications, and long-term audit

**Language:** [English](v3.6.0-design.md) | [Simplified Chinese](../v3.6.0-design.md)

Status: implementation design. Release claims depend on the final code, tests, and deployment evidence.

## Baseline and goal

v3.5.0 has tenant policy bundles, digests, plans, separate-person review, and atomic apply. Policy, Agent, datasource, and relation-binding IDs are environment-local, so a raw bundle cannot be applied in another environment. The notification manager consumes process-local live events and may drop messages on queue overflow, restart, or reload; the durable audit remains authoritative. Audit ZIPs have integrity manifests, while external signed checkpoints and predecessor retention are currently manual.

This release targets three independently verifiable paths: controlled policy transfer across environments, durable retryable external event delivery, and periodically witnessed audit archives. Each path preserves tenant isolation, minimum data exposure, explicit failure states, and audit evidence.

## Operator flow

1. Export a credential-free policy bundle and resource inventory from the source environment. Bind the source tenant and environment, schema, digest, and export time to a signature. Transfer it through an organization-controlled channel.
2. In the target environment, an authorized administrator explicitly selects the tenant and maps each Agent, datasource, and target business table. Preflight shows missing, stale, broadening, and uncertain mappings. Column grants and relation bindings are marked non-transferable and cannot become applicable proposals.
3. Create a proposal against the target's current policy digest, obtain review by another authorized person, and apply only while the digest still matches. Import does not bypass existing review or runtime enforcement.
4. Workers read committed final outcomes from the durable tenant audit stream and compete through persistent tenant/channel cursors and leases. They send stable idempotency IDs, advance a cursor only after acknowledgement, retry failures with bounded backoff, and expose exhausted items for inspection and manual replay.
5. For each fixed audit window, create a tenant archive and externally signed checkpoint. Keep the archive, signature, public-key fingerprint, and predecessor digest in independent storage. Verify the complete chain from externally trusted state.

## Security and failure contract

| Area | Requirement | Failure behavior |
| --- | --- | --- |
| Policy transfer | Sign source environment, tenant, bundle digest, time, and format version. Explicitly remap target identities; never accept target identities or secrets from the source package. | Reject invalid signatures, versions, tenants, mappings, binding fingerprints, or target baselines. Unknown mappings require human resolution. |
| Policy activation | Reuse separate-person review, digest compare-and-swap, and atomic apply. A plan is metadata-only. | Revoked approval, changed permissions, or concurrent policy changes invalidate the operation. Live SQL still passes through authorization, masking, execution, and audit. |
| Event delivery | Read only from the commit-ordered durable final audit stream. Keep a persistent cursor per tenant/channel and a stable idempotency key per event. Delivery is at least once; receivers deduplicate IDs. | Audit failure still fails queries closed. Notification endpoint failure leaves the cursor unadvanced and raises an alert; delivery is not proof of audit durability. |
| Privacy | Use the existing safe projection. Do not send raw SQL, results, credentials, or cross-tenant fields by default. Preserve endpoint SSRF and redirect controls. | Invalid endpoint or secret configuration yields a redacted diagnostic state, never a fallback to an unsafe address. |
| Long-term archive | Bound tenant and time-window pagination; verify sequence continuity, file digests, Ed25519 signatures, predecessor checkpoint, and freshness. Keep the trusted key and predecessor outside AgentSQL. | Missing events, tampering, duplicate windows, stale checkpoints, invalid signatures, or storage failure leave the archive incomplete and the source audit intact. |

This release does not claim third-party WORM certification, indefinite retention, or exactly-once notification. Operators must configure and separately verify immutable retention in their external object store.

## Implementation scope

- Add a versioned, signed, size-bounded delivery envelope. Target import produces a mapping plan and an existing policy proposal, never a direct policy write. The first release transfers only simple rules for exact table names supported by the existing atomic apply path; wildcard names, column grants, relation bindings, row filters, and unrepresentable legacy rules block transfer. Preserve the canonical digest semantics of `agentsql.policy-bundle/v1`.
- Start reliable delivery with the existing webhook transport. Syslog has different acknowledgement semantics and requires a separate claim and acceptance record.
- Reuse the tenant commit sequence assigned in the v3.5.0 audit database transaction. Store tenant/channel cursor, configuration revision, lease, and retry state in shared PostgreSQL or SQLite metadata for three-gateway competing workers, crash recovery, backoff, exhaustion, and manual replay. Read the audit tail before persisting a new channel's starting cursor; this may replay a few pre-activation events but avoids losing later events. Expose backlog count and oldest age. Do not claim atomic commits across separate databases.
- Build on `audit verify-archive` and `checkpoint-create/verify` for fixed windows, chained catalogs, and restore drills. Keep external private signing keys out of gateway configuration and databases.

## Release acceptance

1. On two independent environments with different resource IDs, verify export, signature, mapping, preflight, separate-person review, and apply. Reject cross-tenant access, stale bindings, missing maps, tampering, expiry, replay, and baseline drift.
2. On three gateways, test delivery, temporary endpoint outage, timeout, duplicate response, worker crash, lease expiry, and restart recovery. Compare final audits with unique delivery keys; do not claim network exactly-once semantics.
3. Create and independently verify several archive windows and their signature/predecessor chain. Missing middle package, changed event, old-package substitution, external-storage outage, and wrong key must fail. Recheck trusted predecessor state after paired backup restoration.
4. Verify combined and separate database migrations, old-version rollback, repository quality gates, signed assets, dual-architecture GHCR images, website, and public Demo. Demo claims must match its actual deployment.
