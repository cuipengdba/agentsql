# AgentSQL v2.1.0 YashanDB specified instance candidate acceptance

**Language:** [English](v2.1.0-acceptance.md) | [Simplified Chinese](../v2.1.0-acceptance.md)

Status: Candidate feature verification in progress. The following are actual results from a native isolation environment on 2026-10-19 and are not an official GitHub Release, production customer acceptance, or vendor certification. Formal assets, upgrades, CI, official website and Live Demo must be recorded separately after closure.

## environment and scope

- YashanDB Enterprise Edition 23.4.1.109 x86_64, container image `yashandb:yashandb-image-23.4.1.109-linux-x86_64`, port 1688, `COMPAT_VECTOR=yashan`.
- `yashandb-go v1.4.4` plus standalone C client 23.4.7.100, Linux amd64, CGO, `-tags yashan`. The test container is `golang:1.26-bookworm`. C client redistribution currently only has verbal authorization from the manufacturer stated by the project maintainer, and there is no written document in the repository.
- The `SYS.AGSQL_V21_T_*` authorization table, `SYS.AGSQL_V21_D_*` unauthorized table and read-only account are randomly created in each round, and the synthetic mobile phone number `13800135678` is filled in; SYS is only responsible for table creation, authorization and cleaning, and the AgentSQL data source uses a new read-only account. Genuine library `INSERT` was rejected by the server. The 2 accounts and 2 tables left by the failed attempt have been cleaned up in a targeted manner, and the prefix is ​​queried again to be zero.
- AgentSQL metadata uses temporary SQLite. The basic and dual-client tests use the same database for persistent auditing; the independent audit test uses isolated PostgreSQL 18, and a separate connection is opened for verification after migration. Fault injection is performed separately in the business database and audit library.

## Still needs to be completed and not verified

- GitHub finally submitted CI, official assets/dual-architecture dynamic library and mirror check; v2.0.0 official package upgrade, SQLite and PostgreSQL sub-library complete recovery, official website and Live Demo switching have not yet been declared approved in this document.
- Client cancellation, SQL timeout, and server-side execution stop have not formed verifiable evidence in this specified instance; TLS certificate verification, writing, transactions, EXPLAIN, complex JOIN, functions, system directories, active/standby switchover, sustained load, and aarch64 YashanDB server are not verified or remain closed.
- The MCP data source visibility preflight audit only covers the `query` and `execute_write` unauthorized data sources of authenticated Agents. Non-SQL tools such as `list_schema`, missing required parameters, or failed identity authentication do not belong to this traffic audit path. When the target table policy is revoked and the data source is still visible, R010 is still logged by the pipeline.
- Qualified conclusions only apply to the above product versions, compatibility modes, drivers, clients, x86_64 isolation containers and synthetic data. There is no written manufacturer's redistribution authorization or customer production acceptance, and no "full production support" or "manufacturer certified" expressions are used.
