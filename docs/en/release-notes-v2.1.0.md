# AgentSQL v2.1.0 Release Notes

**Language:** [English](release-notes-v2.1.0.md) | [Simplified Chinese](../release-notes-v2.1.0.md)

v2.1.0 Deepens controlled read-only validation of YashanDB YashanDB specified instances. Previously, there were independent drivers, narrow SELECT dialects and test fixture pipelines; this version strings real minimum privilege accounts, HTTP MCP, table permissions, masking and persistent auditing into the same repeatable test chain, and uses MCP Inspector and Dify to actually call it. Business database disconnection and independent audit database outage are verified based on the principle of no original result delivery.

Verified on Linux x86_64 instances of YashanDB Enterprise Edition 23.4.1.109, `COMPAT_VECTOR=yashan`, `yashandb-go v1.4.4`, and standalone C client 23.4.7.100. The AgentSQL data source uses a temporary read-only account, and the server itself rejects INSERT. SELECT subsets of single table, explicit column projection and bounded WHERE can be executed according to the Agent policy; R010 of the override table is rejected, the mobile phone number is masked according to the table rules, and the decision is written to the persistent audit database. The adapter is still not open for writing, transactions, and EXPLAIN.

## Upgrade and support boundaries

- There are no metadata or audit schema changes in this release. You should still back up the complete set of metadata/audit according to the deployment document first, and practice migration, recovery and rollback from the v2.0.0 official package. Dual-gateway Kubernetes deployments still require maintenance windows; this release does not extend their database adaptability or promise no-downtime rolling upgrades.
- Tests of real clients and specified YashanDB instances use synthetic data. Support declared for **A controlled read-only subset of the specified version, specified schema Verified**, not full production support for all YashanDB versions or production topologies. TLS certificate verification, active/standby switching, continuous load, complex SQL, functions, system directories, client cancellation and timeout termination are still subject to actual subsequent acceptance.
- C Client redistribution is based on verbal authorization from the manufacturer as stated by the project maintainer, and the repository does not have written authorization documents; it does not claim manufacturer certification. When building by yourself, you still need to obtain a client that matches the architecture, compile it with `CGO_ENABLED=1` and `-tags yashan`, and set the runtime path. Failed to close when driver or client library is missing.
- This version completes the `query`/`execute_write` data source visibility preflight rejection audit for certified Agents. After the last allow policy is revoked, it will still not reach the business database, but `deny` will be recorded persistently and the audit ID will be returned; if the audit is not available, an error will be returned. This path does not save unparsed SQL, and non-SQL tools such as `list_schema` and authentication failures still do not belong to SQL traffic auditing.

For real database testing, failed attempts and unverified range, see [v2.1.0 and acceptance record ](v2.1.0-acceptance.md). For the execution results of the official CI, installation package, image, official website and Live Demo, see [v2.1.0 and release evidence ](v2.1.0-release-evidence.md).
