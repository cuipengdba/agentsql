## Code and page boundaries

- PostgreSQL, Dameng/Oracle narrow SQL path and MySQL two result paths check the request context again after reading the row; cancellation or timeout must not deliver collected sensitive rows. `TestPostgresQueryRejectsCancellationAfterRows` and `TestSQLQueryRejectsCancellationAfterRows` have been adopted in Go 1.26 containers.
- The Dameng connection uses the network deadline set according to the data source statement timeout, and directly closes the physical connection bound to the request when canceled; in order to bind the connection establishment context to a single request, the Dameng read-only pool does not retain idle connections. `TestDMDeadlineConnClosesBlockedSocket` has passed, and the real database lock waiting use case has also passed; the performance impact caused by reduced connection reuse has yet to be quantified by load testing.
- Stateless 2026-07-28 MCP endpoint enables request cancellation propagation; legacy stateful `/mcp` continues to be guaranteed safe termination by an independent deadline so as not to break existing rollback constraints for B5 sessions. The final real database use cases of the three manufacturers all distinguish between these two paths.
