# AgentSQL v3.1.0 acceptance record

**Language:** [Simplified Chinese](../v3.1.0-acceptance.md) | [English](v3.1.0-acceptance.md)

Status: candidate acceptance in progress. The following results use isolated synthetic data; formal release status is in the [release record](v3.1.0-release-evidence.md).

## Environment and live results

The Windows host runs Docker Linux containers on an isolated network and named volume, AgentSQL candidate image `agentsql:v3.1.0-acceptance3`, pinned SQLBot v1.10.2, PostgreSQL 16 synthetic orders and products, and a local Qwen3-4B model. SQLBot has an intentionally invalid direct database address, so business requests must pass through AgentSQL. Two SQLBot workspaces and people map to distinct AgentSQL people and read-only Agents. The public Demo was not touched.

| --- | --- | --- |
| Natural-language SQL, real rows and a chart with a numeric vertical axis | Final candidate passed all six checks with three rows in 145.593 seconds | `sqlbot-data/qa-a-ask-final.json` |
| Approval request, administrator decision and original-user one-time execution with B2 explicitly off | Passed; product ID 1 and execution audit ID 348; replay returned HTTP 400 | `sqlbot-data/approval-request.json`, `approval-status.json`, `approval-execute.json`, `approval-replay.json` |
| Approval request with B2 enabled | Failed closed with HTTP 400; B2 was not disabled automatically | `sqlbot-data/approval-b2on.json` |
| Cross-workspace/user, Agent and datasource scope, revocation, audit failure and recovery | All 17 checks passed; audit failure returned neither rows nor a new identity | `live-security.json` |

The live scripts are `scripts/v3.1.0-sqlbot-business-acceptance.py`, `scripts/v3.1.0-gateway-acceptance.py` and `scripts/v3.1.0-live-security-acceptance.py`. Approval submission does not execute SQL; only the original user can consume the sealed SQL once after approval. Rejections are not automatically rewritten and retried by the model.

## Local regression gates

- `go test -short -p 1 -count=1 -timeout 15m ./...`: exit code 0 on Docker Linux tmpfs; every Go package passed. Full local output: `go-full-tmpfs-final.log`.
- PostgreSQL 18 container `TestSQLBotPostgres18UpgradePersistenceAndAuditRollbackE2E`: both combined and separate layouts passed with exit code 0; local log: `postgres18-upgrade-final-ryukoff.log`. The test disabled the Ryuk reaper, which could not become ready under this Docker Desktop network.
- `python -m unittest discover -s /tmp/agentsql-sqlbot -p 'test_*.py' -q` inside the pinned SQLBot image: 31 tests passed.
- `scripts/v3.1.0-sqlbot-compatibility-acceptance.py` in a disposable SQLBot container without network or business volumes: eight pinned files passed; injected installed-file drift and unknown upstream source were both rejected.
- Web `vitest run`: 18 files and 58 tests passed; `tsc --noEmit` exited 0; the English catalog covers 1,454 Chinese literals.
- `scripts/check-docs-i18n.py`: 195 documents and two sites passed structural checks; `git diff --check` passed.

## Boundaries and environment observations

- The PostgreSQL B2 column authorization executor does not currently support approval execution. The gateway rejects requests when B2 is enabled; complete approval acceptance covers only the isolated configuration with B2 explicitly off and does not replace a B2 production deployment.
- The B2 executor requires explicit `pg_catalog` qualification for allowed functions. Model-generated unqualified `COUNT(*)` is denied and audited; the adapter does not rewrite it.
- On this machine's ordinary Docker storage, the 50-concurrent-request test exceeded the audit-chain timeout. The v3.0.2 control reproduced it; the same assertions passed three consecutive times on Docker tmpfs. Release CI remains required.
- Initial cross-system writes to a Windows bind-mounted SQLite fixture corrupted that isolated sample. It was restored from backup and subsequent acceptance uses a Linux named volume. No production data was involved.
