# AgentSQL v2.6.0 Design: Redis/Valkey controlled read

**Language:** [English](v2.6.0-design.md) | [Simplified Chinese](../v2.6.0-design.md)

Status: In progress. The previous version v2.5.0 has been officially released and accepted by the public network; this version must be marked as released after the real database, client, upgrade and public delivery have all passed.

## User problems and goals

The existing Redis/Valkey data source only provides administrator connections, enumerations, and native command previews. Agent MCP does not have provable key-level authorization, masking, and persistent audit chains. v2.6.0 Builds open narrow-shape accurate key reads for a given Redis and Valkey single instance, clarifying version and topological boundaries. The candidate real libraries are Redis Open Source 8.2.9 and Valkey 8.1.10; ultimately, the pulled image digest and the version returned by the server shall prevail. [Redis 8.2 release record ](https://redis.io/docs/latest/operate/oss_and_stack/stack-with-enterprise/release-notes/redisce/redisos-8.2-release-notes/) and [Valkey official download page ](https://valkey.io/download/) were checked on 2026-10-20.

## Candidate Security Contract

1. The new MCP tool `read_key` only accepts data source IDs and exact key names. The execution path is fixed to `TYPE` and then `GETRANGE key 0 65536`, and the detection of reading one more byte exceeds 64 KiB; only UTF-8 strings are delivered. The client is prohibited from passing in native command strings, wildcards, scripts, writes, administrative commands, SCAN, and cross-DB SELECT. Other Redis types are rejected by this version.
2. Agent identity is revalidated with the tenant each time; strict TLS + ACL user connections are established using current data source configuration and secrets. The database number is fixed by the data source and overwriting by request is prohibited; source database changes, key and certificate rotation must take effect immediately. Anonymous and unauthenticated TLS cannot enter the controlled path.
3. The new policy type `key` is separated from the SQL table policy, in the format `dbN:exact-key` or `dbN:bounded-prefix*`; `N` is a fixed 0–15 for the data source, the key is at least three safe ASCII characters, and the deny rule takes precedence. Unbounded `*`, cross-database prefixes, and SQL table grant override key grants are prohibited. The test server ACL is only granted to `customers:*` and `PING`, `HELLO`, `INFO`, `TYPE`, and `GETRANGE`.
4. The maximum size of returned data is 64 KiB, the execution timeout does not exceed 2 seconds, and the connection pool is limited by the data source. masking is performed according to the `dbN`, precise key and `value` sources; no value will be delivered when the masking configuration is incorrect, the audit preflight fails, the final state audit fails, or the result structure does not match. Audit object records isolate HMAC-SHA256 identification by deployment key and data source, without writing the original key value or credentials.
5. The old native command preview on the management side is not counted in the Agent-level production link. Redis/Valkey still only marks the limited functions of specified versions and specified single instances, and does not have full production support.

## acceptance matrix

- Standalone Redis 8.2.9 and Valkey 8.1.10 specify image digest, TLS test CA, minimum ACL user, synthetic phone number and secret value. The current image has been started, and the authorization and out-of-bounds reading of the minimum ACL have been verified by the respective CLI.
- Real HTTP MCP, MCP Inspector, and Dify each allow/deny calls; key prefix out-of-bounds, wildcards, dangerous commands, cross-repository, wrong certificate/password, policy revocation, and ACL revocation are all rejected.
- Persistent audit pre-check/final status, masking and fault closure; stop the independent audit database and business database, then restore it, and check that there is no original value delivery.
- v2.5.0 officially package data for SQLite and PostgreSQL metadata/audit complete set of backup, explicit migration, old version read-only check and recovery; dual architecture signature, GHCR, official website and Demo public network acceptance.

## Implemented boundaries

- The management policy API and console respectively constrain `dbN:key-prefix*` and do not reuse SQL wildcard authorization.
- Redis / Valkey server version, ACL/TLS behavior, dual clients and failure recovery see [ Candidate Acceptance ](v2.6.0-acceptance.md).
- Key names may contain sensitive data; auditing only retains key digests, decisions, and audit IDs, and administrators use the audit ID to locate the call.
