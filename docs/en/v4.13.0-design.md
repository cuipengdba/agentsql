# AgentSQL v4.13.0 authorized-result charts

## User goal and scope

AgentSQL is an independent AI Q&A Agent and an independent MCP Server database security gateway. Based on released v4.12.0, this version lets users visualize a currently authorized result as bars, lines or a pie, explicitly select a dimension and up to four measures, and reopen history using current authorization and the question's persisted default chart metadata.

The existing frontend can choose an identifier as the first numeric measure, coerce empty strings or booleans into numbers, hide all-zero results and connect lines across missing values. This release fixes these reproducible issues and adds multi-measure mapping and explicit missing-value and precision boundaries. Charts project current results; they introduce neither query authority nor a stored result cache.

## Implementation contract

- Fields come only from the current controlled response. Select a dimension and up to four measures; the raw table remains available and switching does not query the database. Interactive choices live only in the current view, without browser persistence; reopening uses the metadata default generated for the question.
- Values must be finite decimals or decimal strings. Missing values are not zero. Booleans, blanks, hexadecimal, nonfinite values and values beyond JavaScript's safe numeric range are not plotted. Lines break at missing points; all-zero charts remain valid. Pie charts require one nonnegative measure with a positive total and never silently discard negative values.
- Display at most the first 20 current rows, with visible row counts and gateway truncation state. Preserve original table values. Insert field names and labels as text nodes, never as HTML, scripts, arbitrary styles or browser-provided SQL.
- An explicit bar/column/line request with one category and up to four provably numeric result fields creates field-name-only metadata for the pinned original client and native page. Pie charts require one measure. Ambiguous or unsupported shapes fall back to a table; metadata contains no row values.
- History retains live identity, binding and policy-fingerprint checks and a controlled reread. Chart switching cannot bypass policy changes, deleted conversations or audit failures. Changing page or identity clears the old chart.

Complete five exact-commit CI jobs, production dual-architecture assets and outer-archive signatures independently verified with a trusted public key, AMD64/QEMU ARM64 offline systemd install/v4.12 upgrade/failure rollback, GitHub Release, anonymous GHCR pulls, website and simulated Demo, public smoke tests, latest promotion and clean canonical main.

## Boundaries

No 80%/100% compatibility, arbitrary charts, custom JavaScript, production SLA or new database production-support level is promised. The user's business system remains untested. QEMU is not physical ARM; public Q&A Demo stays explicitly simulated. Use the raw table for exact large integers or complex values; charts use finite-precision numbers. Previously delivered client data cannot be recalled: local switching projects that response, while new loads and history reopening require fresh authorization.

The release toolchain is upgraded to Go1.26.11 to fix the net/http request-body-limit header race GO-2026-6859. CI, Rocky dual-architecture native packages and Docker builds use this patch version. Offline caches are verified against official pinned AMD64/ARM64 SHA256 values; vulnerability checks are not suppressed.
