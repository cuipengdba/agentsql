## Completed pre-release testing

| range | results and boundaries |
| --- | --- |
| Front-end and official website | The console type check, build and 54 tests of 16 Vitest files passed; the official website static verification passed 8/8, and three v0.9.0 PDFs have been generated. |
| Task Key | By default, one authorization in the synthetic environment is issued after approval by a different person; MCP Inspector accurately queries for the first time and returns masking results and atomic deductions. The second time is rejected and no business data is returned. There are a total of 5 associated audits for application, approval, issuance and two traffic flows. PostgreSQL metadata/audit branch end-to-end testing to verify 1 budget deduction and rejection again. |
| MCP Inspector 2.11.0 | Both `/mcp` and `/mcp/2026-07-28` passed the strict tool schema verification; both entrances completed allow query, `R010` rejection, mobile phone number masking and persistent audit. 16 tools for the old entrance and 8 tools for the new entrance. |
| Dify 1.17.1 | Isolated self-hosted workflow calls standalone Agent identity via `/mcp`; allow query returns 1 row and `138****5678` (audit ID 12), explicitly deny table returns `R010` (audit ID 10). This result does not generalize to modern portals that Dify did not test. |
| Domestic database | DM8 Pack3, KingbaseES V9 PG mode, and Vastbase G100 Build 9 all use restricted accounts and synthetic data to complete bounded query, rejection, masking, and audit review in designated isolated instances; it does not mean that other versions, dialects, or production workloads have obtained manufacturer certification. |
| Strategy and audit operation and maintenance | Offline preflight returns "Unknown" for allowed candidates and "Rejected" for rejection tables; the outbox status of the merged library is clearly not applicable, and tenant isolation, backlog and retry statistics are covered by unit tests. The end-to-end use case of the PostgreSQL metadata/audit sub-library verifies the status reading of 3 events to be delivered in the current tenant. |

## Thresholds that must be passed

| range | Acceptance requirements |
| --- | --- |
| Task Key Budget | Default 1 time, explicit 1–10 times, concurrent atomic deduction, expiration/revocation/exhaustion rejection, old key compatibility, audit failure will not return results |
| sensitive derived output | PostgreSQL/MySQL expressions, aggregations, set operations, CTE/views, aliases and unknown source negative sets; the original text must not appear in the returned results and auditing |
| Audit operation and maintenance | Sub-library outbox status is isolated by tenant; backlog, retry, and status read failures are visible |
| Policy preflight | Only explicit rejection or unknown, never false positive permission; no business database execution or traffic audit writing |
| Upgrade recovery | v0.8.0 official package to v0.9.0 official signature package, SQLite merged library and PostgreSQL metadata/audit sub-library complete backup and recovery |
| Real client and database | Bounded regression of Dify, MCP Inspector, DM8, KingbaseES V9, Vastbase G100 in specified accepted environment |
| publish | Submit CI at the same time, 15 assets with three signatures, dual-architecture GHCR public anonymous pull, official website 3 PDFs, Demo backend same version and public network smoke test |

After release, the submission, CI, signature, image summary, official website and Demo public network smoke test evidence are written into the main text of [v0.9.0 GitHub Release](https://github.com/cuipengdba/agentsql/releases/tag/v0.9.0).
