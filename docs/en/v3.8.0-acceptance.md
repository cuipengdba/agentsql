# AgentSQL v3.8.0 Acceptance Record

**Language:** [English](v3.8.0-acceptance.md) | [Simplified Chinese](../v3.8.0-acceptance.md)

Status: formally released. The results below cover only isolated Docker databases, least-privilege roles, and synthetic data on 2026-10-24. The formal SHA, CI, signed assets, GHCR, website, and public Demo are recorded in the [release evidence](v3.8.0-release-evidence.md).

| Item | Environment and result |
| --- | --- |
| ClickHouse budgets | Pinned image digest `sha256:05d2e46507afdcf08da46e5528b68847104dbbed691c327e505414b4b7f4e4c8`, server 26.8.31.2, native TLS, `readonly=1` role, and five `CHANGEABLE_IN_READONLY` settings. With a custom 100-row/64-KiB/32-MiB budget, the three-row table succeeds and an over-budget scan of a 2000-row synthetic table is rejected. HTTP MCP exact column grants, masking, parameter binding against injection, bad CA, and revocation pass. |
| Milvus tenant filters | `milvusdb/milvus:v2.6.25` digest `sha256:29f7668e64df1c6d5cdadbfbee99f38c72e4001054f149a298725acae57230ad`, TLS/authenticated standalone, Search role scoped to one collection, synthetic records for two other tenants and the default tenant. The real database returns only approved equality-filtered records for the default tenant; other-tenant hits are withheld. Zero hits produce a valid empty result for the pinned SDK response shape. Caller-supplied tenant fields and unknown filters are denied. HTTP MCP exact field grants, masking, audit, and revocation pass. |
| Two clients | MCP Inspector 0.16.8 and Dify 1.17.1 MCPClient each run allowed and denied ClickHouse and Milvus calls with masked output and durable audit IDs. Raw synthetic phone numbers and cross-tenant records are withheld. ClickHouse Inspector audit IDs 14/15, Dify 17/18; Milvus Inspector 8/9, Dify 11/12. |
| Fault closure | When the separate PostgreSQL 16 audit database stops, neither HTTP MCP read delivers values; both recover after restart. Stopping ClickHouse or Milvus likewise withholds results, followed by successful recovery when the database and search channel are ready. The isolated scripts report `V380_CLICKHOUSE_AUDIT_BUSINESS_FAULT_RECOVERY=PASS` and `V380_MILVUS_AUDIT_BUSINESS_FAULT_RECOVERY=PASS`. |
| Upgrade and rollback | Starting with the official v3.7.0 Linux amd64 package and a SHA256-verified synthetic SQLite snapshot, both v3.7.0 and v3.8.0 `agentsqlctl migrate --check` report metadata 27/27. The v3.8.0 no-op migration leaves the SQLite SHA256 unchanged; after restoring the paired backup, v3.7.0 passes again: `V380_SQLITE_FORMAL_UPGRADE_RESTORE=PASS`. In isolated PostgreSQL 18 metadata/audit databases, the formal v3.7.0 binary migrates to 25/7 before both are backed up. The v3.8.0 candidate rechecks/migrates them, then both are restored and rechecked by v3.7.0 with synthetic records preserved: `V380_PAIRED_POSTGRES_UPGRADE_RESTORE=PASS`. |

Full production support is not claimed. ClickHouse clusters or other versions, Milvus clusters, arbitrary expressions, non-ASCII scalar values, long-duration loads, and customer production data remain untested. See the [design](v3.8.0-design.md) for the contract and the [upgrade guide](v3.8.0-upgrade.md) for rollout steps.
