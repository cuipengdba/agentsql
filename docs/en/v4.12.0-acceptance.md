# AgentSQL v4.12.0 acceptance and scope

AgentSQL is both an independent AI data Q&A agent and an independent MCP Server database security gateway. This release focuses on history, export and conversation lifecycle: current policy and identity are rechecked after a durable export receipt; the native page clears old results on failure and fences late history responses and downloads. SQLBot is not a runtime dependency of the Q&A service.

## Performance and untested boundaries

One cold native API question including current history readback took 80.469 seconds; one original-page question recorded about 42.245 seconds. After ChatBI restart and health readiness, the first CSV without an earlier historical requery returned HTTP200 in 12.686 seconds; the following XLSX returned HTTP200 in 10.310 seconds. These are single observations on a shared test host, not p95, throughput or a production SLA.

Accepted original-page history originated from an actual original-page question. Reopening an API-created initial placeholder across clients remained loading and was not accepted; arbitrary cross-client history interchange is not promised. An ambiguous follow-up with all target columns hidden exceeded a 45-second client budget and did not pass. An explicit target-table question with the same 300-second acceptance budget used for other real questions returned an error event without result or new query. An initial broad local short-test run timed out at SQLite fsync and was not counted; final exact CI full-package short tests and local tmpfs short tests passed, while real Linux volumes and systemd scenarios separately checked persistence.

The user's real business system is untested. This release does not promise 80% or 100% compatibility, zero-change switching, arbitrary connection creation, real cloud inference or a new database production-support level. Previously delivered data or downloaded files cannot be recalled; this release governs each new history read and download response.
