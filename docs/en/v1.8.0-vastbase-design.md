# v1.8.0 Vastbase G100 detailed design

**Language:** [English](v1.8.0-vastbase-design.md) | [Simplified Chinese](../v1.8.0-vastbase-design.md)

Status: Under development. The target instance is Vastbase G100 V3.0 Build 9, commit 30156, PG compatibility mode. Other builds, modes, licenses, and deployment topologies are subject to separate acceptance.

## User issues and scope

v1.6.0Verified bounded read-only SQL, security policy, masking, persistent auditing, and single-instance failure shutdown for the specified instance.v1.8.0Focus on completing the server-side identity verification and deployment constraints of this path to prevent administrators from mistakenly thinking that "PG compatible" automatically means secure TLS or full production support. The query scope continues to be limited to clear schema, with`WHERE`and`LIMIT`single table`SELECT`;Continue to reject writes, cross-table queries, unbounded queries, and objects not explicitly authorized.

Goal:

1. The management API and console save and display `verify-full`, CA files, and certificate hostnames; bad CAs, bad hostnames, and insecure trust options all fail to close.
2. Verify correct TLS, bad certificates, clear text deny, allow query, unauthorized deny, masking, and persistent auditing on an isolated G100 Build 9 instance with a least privilege read-only account.
3. Document trial licenses, protocol versions, and deployment methods; certificate and credential rotation, failure recovery are stated based on actual results only.
4. Complete the upgrade from the previous official version to the candidate version and complete backup and recovery without implicitly changing the database schema.

Non-target: Declare active-standby high availability, vendor certification, production capacity, or full production support when there is only one trial-licensed instance. If formal permission and a verifiable active/standby topology cannot be obtained, this item is left as an explicit unverified boundary.

## secure link

`MCP 客户端 → Agent/租户身份 → 数据源与对象授权 → SQL 解析及只读限制 → G100 PG 模式的只读账号与 verify-full TLS → 有界结果 → 列脱敏 → 持久 allow/deny 审计`. When the audit library is unavailable, the request fails and is closed; connection, certificate or account rotation errors cannot return a clear text connection. The server must also set `hostnossl ... reject` for the read-only account so that other clients cannot use clear text to bypass TLS requirements.

## Specify TLS deployment constraints for the instance

In the isolation test, G100 `ssl=on`, server certificate and key permissions are `0600`, `require_ssl=off`, and `hostnossl ... reject` is configured first for the read-only account in `pg_hba.conf`. When `require_ssl=on` is enabled, the G100 rejects protocol 3.0 startup packages driven by the current `pgx`, even if the TLS handshake succeeds; this switch is therefore not an available configuration for this adaptation path. `verify-full` Client uses CA and hostname verification, disallowing downgrade to clear text. This conclusion comes from the isolated actual measurement of the specified Build and is not generalized to other versions or drivers.

The manufacturer's documentation respectively describes [G100's SSL connection ](https://docs.vastdata.com.cn/zh/docs/VastbaseG100Ver2.2.5/doc/%E5%BC%80%E5%8F%91%E8%80%85%E6%8C%87%E5%8D%97/%E6%95%B0%E6%8D%AE%E5%BA%93%E4%BD%BF%E7%94%A8/%E8%BF%9E%E6%8E%A5%E6%95%B0%E6%8D%AE%E5%BA%93.html) and [ image license mounting methods ](https://docs.vastdata.com.cn/zh_CN/VastbaseG100/V2.2.14%20%28DMR%29/1/8e6e35101302438caf6008011852c41f). The actual configuration and compatibility are subject to the evidence of this Build 9.

## Release blocking use case

| path | expected |
| --- | --- |
| Correct CA, hostname, and read-only credentials | TLS query successful, retaining agent identity and persistent allow auditing |
| Bad CA, bad hostname, explicit trust unverified certificate | Connection refused; no clear text fallback |
| Read-only account of `sslmode=disable` | Server HBA rejects |
| No authorized objects, write statements and out-of-bounds queries | AgentSQL deny and log deny |
| Sensitive columns such as mobile phone numbers | Return the masking value without revealing the original text |
| Audit library disconnection, client cancellation, database disconnection | Failed to close, and can explain the final state |
| Certificate and password rotation | Old credentials/old trust failed, new configuration restored; only claimed based on actual testing |
| Active/standby switchover | Requires formal licensing and true active/standby topology; flags not verified when missing |

The final release scope is subject to the acceptance record and official Release.
