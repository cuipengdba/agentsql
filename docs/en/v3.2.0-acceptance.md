# AgentSQL v3.2.0 Candidate Acceptance

**Language:** [English](v3.2.0-acceptance.md) | [Simplified Chinese](../v3.2.0-acceptance.md)

Status: candidate acceptance in progress. This record lists completed checks in an isolated synthetic environment. Formal assets, CI, website, and public Demo require separate verification.

## Live environment and results

The environment uses an isolated candidate gateway, the pinned SQLBot v1.10.2 derivative image, MySQL Community Server 8.4.11 with synthetic orders, a local model, and a PostgreSQL 16 B2 test container. SQLBot's business datasource has an invalid direct connection address, so business SQL must pass through AgentSQL. The MySQL binding uses a real signed-in user, a dedicated read-only Agent, qualified `agentsql_demo.table` permissions, and explicit numeric result aliases.

| Check | Result and evidence |
| --- | --- |
| SQLBot MySQL schema and chart | Real login, table discovery, and selection passed. The model generated grouped MySQL SQL, returning four rows and a bar chart with a numeric Y axis. All six question checks passed in 110.59 seconds. Local synthetic evidence: `sqlbot-mysql-group-chart.json`. |
| MySQL identity and SQL boundaries | Seven checks against the real gateway passed: an authorized backtick-quoted query received a durable audit ID; cross-user, cross-workspace, cross-datasource, writes, side-effecting functions, and multiple statements were rejected. ## Acceptance boundary

The local MySQL chart relies on explicitly configured numeric result aliases such as `order_count`. The model chose a table for a single-count question; that was not a chart failure. SQLBot chat storage did not retain the adapter's internal `agentsql.audit_id` extension field, so durable gateway records are the audit evidence. The results cover only the specified versions and synthetic single-instance setup, not every database, cluster, or production SLA.
