## Verified paths

| Check | Result |
| --- | --- |
| Kingbase read and columns | PG protocol, SCRAM, bind parameters, least-privilege query, phone masking, R006 denial and audit passed on the pinned build. The live B2 catalog-closed matrix passed single-table `SELECT` and allowed/denied column checks. B2 writes were not qualified. |
| Kingbase write closure | Live B5 DML produced an affected-row count inconsistent with the PostgreSQL contract. Write sessions, transactions, direct execution and B5 DML entry points deny a detected KingbaseES kernel or failed identity probe; the live negative test passed. |
| Kingbase external clients and recovery | On the v3.4.0 candidate binary, allowed and denied calls from MCP Inspector 0.16.8 and Dify 1.17.1 MCPClient passed and added four durable audits. Revoking the Agent table policy and database `SELECT` returned no sensitive result; restoring access recovered a masked result. Disconnecting the private network returned no allowed result, followed by masked and audited recovery. |
| Vastbase types and plans | Integers, exact numerics, Chinese text, date/time, booleans, binary data, JSONB and `NULL` passed. The real multiline `vb_version()` matched the pinned Build/commit. Unit and live evidence covers physical scan estimates under `LIMIT` and rejection of unknown nodes. |
| Vastbase MCP controls | Live query, denied table and write, phone masking, single-use approval, denial after changes and durable audit passed. Revoking database `SELECT` withheld sensitive values; restoring it recovered masked, audited results. A network outage returned no allowed result, followed by masked and audited recovery. |
| Vastbase external clients | MCP Inspector 0.16.8 and Dify 1.17.1 MCPClient each made one allowed and one R010-denied call, adding four durable audits. Every allowed result kept the phone number masked. |
| Vastbase TLS and rotation | A correct CA and hostname connected; wrong CA, wrong hostname and plaintext were denied. New connections verified a hot-reloaded server certificate. After read-only credential rotation, the new password worked and the old one was denied. |
| Vastbase bounded load | Twelve real MCP calls with concurrency 2 and pool limit 2 all returned masked values and separate durable audits. Isolated-sample P50 was 6.8 ms and P95 was 42.4 ms. This is not a production SLA. |
| General regression | Go 1.26.10 container `go test -short -timeout 20m -p 2 ./...` passed. The existing 10-agent/50-synchronized-request case passed three successive runs on Docker tmpfs; a persisted temporary directory triggers the previously documented SQLite synchronous-write timeout, described in the [historical diagnosis](v0.5-known-issues-task7.md). |

## Closed paths and retest requirements

The live Vastbase G100 B2 probe returned `AUTH_DATABASE_ERROR`, so column authorization remains fail closed. Kingbase B5 writes remain closed because they do not meet the PostgreSQL affected-row contract. Neither database is claimed as fully production supported. Formal primary/standby, clusters, other builds, vendor certification and production load were not accepted. A deployment needs its own certificate, least-privilege and operational fault retests.
