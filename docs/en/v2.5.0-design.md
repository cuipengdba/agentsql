# AgentSQL v2.5.0 Design: MongoDB controlled read-only

**Language:** [English](v2.5.0-design.md) | [Simplified Chinese](../v2.5.0-design.md)

Status: Implementing. This version only establishes Agent-level bounded read paths for designated MongoDB 7.0 single instances; the scope of support is subject to the real database acceptance record.

## User tasks and current gaps

Enterprise AI assistants need to read a small number of business fields from a designated collection, while letting data administrators limit the collection, hide sensitive values, and trace every allow, deny, and failure. The existing MongoDB adapter only provides a preview of the management-side native commands; the local log of this path does not contain agent-level persistent auditing and is not suitable as the basis for MCP authorization.

## Delivery scope

| path | constraint |
| --- | --- |
| MCP `find_documents` | Binds the current Agent; only accepts specified databases and collections from authorized data sources, explicit fields, at least one string equivalent filter, and a 1–100 row limit. Query results are returned by field and complete documents are not returned. |
| Database access | Must use strict TLS, authenticated least privilege accounts, and read-only `find`; rejects unknown MongoDB major versions, operators in collection names/field names, nested paths, arbitrary pipes, scripts, write commands, and unauthorized fields. |
| Configuration changes | Each controlled read uses the current data source configuration to establish a read-only connection, and does not reuse the native preview connection cached by the data source ID; changes in account, database, certificate, or host cannot continue to use the old connection. |
| Authorize | Each call revalidates the Agent, data source, and current policy. The collection must have precise authorization, and the explicit column policy further restricts the result fields and filter fields; the next call after revocation is rejected. |
| masking and auditing | Apply existing data source masking rules to source-determined projected fields. Write persistent preflight audit before database access, and write allow/deny/error audit after completion; no data will be returned when the final audit fails. Auditing does not log query values ​​or connection credentials. |
| client | Allow and deny real HTTP MCP calls on MCP Inspector and Dify MCPClient respectively. |

Aggregation, `distinct`, `count`, sorting, paging, nested fields, array fields, writing, cross-collection query, temporary task authorization and approval execution are not supported at the moment. The native preview on the management side maintains the existing connection-level capabilities and is not included in this version of MCP secure links. The public network demo maintains synthetic PostgreSQL data.

## Call and fault boundaries

`MCP 身份 → 当前 Agent 与租户 → 数据源归属 → 精确集合/字段策略 → 输入封闭验证 → 持久预检审计 → 严格 TLS/最小权限 MongoDB find → 投影字段结构校验 → 脱敏 → 持久终态审计 → MCP 响应`。

Negative acceptance covers cross-Agent/tenant, policy revocation, no filter conditions, operator injection, extra fields, implicit `_id`, database account revocation, untrusted certificate, connection disconnection, audit database failure and timeout. The business database must not be accessed when preflight auditing is unavailable; results must not be returned to the client when final auditing is unavailable. Real database testing needs to record the precise server version, image summary, TLS, account permissions and synthetic data range.

## Publishing standards

This version completes source code CI, front-end and back-end regression, real client and database, upgrade and recovery from v2.4.0 official package, dual-architecture signature assets, GHCR, official website and Live Demo public network re-verification in accordance with `docs/RELEASE_ROUTINE.md`. Failures may not claim official release or full production support.
