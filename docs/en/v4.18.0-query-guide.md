# AgentSQL v4.18.0 · Native Q&A, MCP, and embedding

**Language** [English](v4.18.0-query-guide.md) · [Simplified Chinese](../v4.18.0-query-guide.md)

## Independent Q&A agent

1. Register PostgreSQL in the gateway. Configure catalog, table, column, and query permissions, then bind the source to each authorized member.
2. Configure a local model in the AgentSQL workspace. Sign in as a member and pick a visible source. On the synthetic orders table, ask “What is the total order amount by region?”
3. Check the chart, data, and query record. Refreshing or reopening history checks current authorization. An administrator can locate the query in the gateway audit.

## Standalone MCP Server security gateway

1. Deploy the gateway as described in [Product modes](PRODUCT_MODES.md). In a PostgreSQL catalog authorization deployment, follow its restart procedure after registering a new source and confirm the connection and catalog binding are active.
2. Configure a dedicated Agent for the external application. Bind the required datasource, tables, columns, and read-only access.
3. Configure the client's Streamable HTTP gateway URL `https://<gateway-host>/mcp`. Supply its Bearer credential using the client's credential settings. Call `list_datasources`, `list_schema`, and `query` in order.
4. Check the caller, data objects, and audit in gateway administration. After rotating the credential, update the client's credential settings and start a new session.

## Combined use and page embedding

Native Q&A and external MCP clients can share a gateway. Configure the member binding and the external application's Agent separately. Check query results and audits against their respective identities.

A basic assistant runs on a dedicated `chatbi serve --assistant-only` listener and queries with the approved guest identity. Configure the host origins and datasources, then load the unmodified `assistant.js` on the separate origin.

Give a Type 4 page a separate browser origin. Use a restricted reverse proxy to serve the original page assets and forward only the embed handshake and scoped query, datasource, and history APIs. Keep administrator login and management APIs on the private address. The host signs a short-lived identity assertion and queries use the current member binding. Follow the [SQLBot client guide](SQLBOT.md) to configure the gateway, then verify queries, history, and revocation.
