# v4.5.0 page and positioning acceptance matrix

[Chinese](../v4.5.0-page-parity.md) | [English](v4.5.0-page-parity.md)

Status: acceptance scope, not yet complete. The reference is an unmodified local image and browser of [SQLBot Community v1.10.2](https://github.com/dataease/SQLBot/releases/tag/v1.10.2). These are entry points and workflows actually observed on 2026-10-26; each still needs operation, response, permission and error comparison. AgentSQL designs and implements its own interface and does not copy the other product's page source, icons or branding.

## Page capability matrix

| Area | Observed workflow in the pinned baseline | v4.5.0 delivery and acceptance |
| --- | --- | --- |
| Data Q&A | Create, search and read conversations; select datasource, suggested questions and multi-turn follow-ups; results, SQL, charts, execution log, analysis and prediction entry points | AgentSQL's own Q&A page completes the same user tasks; compare original requests, stream events, history IDs, chart data and export item by item; reauthorize and durably audit every turn |
| Datasources | Create database or local Excel/CSV source; preview file, select table and save; source list, schema, field search, comments, field status and data preview | Independent source pages cover connection, edit, test, file import, table/field management and delete; compare original-client request shapes; managed files remain isolated and owner-authorized |

| Assistant apps | Basic and advanced apps; name, description, allowed origins, model and datasource settings; advanced apps use third-party data validation | Independent app management and embedded SDK/API cover both app types, authorization, sessions, callbacks, origin validation and revocation; accept unchanged integration parameters in the original application |
| Members and permissions | Search and add workspace members; rule groups, row and column permissions, restricted users | Independent pages cover members, rule groups, row/column rules and change audit; queries, previews, charts, exports, MCP and embedded calls apply current rules consistently and revoke immediately |

## Two product modes

| Mode | AgentSQL responsibility | Evidence required for public claims |
| --- | --- | --- |
| SQLBot security gateway | Keep the existing SQLBot Q&A interface while routing business database access through AgentSQL identity mapping, table/column and row rules, read-only execution, masking and durable audit | Test the original SQLBot and real database in isolation for allow, deny, revocation, masking, fail-closed behavior and audit; state tested versions and databases |
| Standalone Q&A product | AgentSQL itself provides Q&A, datasource, chart, dashboard, assistant, embedded and administration pages, plus compatible API/MCP | With SQLBot stopped, run the same original client and business program at unchanged addresses, paths, identifiers, SDKs and callbacks; no missing page or empty endpoint |

Use one accurate description on the website, GitHub and AgentSQL Web: AgentSQL is an independently implemented database security and Q&A product that can secure SQLBot as a gateway and can also provide Q&A on its own. Claim each mode only after its respective acceptance passes. Zero-change replacement of the user's existing business system additionally needs before/after evidence in their actual isolated environment. Pages, code and assets use AgentSQL's own brand, and current-distribution licensing text presents Apache-2.0 only.

## Per-page completion rule

For each row, record the visible entry point; create/read/update/delete; pagination and search; errors and permissions; persistence; restart/rollback; and differences from original client responses. Static pages, route counts and simulated data do not prove completion. Test real model behavior locally. The public Demo labels model interaction “simulation only; no real model connected.” Before release, confirm the Chinese/English website, current GitHub descriptions and docs, Web, Demo, packages and Release all identify the same actual version.
