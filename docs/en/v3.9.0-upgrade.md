# AgentSQL v3.9.0 Upgrade and Rollback

**Language:** [English](v3.9.0-upgrade.md) | [Simplified Chinese](../v3.9.0-upgrade.md)

## Before upgrade

1. Stop writes to the old gateway and take a paired backup of metadata, the separate audit database if present, `AGENTSQL_SECRET`, and datasource configuration. Check the previous formal package and v3.9.0 package in isolation first. Expected versions are SQLite metadata 27/27, separate PostgreSQL metadata 25/25, and audit 7/7, with no new migration.
2. Mount a readable Oracle CA file inside the gateway container and set its absolute path, `verify-full`, port 2484, and a connection host matching the certificate SAN. Verify the dedicated read-only account's certificate, table grants, and `PLAN_TABLE` first. Set `{"oracle":{"explain":true}}` only when R004/R005 plan budgets are needed. Existing Oracle datasources without TLS/plan settings retain prior behavior but cannot be called verified connections.
3. When rotating a SQL Server strict-TLS certificate, update the trusted CA and recheck host name, database-level SHOWPLAN, reader table grants, and revocation. Do not use `TrustServerCertificate` to pass new-path acceptance.

## Rehearsal and rollback

Run `agentsqlctl migrate --check` on the isolated candidate, then have the migration owner run `agentsqlctl migrate`. Confirm no schema change and check allowed/denied reads, masking, terminal audit, and negative certificate cases before cutover. Stop the new gateway, restore the paired backup and previous formal binary/image, then check version, migration state, and health. Restoring the previous datasource configuration is required on rollback because the old release cannot interpret the new Oracle plan contract.
