# AgentSQL v3.9.0 design: certificates, plans, and controlled queries for Oracle and SQL Server

**Language:** [English](v3.9.0-design.md) | [Simplified Chinese](../v3.9.0-design.md)

Status: design and implementation in progress. This release builds on v3.8.0 and deepens the existing read-only Oracle and SQL Server paths. Findings apply only to the recorded database versions, certificate settings, account privileges, and isolated topologies. This release does not claim complete production support or vendor certification.

## User need

Administrators need verified server certificates for Oracle, bounded privileges for plan checks, and evidence that queries, authorization, masking, audit, and fail-closed behavior hold in specified Oracle and SQL Server deployments. After certificate rotation, an incorrect CA or server name and a revoked account must be rejected. The UI must not bypass this by trusting an unverified certificate.

| Area | Target contract | Compatibility boundary |
| --- | --- | --- |
| Oracle TCPS | Explicit `verify-full`, server CA, and matching server name. Verify the chain and name when connecting and reconnecting. Test before and after certificate rotation, wrong CA/name, and a plaintext endpoint. | Existing Oracle datasources without TLS retain prior behavior but cannot be described as secure connections. Wallets, mutual TLS, RAC, and commercial editions require separate acceptance. |
| Oracle plans | When explicitly enabled by an administrator, a dedicated read-only account may obtain bounded plans only for authorized narrow SELECTs. Missing privileges or invalid plan output fail closed. A DBA must provision and verify the plan table without permanently granting the runtime account table creation, administration, or business-table writes. | When disabled, plan checks remain off; R004/R005 are not claimed. An administrator-account test cannot substitute for runtime-account evidence. |
| SQL Server certificates and plans | For the specified SQL Server 2025 instance, retain verified TLS, bounded SHOWPLAN XML parsing, and database-level SHOWPLAN privilege. Test old/new certificate transition, wrong CA/name, SHOWPLAN revocation, over-limit plans, and timeout. | `TrustServerCertificate` is confined to the existing controlled development compatibility path; new acceptance must use verified certificates. Unauthorized-table R010 remains a gateway static denial. |
| Specified topology | Verify Oracle single-service TCPS and clearly recorded SQL Server single-instance topology. After a target switch, recheck certificate, privileges, data consistency, and audit. | A DNS/proxy switch test is not RAC or Always On high-availability certification. List untested topologies in the release boundary. |

## Security chain and release gates

`MCP identity → current tenant/Agent and datasource → SQL parsing and exact table/column authorization → durable preflight audit → verified-certificate database connection → bounded plan and query → source masking → durable final audit → response`. A certificate, plan privilege, business database, or audit database failure cannot deliver raw rows. Errors and audit records must not contain connection passwords, raw sensitive columns, or certificate private keys.

Use specified versions, synthetic data, and least-privilege accounts to test allow, R010 denial, blocked writes, revocation, certificate rotation, bad certificates, missing plan privilege, excess query cost, timeout/cancellation, and business/audit database outage and recovery. Run real MCP Inspector and Dify calls; rehearse upgrade and restore of SQLite and paired PostgreSQL from the previous official package. Full CI, signed multiarch assets, GHCR, official website, and public Demo each require independent evidence. A failed item cannot be presented as supported.
