# AgentSQL v2.8.0 Design: Milvus Controlled Vector Retrieval

**Language:** [English](v2.8.0-design.md) | [Simplified Chinese](../v2.8.0-design.md)

Status: v2.8.0 Published. Actual boundaries are Milvus 2.6.25 standalone, `default` database, gRPC TLS, and authenticated least privilege accounts; no clustering, other versions, or full production support is claimed. For official results, see [ and release evidence ](v2.8.0-release-evidence.md).

## User tasks and scope

The agent retrieves a vector from the exact authorization collection, taking a small number of scalar fields in order of similarity. The administrator's original Milvus native command preview is a connection-level capability and is not used as the basis for the Agent's MCP permissions.

| path | constraint |
| --- | --- |
| MCP `search_vectors` | Data source ID, single collection, FloatVector field, a finite float32 vector, 1–16 explicit scalar output fields, and `top_k` of 1–20; no expressions, partitions, mixed retrievals, writes, or native commands are accepted. Only allowed if exact `default.collection` table authorization, vector field and all output field column authorization are configured. |
| Database connection | Read the account number, certificate and address from the current data source one by one, establish a TLS connection to verify the CA and host name; reject `root`, empty password, plain text and trust any certificate. The Milvus account should only have `Search` permissions on the target collection. Connection testing also uses this controlled TLS path. |
| Metadata and execution | Check server version, non-dynamic collections, FloatVector dimensions, scalar output types, and single COSINE vector indexes. Gateway max 5 seconds, 20 hits, 1 MiB response; gRPC receive message limit 2 MiB. The server-side structure fixes the Search call, and the input filter expression cannot be passed in. |
| safety chain | Re-verify the Agent/tenant and current policy each time; connect Milvus only after preflight audit persistence. The number of columns and rows returned by the verification is masked by collection/field source; the final state is audited and persisted before delivery. The audit only records objects, stages, row numbers and masked numbers, not vectors and original values. Any audit failures fail to close. |
| Compatible | Existing connection-level Milvus previews are retained. Data sources configured for strict TLS test connections over a separate controlled path, which is not supported in the original preview. The existing behavior of other databases is not affected by the new tool authorization. |

Call chain: `HTTP MCP 身份 → Agent/租户 → 当前数据源 → 精确 collection/字段策略 → 输入校验 → 持久预检审计 → TLS/最小角色/版本/元数据 → 固定有界 Search → 返回结构校验 → 来源字段脱敏 → 持久终态审计 → MCP 响应`.

Negative acceptance includes broad or revoked authorization, unauthorized fields and collections, incorrect CA/hostnames, clear text or administrator accounts, incorrect dimensions, NaN/Inf, dynamic fields, non-COSINE indexes, business database outages, timeouts/cancellations, and preflight and final audit failures. The real Milvus library is verified with the official 2.6.25 stand-alone image, synthetic data and single collection Search role; MCP Inspector and Dify MCPClient accept and allow calls respectively. Release also requires v2.7.0 official package upgrade and paired recovery, CI, dual-architecture signature assets, GHCR, official website and Live Demo public network re-verification.
