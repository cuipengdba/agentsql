## Analyze orders with a region lookup table

1. Authorize the orders table, the region lookup table, and the required fields in one read-only data source. Join on a region code that is unique in the lookup table.
2. Confirm that both sides of the join are visible before saving the relation. Add distinct business descriptions to tables and columns with similar names.
3. Start a new conversation. For example, ask for the three regions with the highest value of completed January orders, using the names from the region lookup table.
4. Review the result and generated SQL. Check that the gateway audit lists the expected query objects.

## Configure business terms and SQL examples

| Configuration | Use case | How to use it |
| --- | --- | --- |
| Business term | The team uses a short name for a set of records | Explain its meaning and the exact values stored in the database. Choose the data sources, enable the term, and verify the result. |
| SQL example | A business metric has a specific calculation and filters | Save a representative question and a read-only, single-table `SELECT` under the target data source. Use the same question to compare the enabled and disabled states. |
| Table and field remarks | Several data sets or lookup tables have similar names | Describe the authorized tables and fields clearly. After editing, ask the same question and review the selected objects in the gateway audit. |

An example gives the model business context. The model generates SQL using the currently authorized schema, and the gateway checks identity, object access, and execution permissions. After a permission change, recheck both new questions and existing history and exports.

These steps apply to the independent AgentSQL question interface. See [product modes](PRODUCT_MODES.md) for the standalone MCP Server gateway and combined deployment, and [SQLBot integration](SQLBOT.md) for the fixed client version.
