# AgentSQL v4.14.0 single-table analysis and table selection

**Languages:** [Chinese](../v4.14.0-query-guide.md) | [English](v4.14.0-query-guide.md)

## Native Q&A

1. Have an operator register a read-only PostgreSQL gateway binding, authorize the required tables for the user, and configure a text model for the Q&A workspace.
2. Sign in to the AgentSQL Q&A page, select an authorized data source, and start a new conversation. Include the business meaning of the table, time period, filters, result fields, and ordering.
3. Check the result against the raw table and generated SQL. Use the gateway audit ID to verify the queried object, decision, and row count.

Single-table examples

| Goal | Example question |
| --- | --- |
| Retrieve matching details | List the order ID, region, and amount for completed East China orders in January 2026. Sort by order ID ascending and return the first three. |
| Aggregate and rank one table | Sum completed actual sales orders in January 2026 by sales region. Show the two regions with the highest totals in descending order. |

## When many tables are authorized

Assign distinct business remarks to similar tables, such as “Actual Sales Orders,” “Next-Year Sales Forecast,” and “Historical Canceled Orders.” State the business scope when asking a question. A unique business-name match puts its authorized table first in the candidate schema. Questions without a unique match follow the existing selection process under current authorization.

Cold and warm states depend on the table-vector index for the current user, data source, and permissions. Opening the data-source list can trigger background prewarming. The gateway rechecks current authorization for later queries after permissions change. Table selection guides SQL generation, and the gateway decides what may execute.

## Independent gateway and combined deployment

Third-party MCP clients can request controlled queries from a separately deployed security gateway. In a combined deployment, AgentSQL Q&A interprets the question and generates SQL, and the gateway handles identity, authorization, execution, and auditing.
