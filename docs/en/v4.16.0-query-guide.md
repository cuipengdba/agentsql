**Languages** [Chinese](../v4.16.0-query-guide.md) · [English](v4.16.0-query-guide.md)

## Native Q&A

Register PostgreSQL in the gateway with a database account limited to reads. Create a personal datasource binding for each member and grant access to the tables and columns needed for that role. Use a row rule for geographic scope and mask fields such as email addresses. Install the AgentSQL Q&A service, configure a local text model, and sign in as a regular member. [Three usage modes](PRODUCT_MODES.md)

On the synthetic orders datasource, ask for the order number, region, and contact email for the orders you can view. Run the question as two members and compare the permitted regions, columns, and masks. The native Q&A UI displays the gateway audit ID. Review the generated SQL and result scope before using an answer for a business decision.

## Standalone MCP Server security gateway

Give each client a separate gateway identity with the read permissions it needs. Discover available tools and authorized metadata over MCP. The gateway enforces policy, executes queries, masks results, and writes a durable audit record. Rotate or revoke bindings and credentials when access changes. [Deployment](DEPLOY.md) · [Operations](OPERATIONS.md)

## Use Q&A and MCP together or connect SQLBot

Run the AgentSQL Q&A agent and the standalone MCP Server gateway for their respective clients. The agent proposes SQL and the gateway decides whether it can run. To keep a verified SQLBot client, connect the supported execution path through the AgentSQL adapter with a personal binding. Reopening history and requesting CSV or Excel downloads reevaluates results under current authorization. [SQLBot setup](SQLBOT.md)

The verified extension-free PostgreSQL `CATALOG_CLOSED_V1` path uses a simple base-table projection. If the UI reports an unsupported query shape, check whether the requested sorting, joins, or other query requirements are covered by the current authorization mode.
