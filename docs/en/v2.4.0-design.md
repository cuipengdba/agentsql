# v2.4.0 openGauss 7.0.0 LTS specified example design

**Language:** [English](v2.4.0-design.md) | [Simplified Chinese](../v2.4.0-design.md)

Status: Under development. The previous official version is v2.3.0; this version only establishes a reviewable controlled read-only link to the designated openGauss Community Edition instance.

## User problems and goals

Currently, openGauss can only use `db_type=postgres` to complete part of the PG protocol smoke; its `server_version_num=90204` lacks the system directory that PostgreSQL B2 closed query pack depends on. Users need independent data source types, clear SQL and permission boundaries, and evidence of identity, authorization, execution, masking, approval, auditing, and failure closure on the real database. Protocol interoperability or RC mirroring results cannot be written as support commitments for LTS or GaussDB commercial versions.

## Product and Safety Contract

| path | v2.4.0 target and rejection boundary |
| --- | --- |
| Data source identity | Added independent `opengauss` type. Each new pool connection must verify that the server is the specified LTS build and the session is read-only; reconnections cannot silently fall to an unknown host or mode. |
| SQL | Only explicit schema, `FROM ONLY` single table, direct column SELECT with WHERE and 1–10000 integer LIMIT are allowed; `ONLY` avoids inheriting child table overrides. Multiple statements, JOINs, functions, aggregates, CTEs, system objects, locked reads, writes, stored procedures, and projections with undetermined sources failed to close. PostgreSQL B2/B5 must not be inherited. |
| Authorization and Approval | Agent/tenant/table policy and single approval are verified one by one according to the existing contract; the original results shall not be delivered after the policy is revoked and the database SELECT rights are revoked. Execution refused due to unknown approval status. |
| Results and audits | Allows the query to return only the results after masking is completed; the unauthorized table returns static R010. Allow, deny, database errors, and audit failures have associated persistent auditing; query results are not delivered when auditing is unavailable. |
| TLS | The `verify-full` claim is only opened after the real database difference between the correct CA and the host name succeeds and the error CA and the wrong host name fail. TLS remains off when not provable and is noted in the support matrix. |
| Operation and maintenance | Verification timeout/cancellation, business database and independent audit library failure and recovery; use openGauss `gs_dump`/`gs_restore` to practice synthetic library backup recovery, and practice AgentSQL SQLite and PostgreSQL metadata/audit sub-library upgrade and complete recovery from the v2.3.0 official package. |

## Release blocking threshold

1. The minimum permissions of the real database are directly connected to HTTP MCP: query, R010, unsafe SQL, masking, persistent auditing, approval, policy and database authorization revocation, and retest after recovery.
2. MCP Inspector and Dify respectively complete the real permission and deny calls; indicate their respective versions, protocol entrances and test environments.
3. TLS positive and negative examples, timeout/cancellation, business database/audit library disconnection and recovery pass; if an item is not completed, the support statement of the sub-capability will not be improved.
4. Compatibility upgrades with the previous official version, backup and recovery, Go/Web/website regression, merged SHA CI, dual-architecture signature package, GHCR anonymous pull, three PDFs of the official website and public network demo are subject to item-by-item acceptance according to the [ each version delivery process ](RELEASE_ROUTINE.md).

## No expansion statement

Specifying a controlled read-only path to an LTS single instance does not equate to full production support or vendor certification. B2 column-level authorization, B5 session, write, active-standby, certificate rotation, long-term load, GaussDB Commercial Edition, and customer production topologies are not inferred by this release. The public network Live Demo continues to use synthetic PostgreSQL/MySQL data and does not display the openGauss real database.
