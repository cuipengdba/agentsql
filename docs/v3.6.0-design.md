# AgentSQL v3.6.0 策略交付、可靠通知与长期审计设计

**语言 / Language:** [简体中文](v3.6.0-design.md) | [English](en/v3.6.0-design.md)

状态：实施设计。发布声明以最终代码、测试和部署证据为准。

## 现状与目标

v3.5.0 已有租户策略包、摘要、差异预览、异人评审和原子应用，但策略 ID、Agent ID、数据源 ID 与关系绑定 ID 都是环境内身份，不能把原始包直接应用到另一环境。通知管理器订阅进程内实时事件，队列满、重启或重载可丢通知；审计本身仍是权威记录。审计 ZIP 有清单哈希，外部签名 checkpoint 需运维手工生成并保管前序摘要。

本版交付三条独立、可验收的链路：受控跨环境策略迁移；持久、可重试的对外事件通知；带外部见证的周期审计归档。三者共用租户隔离、最小数据投影、明确故障状态和审计证据。

## 产品流程

1. 源环境导出不含凭据的策略包与资源清单，标注源租户、源环境、schema、包摘要及签名。管理员下载后由组织自己的交付渠道传输。
2. 目标环境由有权限的管理员上传包，显式选择目标租户并逐项映射 Agent、数据源及目标业务表。目标预检输出未映射、失效、权限扩张及不确定项；含列授权或关系绑定的规则标为不可迁移，不生成可应用提案。
3. 目标环境针对当前策略摘要建立提案；另一位有权限的人复核；操作员在摘要仍匹配时应用。跨环境导入不得跳过现有评审、原子应用和执行时权限检查。
4. 订阅者配置通知通道后，工作节点从已经提交的租户审计流读取最终结果，并用持久化的租户/通道游标和租约竞争领取。按幂等 ID 投递、回执后推进游标；失败按有界退避重试，达到上限进入可查看与人工重放状态。
5. 运维按固定时间窗口生成租户审计归档与外部签名 checkpoint，保存归档、签名、公钥指纹和前序摘要到独立存储；验证器从可信前序状态核对完整链及时间窗口。

## 安全与故障合同

| 领域 | 必须满足 | 拒绝或故障行为 |
| --- | --- | --- |
| 策略移植 | 签名绑定源环境、租户、包摘要、导出时间及格式版本；目标显式重映射，不能从包内接受目标身份或凭据。 | 签名、版本、租户、映射、绑定指纹或目标基线不一致时拒绝。未知项必须人工处理，不自动放宽。 |
| 策略生效 | 复用既有双人评审、当前摘要 CAS 和原子应用；预览仅为元数据判断。 | 审批撤销、权限变化或并发策略更改时失效；实际 SQL 仍走网关权限、脱敏、执行和审计。 |
| 事件投递 | 只从最终持久审计的提交顺序流读取；每个租户/通道有持久游标，每个事件有稳定幂等键；投递为至少一次，接收方按 ID 去重。 | 审计库不可用时查询继续失败关闭；通知端不可用时游标不推进并告警，不把已投递当作审计成功条件。 |
| 投递隐私 | 使用现有安全投影，不默认发送原 SQL、查询结果、凭据或跨租户字段；端点 SSRF 与重定向限制继续生效。 | 端点/密钥配置错误时记录脱敏错误并停在可诊断状态，不回退到不安全地址。 |
| 长期归档 | 归档按租户与时间窗口有界分页，校验连续序号、文件摘要、Ed25519 签名、前序 checkpoint 和最大新鲜度；可信公钥与前序摘要由独立系统保管。 | 缺口、篡改、重复窗口、旧 checkpoint、签名错误或外部存储失败时返回未完成，保留源审计，不标记可删除。 |

首次发布不宣称第三方 WORM 认证、永久保留或恰好一次通知。外部对象存储的不可变保留需由部署者配置和单独验证。

## 实施边界

- 为源包增加版本化、可签名的交付封套和严格尺寸限制；目标导入只产生映射计划和现有策略提案，不直接改写策略。首版只迁移现有原子应用支持的精确表名简单规则；通配表名、列授权、关系绑定、行过滤和旧版不可表达规则必须阻断。保留现有 `agentsql.policy-bundle/v1` 的规范摘要语义。
- 通知以现有 webhook 为首个可靠投递目标；syslog 的传输回执语义不同，必须单独标注，不能借 webhook 的验收扩大声明。
- 复用 v3.5.0 在审计库事务内分配的租户提交序列；共享 PostgreSQL 或 SQLite 元数据库保存每个租户/通道的游标、配置版本、租约和重试状态，支持三网关竞争领取、崩溃重领、退避、上限和人工重放。创建通道时先读取流尾再保存起始游标，允许少量先于配置提交的事件重放，避免丢失后续事件；指标显示积压量与最老待投递时间。跨库不能声称原子提交。
- 归档工具以现有 `audit verify-archive` 和 `checkpoint-create/verify` 为基础，增加时间窗口、链式目录及恢复演练；外部私钥不进入网关配置或数据库。

## 发布验收

1. 两套独立环境与不同资源 ID 上完成导出、签名、映射、预检、异人评审和应用；跨租户、失效绑定、缺映射、篡改、过期、重放与基线漂移均拒绝。
2. 在三个网关上进行通知投递、端点短暂中断、超时、重复响应、节点崩溃、租约到期及重启恢复测试；核对最终审计与待投递唯一键，不承诺网络端恰好一次。
3. 多窗口生成审计归档并由独立验证器验证签名和前序链；删除中间包、篡改一条、替换旧包、切断外部存储和密钥错误必须失败。成套备份恢复后验证可信前序状态。
4. 测试合库及分库迁移、旧版回退、整仓质量门、正式签名资产、双架构 GHCR、官网与公网 Demo；Demo 仅声明实际部署的功能。
