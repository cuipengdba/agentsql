# v3.6.0 审计归档链式验证操作草案

**语言 / Language:** [简体中文](v3.6.0-audit-archive.md) | [English](en/v3.6.0-audit-archive.md)

现有 `audit report --format archive` 生成 ZIP，`audit checkpoint-create` 使用网关外部保管的 Ed25519 私钥签名。v3.6.0 增加多个归档的链式验收；它检查归档内容、签名、链 ID、前序摘要、顺序和外部固定的最终摘要。此验证不能证明导出覆盖了源审计库的每一条记录，也不提供对象存储的不可变保留。

## 创建与保存

1. 对每个明确的租户和时间窗口导出归档，并核对审计链头序号、哈希和导出过滤条件。归档、签名、可信公钥、窗口说明以及前一 checkpoint 摘要应保存在独立于 AgentSQL 网关和数据库的受控存储。
2. 用现有 `agentsqlctl audit checkpoint-create` 签名每个 ZIP。第一个 checkpoint 的 `--previous-sha256` 为空；后续使用前一个 checkpoint 的 SHA-256 摘要。私钥不进入网关容器、元数据或审计数据库。
3. 在归档同一目录建立按时间顺序排列的 `catalog.json`：

   ```json
   {
     "schema_version": "agentsql.audit-chain-catalog/v1",
     "entries": [
       {"archive": "2026-10-01.zip", "checkpoint": "2026-10-01.checkpoint.json"},
       {"archive": "2026-10-02.zip", "checkpoint": "2026-10-02.checkpoint.json"}
     ]
   }
   ```

   条目文件必须是目录内相对路径，不得重复；一次最多验证 1000 项。把最后一个 checkpoint 的摘要通过独立可信渠道固定，不能只从待验证的目录读取该值。

## 验证

```sh
agentsqlctl audit checkpoint-chain-verify \
  --catalog catalog.json \
  --public-key-file checkpoint-public.hex \
  --chain-id trusted-chain-id \
  --expected-head externally-pinned-64-character-sha256 \
  --max-age 87600h
```

从历史链中间开始验证时，还需使用 `--trusted-predecessor` 提供外部固定的前一 checkpoint 摘要。`--max-age` 必须显式选择；历史十年窗口示例不代表默认保留策略或新鲜度保证。当前 checkpoint 结构未签入窗口起止时间，因此运维还须独立核对导出窗口连续性、源审计链头及实际对象存储的保留策略。

遇到缺失中间归档、篡改、签名错误、链 ID 错误、顺序倒退、前序不符或最终摘要不符时，验证返回失败；不要删除源审计记录或将该目录标记为已归档完成。
