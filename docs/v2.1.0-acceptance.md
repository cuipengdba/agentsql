# AgentSQL v2.1.0 崖山指定实例候选验收

**语言 / Language:** [简体中文](v2.1.0-acceptance.md) | [English](en/v2.1.0-acceptance.md)

状态：候选功能验证中。以下是 2026-10-19 本机隔离环境的实际结果，不是正式 GitHub Release、生产客户验收或厂商认证。正式资产、升级、CI、官网和 Live Demo 须在封版后另行记录。

## 环境与范围

- YashanDB Enterprise Edition 23.4.1.109 x86_64，容器镜像 `yashandb:yashandb-image-23.4.1.109-linux-x86_64`，端口 1688，`COMPAT_VECTOR=yashan`。
- `yashandb-go v1.4.4` 加独立 C 客户端 23.4.7.100，Linux amd64、CGO、`-tags yashan`。测试容器为 `golang:1.26-bookworm`。C 客户端再分发目前仅有项目维护者所述厂家口头授权，仓库没有书面文件。
- 每轮随机创建 `SYS.AGSQL_V21_T_*` 授权表、`SYS.AGSQL_V21_D_*` 未授权表及只读账号，填入合成手机号 `13800135678`；SYS 只负责建表、授权和清理，AgentSQL 数据源使用新建只读账号。真库 `INSERT` 由服务器拒绝。失败尝试留下的 2 个账号和 2 张表已定向清理，再次查询该前缀为零。
- AgentSQL 元数据使用临时 SQLite。基础与双客户端测试使用同库持久审计；独立审计测试使用隔离 PostgreSQL 18，迁移后另开连接验证。业务库与审计库故障注入分别进行。

## 已运行验证

| 验收项 | 结果与边界 |
| --- | --- |
| 原生账号与现代 HTTP MCP | `TestYashanHTTPMCPRealE2E` 实际连接只读账号，通过 Go MCP SDK 的 `/mcp/2026-07-28` 完成允许、未授权表 R010、超出窄 SQL 子集、写操作阻断、策略撤销与恢复；允许响应手机号为 `138****5678`，原值未到客户端；含可见性预检拒绝的决策在审计存储重连后可读。最终双客户端重跑退出码 0。 |
| 数据库权限变化 | SYS 撤销只读账号对授权表的 SELECT 后，真实 MCP 查询未交付数据并产生 `error` 审计；恢复权限后再次返回脱敏结果并产生 `allow` 审计。 |
| MCP Inspector 与 Dify | MCP Inspector 0.16.8 CLI、Dify 1.17.1 MCPClient 各自经 `/mcp` 执行一次 allow、一次 R010 deny；最终结果含审计 ID 10–13，手机号只以脱敏形态出现。当前探针适配旧版 `/mcp` 握手；新版入口由 Go SDK 另验。`scripts/v2.1-yashan-clients.ps1` 退出码 0。首次把旧探针指向新版入口时因缺少协议版本头返回 HTTP 400，已改为正确入口重跑。 |
| 独立持久审计 | 使用 PostgreSQL 18 独立审计库重跑真库 HTTP MCP 链路及审计重连，通过，退出码 0。停止独立审计容器时查询未向客户端交付原始行；恢复后新请求脱敏且新增持久审计。`scripts/v2.1-yashan-fault.ps1 -Target audit` 退出码 0。 |
| 业务库断线 | 停止崖山容器后查询未交付原始行，独立审计记录 `error`；恢复后返回脱敏结果并新增 `allow`。首次测试在数据库重启后清理临时账号时沿用了失效管理连接，导致最终退出码 1；改为重新建连清理后完整重跑，`-Target business` 退出码 0。 |
| MCP 可见性预检拒绝 | 发现撤销数据源最后一条 allow 策略时，原入口会拒绝但不写 SQL 交通审计。候选补丁对已认证 Agent 的 `query`/`execute_write` 在该预检处先写持久 `deny` 并返回审计 ID；未解析 SQL 不写入该审计，审计失败时返回错误且不交付数据。单元、真库、独立审计库停机重跑通过。 |
| 前端 | 类型检查通过；Vitest 17 个文件、56 项测试通过；生产构建通过。未改动控制台交互。 |
| Go 全包首轮 | `go test -short -p 1 -timeout 20m ./... -count=1` 仅 `TestParseProjectionLineageP99Budget` 的 PostgreSQL P99 为 6.184 ms，超过 5 ms 门槛；其他包通过。独占条件下单独连续 3 次重跑该性能测试通过，P99 约 1.48–1.52 ms。首轮失败仍计入记录，待最终 CI 完整重跑。 |
| Go 全包封版复测 | 同一 `go test -short -p 1 -timeout 20m ./... -count=1` 在隔离 Go 1.26.8 容器、`GOMAXPROCS=2`、离线依赖缓存中退出码 0；含 `internal/mcpserver`、`internal/parser`、`internal/store` 及其余包。`go vet ./...` 与 `go build -tags yashan ./...` 退出码均为 0。 |
| 官网本地资源 | 三份 v2.1.0 PDF 生成并验证；`website/deploy/verify-static.sh --root` 本地 8/8 项通过。公网发布与公网校验仍待正式资产验收。 |

## 仍需完成与未验证

- GitHub 最终提交 CI、正式资产/双架构动态库与镜像检查；v2.0.0 正式包升级、SQLite 与 PostgreSQL 分库成套恢复、官网和 Live Demo 切换尚未在本文件宣称通过。
- 客户端取消、SQL 超时与服务器侧停止执行尚未在此指定实例形成可复核证据；TLS 证书校验、写入、事务、EXPLAIN、复杂 JOIN、函数、系统目录、主备切换、持续负载及 aarch64 崖山服务端均未验证或维持关闭。
- MCP 数据源可见性预检审计只覆盖已认证 Agent 的 `query` 与 `execute_write` 无权限数据源拒绝；`list_schema` 等非 SQL 工具、缺失必填参数或身份认证失败不属于该交通审计路径。目标表策略撤销且数据源仍可见时，仍由流水线记录 R010。
- 限定结论只适用于上述产品版本、兼容模式、驱动、客户端、x86_64 隔离容器和合成数据。没有书面厂商再分发授权或客户生产验收，不使用“完整生产支持”或“厂商认证”表述。
