# v0.6.0 开发与验收计划

状态：候选验收中（2026-10-14）。本文件描述目标和验收门槛，不代表功能已发布或厂商认证。

当前工作树 `feature/v0.6.0` 已有用户/角色/租户控制台及接入向导、管理 API 越权防护、[普通 SQL 审批单次执行](v0.6.0-approval-contract.md)，并在真实 G100 Build 9 PG 模式实例验证[受限只读适配](vastbase-g100-v060.md)的驱动、流水线和 MCP。v0.6.0 版本号、文档与官网静态候选已就绪；公开发布仍须通过全部验收门槛。

## 目标场景

企业管理员将一个 AI 助手接入已有数据库：创建数据源和 Agent、授予最小查询权限、在 Dify 发起 MCP 查询、确认脱敏及可追溯审计。另用 MCP Inspector 图形界面直接调用同一工具，检查协议、拒绝和审计。管理员能在控制台管理人类用户、角色和租户，审批操作有明确的执行语义。

v0.5.1 已有 PostgreSQL/MySQL 主链路、MCP stdio/HTTP、策略和审计，以及人类用户/角色/租户 API。v0.6.0 不能把注册的数据源数量、PG 协议兼容性或审批记录误称为所有数据库的完整生产支持。

## Bytebase 对比带来的优先级

2026-10-14 查阅 Bytebase 官方资料，属于文档对比；尚未在相同数据和客户端环境中进行动手对比。

| 用户任务 | Bytebase 官方公开能力 | AgentSQL v0.5.1 事实 | v0.6.0 选择 |
| --- | --- | --- | --- |
| AI 助手接入 | MCP + OAuth，以人类账号权限执行和审计 | MCP + 独立 Agent Key，执行身份与人类管理身份分开 | 保持 Agent 最小权限，完成 Dify 与 MCP Inspector 真实客户端验收；Inspector 是开发工具，不代表 AI 助手体验 |
| 数据库变更 | GitOps、SQL Review、审批、审计 | SQL 风险评估和审批决策记录，普通请求的审批通过不触发封存请求执行 | 建立审批内容绑定、有效期、单次执行和终态审计；不在此版建设通用 GitOps 迁移平台 |
| 日常查询 | Web SQL Editor、历史记录、按角色脱敏、限时授权 | 演示台、结果脱敏、审计；没有完整人类 SQL 工作台 | 优先完成接入流程和治理控制台；查询历史与 JIT 授权留作后续候选 |
| 企业组织 | 用户、权限和审计工作流 | 后端 RBAC/租户 API 已有，缺控制台入口 | 交付用户、角色、租户管理页，并验证跨租户拒绝及权限升级防护 |

官方来源：[Bytebase MCP](https://docs.bytebase.com/integrations/mcp)、[产品能力](https://www.bytebase.com/database-devsecops/)、[SQL Editor](https://www.bytebase.com/sql-editor/)。产品页面说明能力，不等于已确认特定套餐可用；商业套餐以当前报价和实际部署为准。

## 交付顺序与通过条件

1. **治理控制台与后端授权**：可在可见租户内创建、编辑用户和角色；初始管理员能管理租户；不能借角色分配或继承获得调用者没有的权限；管理 API 的跨租户访问仍拒绝。前端构建及 API 回归通过。
2. **首次接入向导**：按数据源 → Agent → 最小权限 → MCP 客户端 → 审计引导，显示真实配置状态和失败处理，不声称演示台代替真实客户端。空实例和已配置实例都要走通。
3. **审批执行闭环**：审批对象绑定租户、Agent、数据源配置摘要、规范化 SQL/原文与申请理由，带过期时间和单次消费状态。当前普通 SQL MCP 工具没有参数数组，参数化审批另行设计。执行时重新检查身份、权限、规则和数据库连接；拒绝替换、过期、重复和依赖故障；受控执行及审计落盘的终态可追踪。普通审批与 B5 审批的语义分别验证。
4. **Vastbase G100**：选定明确的产品/版本及 PG 兼容模式，增加独立 `db_type` 和有界只读适配。使用目标实例验证连接、发现、参数绑定、表授权、脱敏、持久审计、写入/DDL/畸形 SQL/超时/断库拒绝。没有目标实例与许可证时仅能标记为“实现中、真库未验收”。
5. **客户端与升级**：Dify 和 MCP Inspector 各完成一次真实工具调用、拒绝和审计关联；从 v0.5.1 升级并回滚，保留元数据与密钥；发布候选构建、安装包、镜像和文档一致。用户于 2026-10-14 同意以无需账号的 Inspector 替代 Claude Desktop 作为本版验收目标；Claude Desktop UI 兼容性仍待账号与真实环境验证。

达梦 DM8、金仓 KingbaseES 的多行/JOIN/异常分支扩展属于本版增强；崖山独立客户端到 HTTP/MCP 的验收视资源而定。没有真库证据时不扩大支持口径。真实客户试点等待用户找到客户后再排期。

## 发布门槛

- 关键安全用例有“请求拒绝且数据库无副作用”的证据，执行与审计记录可关联。
- 真库报告写明产品、版本、模式、驱动、账号权限、拓扑、数据集和未测项；普通 PostgreSQL 不能代替 Vastbase 验收。
- Go 与 Web 测试、前端内嵌产物、安装与升级回滚、两个实际 MCP 客户端均通过。
- README、支持矩阵、变更日志、版本号、网站和发布资产在正式发布时一致。
