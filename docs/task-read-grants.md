# 任务级临时只读授权

管理员持有同时包含 `strategy.manage` 和 `query.execute` 的会话令牌时，可通过
`POST /api/v1/task-read-grants` 创建临时授权。请求提供 `agent_id`、
`datasource_id`、`sql` 和 RFC 3339 格式的 `expires_at`。发起人和租户由
服务器从会话身份确定，不接受请求体指定。有效期最长 24 小时。

创建响应只展示一次 `asql_` 任务密钥。后续 `GET /api/v1/task-read-grants` 与
`GET /api/v1/task-read-grants/{id}` 仅返回授权元数据，不返回密钥或 SQL。
`POST /api/v1/task-read-grants/{id}/revoke` 立即撤销；撤销提交后的新请求被拒绝。
已在执行的查询会在数据库执行前、审计写入前及审计写入后再次验证；若最后一次复查发现授权
已撤销或过期，网关清除结果并追加关联的拒绝审计。最后一次复查与实际响应提交仍有跨实例并发窗口，
因此撤销不能保证阻止所有已经在途的结果返回。

任务密钥只允许 MCP 的普通 `query` 路径。SQL 必须与创建时的原始字节完全相同，
并由网关重新按数据源方言解析。当前保守子集仅接受单条、以 `SELECT` 开头且不含圆括号的简单查询；
函数调用、子查询、`WITH`、`INTO`、注释、行锁定、`EXPLAIN`、多语句和所有写语句均被拒绝。
任务密钥继续受原 Agent 的永久策略、规则、脱敏与审计约束，不扩展其权限。
`SELECT` 类型限制不能证明数据库函数或视图没有副作用；生产数据源仍应使用最小权限、只读数据库账号。

授权表只存任务密钥 SHA-256 和 SQL SHA-256。任务密钥的流量审计记录授权 ID、发起人
ID、Agent 和数据源，包含精确 SQL 不匹配等拒绝事件；不记录密钥或 SQL 原文。创建和撤销操作产生管理审计记录。

管理端的授权状态更新与管理审计写入目前不是一个跨库原子事务。创建审计失败时不返回密钥，
并使用独立的限时上下文补偿撤销；若存储也故障，可能留下无人持有密钥的孤儿记录。
撤销先持久化再写管理审计，因此审计写入失败可能返回 HTTP 500，但密钥已经失效且该次管理事件缺失；
管理员应通过 `GET /api/v1/task-read-grants/{id}` 核实撤销状态，并调查审计故障。
