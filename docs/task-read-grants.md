# 任务级临时只读授权

v0.8.0 将临时授权改为申请、审批和一次性领取；v0.9.0 为新申请增加结果返回预算。申请人需要
`query.execute`；审批人需要 `query.execute` 与 `strategy.manage`，且必须是
同租户的另一位有效用户。旧 `POST /api/v1/task-read-grants` 直接签发入口返回
HTTP 410；v0.7.0 已签发的授权在到期或撤销前仍按原有执行约束校验。

## 管理 API

1. `POST /api/v1/task-read-grant-requests` 提交 `agent_id`、`datasource_id`、
   `sql`、RFC 3339 `expires_at`、客户端生成的 `idempotency_key`，以及可选的
   `max_uses`（1–10，省略时默认 1）。服务器从
   登录身份确定申请人及租户，验证单条简单 SELECT 与最长 24 小时有效期，
   保存 SQL SHA-256 与使用 `AGENTSQL_SECRET` 派生密钥加密的 SQL，不保存明文。
   同一申请人用同一幂等键重试相同内容，
   返回原申请；内容不同返回 HTTP 409。
2. `GET /api/v1/task-read-grant-requests` 和 `GET .../{id}` 返回申请状态。
   申请人只能看到自己的申请；具备审批权限的用户可查看本租户申请。
   列表不返回 SQL；只有与申请人不同的审批人读取详情时，服务端才解密并
   校验 SHA-256，供其核对精确语句。密钥丢失或密文损坏会阻止审批。
3. `POST .../{id}/approve` 或 `/reject` 仅允许另一位审批人处理待审批且
   未过期的申请。申请人不能自批；重复审批返回 HTTP 409。
4. 批准后由原申请人调用 `POST .../{id}/issue`。密钥仅在这次成功响应展示。
   签发状态与授权记录在一个元数据事务中提交；重复调用、过期、撤销审批人
   或 Agent 已失效均不会生成第二个有效授权。
5. `GET /api/v1/task-read-grants`、`GET .../{id}` 仅向管理者返回授权元数据。
   其中 `max_uses` 与 `used_count` 显示结果预算和已用次数；旧版授权的空预算
   表示不限次。
   `POST .../{id}/revoke` 允许原申请人撤销自己的授权，也允许具备管理权限的
   用户撤销同租户授权；后续新请求被拒绝。

申请、审批、拒绝、签发的管理审计与状态变更共用元数据事务。同库部署直接
写入审计表；PostgreSQL 分库部署在事务中持久化管理审计 outbox，再由 relay
投递到 audit 库。元数据审计写入失败时状态变更回滚。分库投递延迟及故障需
由总览中的当前租户 outbox 积压状态和 Prometheus 指标监控；流量执行依然要求持久审计可用，否则关闭执行。
审计只包含申请 ID、授权 ID、SQL 哈希、状态和操作者，不记录 Key 或 SQL 原文。
升级与恢复时应把 metadata 备份与原 `AGENTSQL_SECRET` 成对保管，否则待审批
申请的 SQL 无法解密。SQLite 使用一致性备份接口（例如 `sqlite3 .backup`）；
若有尚未 checkpoint 的 WAL 页面，单独复制 `agentsql.db` 会漏掉授权与审计记录。
控制台的授权 ID 可跳转至审计页，按 `task_grant_id` 精确匹配管理记录与
进入 SQL 流水线的执行记录；协议认证前被拒绝的请求仍不属于流量审计范围。

## 执行边界

任务密钥只允许 MCP 的普通 `query` 路径。SQL 必须与申请时的原始字节完全
相同，并由网关按数据源方言重新解析。当前保守子集仅接受单条、以 `SELECT`
开头且不含圆括号的简单查询；函数调用、子查询、`WITH`、`INTO`、注释、
行锁定、`EXPLAIN`、多语句和所有写语句均被拒绝。

任务密钥继续受原 Agent 的永久策略、规则、脱敏与审计约束，不扩展其权限。
`SELECT` 类型限制不能证明数据库函数或视图没有副作用；生产数据源仍应使用
最小权限、只读数据库账号。

已在执行的查询会在数据库执行前、审计写入前及审计写入后再次验证授权；若
最后一次复查发现授权已撤销或过期，网关清除结果并追加关联的拒绝审计。
最后一次复查与实际响应提交仍有跨实例并发窗口，因此撤销不能保证阻止所有
已经在途的结果返回。

v0.9.0 的有预算授权在持久审计之后、实际返回结果之前，通过同一元数据库的
条件更新原子扣减一次。耗尽的 Key 不再执行新查询；并发中已开始的查询若在
结果交付前争用最后一个次数，只有抢到预算的请求可返回。传输失败与进程异常
不退还已扣次数。拒绝结果、解析失败和审计失败不会消耗预算。v0.8.0 及更早
创建的空预算授权仍按原有效期与撤销规则运行。
