| 项目 | 环境与结果 |
| --- | --- |
| ClickHouse 预算 | 固定镜像摘要 `sha256:05d2e46507afdcf08da46e5528b68847104dbbed691c327e505414b4b7f4e4c8`，服务端 26.8.31.2，原生 TLS、`readonly=1` 角色及五项 `CHANGEABLE_IN_READONLY`。100 行/64 KiB/32 MiB 自定义预算下三行表允许、2000 行合成表的超预算扫描拒绝；HTTP MCP 精确列授权、脱敏、注入值绑定、错误 CA 和撤权测试通过。 |
| Milvus 租户过滤 | `milvusdb/milvus:v2.6.25` 摘要 `sha256:29f7668e64df1c6d5cdadbfbee99f38c72e4001054f149a298725acae57230ad`，TLS/认证单机、仅指定集合 Search 角色，两个租户及默认租户的合成记录。真库确认默认租户只见获准字段等值过滤的记录，其他租户命中不交付；零命中按指定 SDK 结构正确返回空结果；伪造租户字段及未知过滤字段拒绝。HTTP MCP 精确字段授权、脱敏、审计、撤权通过。 |

| 故障关闭 | 独立 PostgreSQL 16 审计库停机时两种 HTTP MCP 读取均不交付；恢复后允许。分别停止 ClickHouse 和 Milvus 业务库时不交付，重启及检索通道恢复后允许。隔离脚本分别输出 `V380_CLICKHOUSE_AUDIT_BUSINESS_FAULT_RECOVERY=PASS` 和 `V380_MILVUS_AUDIT_BUSINESS_FAULT_RECOVERY=PASS`。 |
| 升级与回退 | 从正式 v3.7.0 Linux amd64 包及 SHA256 校验后的合成 SQLite 快照出发，v3.7.0 和 v3.8.0 `agentsqlctl migrate --check` 均为 metadata 27/27；v3.8.0 无迁移写入，升级前后 SQLite SHA256 相同，恢复成套备份后 v3.7.0 再次通过检查，`V380_SQLITE_FORMAL_UPGRADE_RESTORE=PASS`。另用隔离 PostgreSQL 18 metadata/audit 双库，在正式 v3.7.0 包迁移到 25/7 并备份后，由 v3.8.0 候选包复查/迁移，再成套恢复两库并由旧包复查，合成记录均保留，`V380_PAIRED_POSTGRES_UPGRADE_RESTORE=PASS`。 |
