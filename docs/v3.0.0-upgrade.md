# v2.9.0 → v3.0.0 升级与恢复

状态：候选步骤；正式包验收完成后以[验收记录](v3.0.0-acceptance.md)中的 SHA 和环境为准。

1. 用 v2.9.0 正式 `agentsqlctl migrate --check` 确认合并 SQLite metadata 为 23，或分库 PostgreSQL metadata 为 22、独立 audit 为 6。停止所有网关的管理与 MCP 写入，等待 B2 租约失效。
2. 对 metadata、audit（若分库）、`AGENTSQL_SECRET`、审计链密钥和配置制作同一时点的成套备份；记录哈希。不要只备份 metadata，因为审计 outbox 与链头需处于一致恢复点。
3. 以 v3.0.0 正式 `agentsqlctl doctor --config ... --format json` 检查目标配置。预期退出码 0、所有已配置存储 `current=latest`；本版没有 schema 迁移。退出码 2 或 1 均停止切换，先检查配置、历史与备份。`doctor` 只读，不等于恢复演练。
4. 在隔离副本启动 v3.0.0，验证 Agent、数据源、策略、允许与拒绝查询、脱敏和持久审计。核对 `list_datasources` 中新增的 `support` 只对已授权数据源可见；实际授权不因声明变化而放宽。确认后再对正式服务统一换版，双网关不能混合版本承接流量。
5. 回退时停止全部 v3.0.0 网关，将同点备份的 metadata、audit、密钥和配置整体恢复，使用 v2.9.0 正式包执行 `migrate --check`，再验证登录、审计链和真实 MCP 允许/拒绝。不得仅替换二进制而保留升级后产生的业务变更。

本步骤只针对既有受控能力和指定环境；不声称所有数据库适配器具有相同生产支持等级。
