# v3.4.0 金仓与 Vastbase 深化设计

**语言 / Language:** [简体中文](v3.4.0-design.md) | [English](en/v3.4.0-design.md)

状态：设计中。目标为用户已有的 KingbaseES V9R1C10 PG 模式与 Vastbase G100 V3.0 Build 9（commit 30156）PG 模式镜像；启动后的版本、许可、模式及拓扑均须重新取证。其他版本、Oracle 兼容模式和集群拓扑不沿用本版结论。

## 用户问题与现有边界

金仓目前通过 PostgreSQL 协议路径连接，指定单实例的 `verify-full`、最小权限、MCP 脱敏与审计已有证据。Vastbase 使用独立的只读适配器，启动时核对 G100 Build 9、PG 模式与只读状态。两者的类型、计划与查询子集还需要逐项证明；PostgreSQL 的原生 B2 绑定器不能因协议相似就自动授予这两个厂商。现有列策略遇到不能证明列来源的路径必须继续失败关闭。

## 实现范围

1. **查询与类型：**在两个固定实例上建立相同的合成表，覆盖整数、精确数值、文本、日期时间、布尔、二进制及厂商实际支持的 JSON 类型。逐项记录发现、样本、空值、分页、受限 `SELECT` 与未知类型的结果；未知类型、复杂表达式、写入和多语句不得误判为安全读取。
2. **列授权：**仅对可证明单一基础表与所有被使用列的受限 `SELECT` 子集开放。投影、谓词、排序及分页用到的列都必须落在实时列策略中。元数据、授权判定与查询应处于同一只读事务，并锁定目标关系或采取等价的目录竞态防护；视图、函数、派生列、JOIN、子查询、通配符和无法确定来源的语法先拒绝。不得直接复用仅针对 PostgreSQL 验证的原生 B2 扩展或把预检结果当作执行许可。
3. **执行与成本：**对两个固定构建分别识别已实测的 EXPLAIN 节点；未知结构、负数和估算溢出在执行前拒绝。保留行数、超时、连接数、并发与只读账户上界，结果仍经脱敏和持久审计才返回。
4. **运维：**验证 CA/主机名错误、证书和凭据轮换、连接中断、取消、审计库故障与恢复后的允许/拒绝查询。提供清晰的连接配置、支持层级及升级回退步骤。

## 发布门槛

两种真库分别通过真实 HTTP MCP 的允许、越权列、未授权表、写入、多语句、脱敏、持久审计和故障关闭；在连接池上限内完成有界负载，记录成功率与延迟而不宣称 SLA。另需完成客户端实测、上一版升级与恢复、Go/Web/双语文档 CI、双架构签名资产、GHCR 匿名拉取、官网和公网 Demo 烟测。若某一厂商无法证明列来源，则该厂商的列策略继续失败关闭，并在发布说明中明确未交付该项能力。
