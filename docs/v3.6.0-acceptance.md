# AgentSQL v3.6.0 候选验收

**语言 / Language:** [简体中文](v3.6.0-acceptance.md) | [English](en/v3.6.0-acceptance.md)

状态：候选验收中。以下为提交 `309f97a` 的本机合成环境证据；正式签名产物、GHCR、官网和公网 Demo 尚须单独验收。

## 环境与结果

| 项目 | 证据与结果 |
| --- | --- |
| 策略交付与审计链 | Linux Go 1.26.10 定向运行 `cmd/agentsqlctl`、`internal/policybundle`、`internal/compliance` 中的策略交付和 checkpoint 链测试，通过。两个隔离管理环境的合成 API 用例完成源快照签名、目标资源映射、预检、异人审核和应用，源环境未改变。签名篡改、过期、映射约束、归档创建顺序及外部固定头的负向用例由单元/CLI 夹具覆盖；尚未在两套实际部署上复验。 |
| SQLite 游标与迁移 | Windows Go 1.26.0 定向运行通知配置/游标原子提交、租户隔离、租约、重试、死信、迁移及审计流测试，通过。Docker 挂载目录上的整包短测曾在无关的 B5 SQLite 回滚用例中等待 `fsync`，10 分钟默认超时；该次不能计为整包通过。 |
| PostgreSQL 18 | 指定 `postgres:18` 测试容器验证 metadata 合库/分库迁移、SQLite→PostgreSQL 搬迁和通知租约；三个独立 PostgreSQL 连接同时争抢，恰有一个领取成功。 |
| 三网关投递 | 三个独立 AgentSQL 运行时共用 PostgreSQL 18，真实 HTTP Webhook 收到第一条审计事件一次；停止一个运行时后，第二条由剩余节点投递一次，游标推进至 2。测试为合成 deny 审计与本机接收端，不是公网网络或客户生产拓扑。 |
| 重启与管理端 | SQLite 测试中 Webhook 首次返回失败，游标保留、重试状态持久化；运行时重启和端点恢复后投递同一 Delivery ID。管理端验证可靠通道建立、健康积压、同 ID 改端点拒绝、死信重放鉴权与审计。 |
| 控制台与双语 | Node 24 容器 `check:i18n`、TypeScript 类型检查、19 个 Vitest 文件中 60 个测试通过；中英文文档结构与源哈希校验通过。正式站点静态包尚待构建和公网核验。 |
| v3.5.0 升级/恢复 | 从官方 v3.5.0 amd64 二进制启动的 SQLite 25 和分离 PostgreSQL metadata 23/audit 7，使用 v3.6.0 候选分别迁移至 26 与 24/7 并启动。停止后，SQLite 恢复前备份的 SHA-256 为 `AE5EDDC82C57F6D873A7FBDFC66C564AAD4FA9FC499AC7EC282BE6C9CD1D0BF7`，PostgreSQL metadata/audit 分别恢复前备份到新数据库；v3.5.0 二进制均再次启动，版本回到 25 与 23/7。 |

## 发布前剩余门禁

PR #68 的 Go 整仓 CI 必须以最终候选提交通过；按该提交完成正式签名包、双架构镜像与匿名拉取、官网和公网 Demo 部署及烟测，再记录不可变的摘要与链接。跨环境策略包在两套实际部署中的提案/异人审批/应用，以及外部对象存储的保留策略和归档窗口覆盖，不属于上述本机夹具的已验证结论。
