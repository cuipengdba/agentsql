# AgentSQL v3.9.0 设计：Oracle 与 SQL Server 的证书、计划和受控查询

**语言 / Language:** [简体中文](v3.9.0-design.md) | [English](en/v3.9.0-design.md)

状态：候选验收中。以 v3.8.0 为基线，深化已经注册的 Oracle 与 SQL Server 只读路径。验证结论仅适用于明确记录的数据库版本、证书配置、账号权限和隔离拓扑；本版不承诺完整生产支持或厂商认证。

## 用户任务

管理员要用可验证的服务器证书连接 Oracle，限制计划预检所需权限，并在 Oracle 和 SQL Server 的指定部署拓扑中确认查询、授权、脱敏、审计及失败关闭。证书轮换后，错误 CA、错误主机名和已撤销账号必须拒绝；前端不得通过信任未验证证书绕过此要求。

| 领域 | 目标合同 | 兼容边界 |
| --- | --- | --- |
| Oracle TCPS | 明确的 `verify-full`、服务端 CA 与匹配的服务器名称；连接和每次重新建连均验证链与名称。证书更新前后、错误 CA/名称及明文端口均做负向验证。 | 既有未设置 TLS 的 Oracle 数据源保持原行为，但不能标为安全连接。钱包、mTLS、RAC 和商业版另行验收。 |
| Oracle 计划 | 管理员显式启用后，专用只读账号只能对已授权的窄 SELECT 获取有界计划；权限或计划内容不符合合同时失败关闭。计划表须由 DBA 预置并验证，无需赋予持续建表、管理或写业务表权限。 | 未启用时仍不执行计划，R004/R005 不声称有效；不能凭管理员账号测试替代运行账号证据。 |
| SQL Server 证书与计划 | SQL Server 2025 指定实例保持严格证书校验、有限 SHOWPLAN XML 解析和数据库级 SHOWPLAN 权限。验证新旧证书切换、错误 CA/名称、SHOWPLAN 撤权、超额计划及超时。 | `TrustServerCertificate` 仅限既有受控开发兼容路径，新的受控验收不得使用；无权表 R010 在网关静态拒绝。 |
| 指定拓扑 | 对 Oracle 单服务 TCPS 与 SQL Server 明确记录的单实例拓扑分别验证；切换目标后重新验证证书、权限、数据一致性和审计。 | 不把 DNS/代理切换测试写成 RAC 或 Always On 高可用认证；未测拓扑列入发布边界。 |

## 安全链和发布门槛

`MCP 身份 → 当前租户/Agent 和数据源 → SQL 解析及精确表/列授权 → 持久预检审计 → 校验证书的数据库连接 → 有界计划和查询 → 来源脱敏 → 持久终态审计 → 返回`。证书、计划权限、业务库或审计库失效时不交付原始行。错误日志与审计不得包含连接口令、原始敏感列或证书私钥。

使用指定版本、合成数据和最小权限账号，实测允许、R010 拒绝、写入阻断、撤权、证书轮换、错误证书、计划权限缺失、超额查询、超时/取消、数据库与独立审计库断线及恢复。MCP Inspector 与 Dify 真实调用；上一正式版包的 SQLite/成对 PostgreSQL 升级及恢复；全包 CI、签名双架构资产、GHCR、官网和公网 Demo 必须分别留下证据。未通过的单项不得写成已支持。

实现依据：[Oracle TCPS 与服务器证书匹配](https://docs.oracle.com/en/database/oracle/oracle-database/26/netrf/local-naming-parameters-in-tns-ora-file.html)、[go-ora v3 TLS 选项](https://github.com/sijms/go-ora/blob/master/README.md)、[SQL Server 2025 Linux TLS](https://learn.microsoft.com/en-us/sql/linux/security/encrypted-connections?view=sql-server-ver17)、[SQL Server Linux 可用性组边界](https://learn.microsoft.com/en-us/sql/linux/business-continuity/availability-groups/configure?view=sql-server-ver17)。
