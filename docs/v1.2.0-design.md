# AgentSQL v1.2.0 MCP OAuth 受保护资源设计

## 目标

为 MCP 2026-07-28 HTTP 入口提供可选的 OAuth 2.1 受保护资源接入，复用 v1.1.0 的已验证用户、Agent、租户双身份控制链。AgentSQL 作为资源服务器，使用外部 OIDC/OAuth 授权服务器；控制台现有 OIDC 登录不自动等同于 MCP OAuth 访问令牌。旧 `/mcp` 与 `/mcp/2026-07-28` 的 Agent Key 入口保持兼容。

## 协议边界

- OAuth MCP 路径为 `/mcp/oauth`，要求精确配置资源 URI，例如 `https://mcp.example.com/mcp/oauth`；只允许本机回环地址在测试中使用 HTTP。`/.well-known/oauth-protected-resource/mcp/oauth` 发布包含 `resource`、`authorization_servers`、最小 `scopes_supported` 的元数据。401 返回指向它的 Bearer `WWW-Authenticate` 挑战，scope 不足返回 403。
- OAuth Access Token 只从 `Authorization: Bearer` 读取，Agent Key 从 `X-AgentSQL-Agent-Key` 读取。每次请求检查两种凭据、Agent 状态、用户映射、租户一致性和权限，任何一项无法证明均拒绝。拒绝同时提交旧 `X-AgentSQL-User-Authorization`，避免两套人员身份混用。不得把控制台会话 token、其他资源的 token、ID Token 或 URI query token 当成 MCP Access Token。
- 本版只接受由指定外部 issuer 签发的 RS256 JWT Access Token；校验授权服务器元数据与 issuer、JWKS 签名、`iss`、`aud`/resource、`exp`、`nbf`、`iat`、必要 scope。JWKS 缺失或轮换异常时拒绝；已缓存的有效公钥可在 5 分钟缓存期内继续验签，缓存到期后 IdP 不可用则拒绝。MCP OAuth 的 issuer 与租户必须和已启用的控制台 OIDC 身份源一致，防止同名 `sub` 跨身份源串用。用户映射使用本地受管 OIDC subject，逐请求确认活跃状态及 `query.execute` 权限。令牌不扩大 Agent 的 SQL 权限。Opaque token/introspection 与非 RS256 算法不在本版声明范围。
- OAuth 授权客户端负责 PKCE、`resource` 参数和在 IdP 预注册；AgentSQL 不在本版实现授权服务器或动态客户端注册。客户端还需支持配置固定 Agent Key 请求头。正式支持声明只覆盖实测 IdP、客户端和部署组合。
- MCP 会话绑定双身份；审批、B5 与审计继续使用 v1.1.0 的用户+Agent+租户约束。旧客户端不被新路径静默升级或降级。

## 验收

1. 官方 MCP Inspector 真实 OAuth 授权与工具调用：发现元数据、登录后允许查询、R010 拒绝、脱敏和人员审计。Dify 用旧入口验证兼容；按实际能力标注是否支持 OAuth 流。
2. 真 IdP 与本地负向矩阵：错误 issuer、audience、签名、过期、scope、用户/Agent/租户、复用控制台 token、缺少独立 Agent Key、跨用户会话续接均在 SQL 执行前拒绝。
3. 本版无预期 schema 迁移，仍要从 v1.1.0 正式包分别验证 SQLite 与 PostgreSQL 分库升级、恢复和配置禁用回退。Go/Web CI、正式发行物与签名、GHCR 精确 tag 全部通过；按用户要求官网/Demo/`latest` 仍保持 v1.0.0。

依据：[MCP 2026-07-28 授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)、[授权服务器发现](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/authorization-server-discovery)。
