# AgentSQL v4.14.0 · 单表分析与授权选表

**语言 / Language:** [简体中文](v4.14.0-design.md) | [English](en/v4.14.0-design.md)

v4.14.0 处理两个实际问题：单表问数的过滤、聚合、排序和结果顺序可核对，以及 128 张当前授权表中能根据中文业务含义找到正确的数据表。固定的 SQLBot Community v1.10.3 矩阵目标是 Q2 和 Q3，累计 10/25。正式成绩由同一最终签名包的实测决定。 [评分合同](sqlbot-community-chatbi-score-v1103.md)

选表优先保留问题明确点名的表。未写表名时，问题中逐字出现的业务字段备注可帮助排序。只有在当前授权列中归属唯一表的备注才参与此项排序。索引超时且只有一张表具有明确字段备注时，按匹配继续缩小模型读取范围。行列权限、网关执行和审计仍按实时授权核验。

## 验收场景

| 场景 | 必须核对的结果 |
| --- | --- |
| 单表过滤 | 根据地区、状态、日期过滤，核对列、行值与固定顺序。原生页面和未修改的原版页面使用同一只读网关。 |
| 分组、排序和限量 | 按地区合计实际订单金额，核对合计值、顺序、Top N 及可核查的受控查询审计。 |
| 128 表冷态首问 | 使用无现成索引的会话，用不含物理表名的中文提问。夹具包含实际订单、近似的预测和取消订单表、台账干扰表以及不可见表。核对实际查询对象和结果。 |
| 热态首问 | 预热完成后运行同题和改述，重启服务后再测热索引。记录前台选表、网关和端到端耗时，保留失败及超时样本。 |
| 权限与故障 | 规则变化、撤权、模型中断和索引取消分别验证。不能将失去权限的元数据写入索引、发送给模型或释放到结果和历史。 |

复用现有的受授权结构、词项匹配、固定 ONNX 模型和加密索引。本版先对 v4.13.0 在相同真模型和 PostgreSQL 夹具上记录实际基线，确认选表、生成和执行各阶段的失败，再确定需要修复的行为。计时按硬件、并发、索引状态和样本量记录。单次最快值不作为 p95。

AgentSQL 原生问数与独立 MCP 网关仍分别提供部署方式。外部客户端可继续按当前身份和权限访问网关。本版复核 PostgreSQL 只读范围，保留模型、网关与数据库的安全边界。用户真实业务系统尚未验证。

封版交付包括当前固定矩阵、真模型真库证据、中文真实截图、GitHub 文档、签名包、官网和明确标注模拟模型的公网 Demo。 [交付流程](RELEASE_ROUTINE.md)
