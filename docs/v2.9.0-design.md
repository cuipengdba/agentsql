# AgentSQL v2.9.0 设计：策略评审与外部审计见证

状态：开发中；此文档描述本版实现边界，发布证据另行记录。

## 用户任务

管理员要从当前租户导出策略，审查一次变更的影响，由另一位管理员批准，再一次性应用。运维人员要能发现绕过评审的直接策略改动，并把审计导出的完整性证明保存在数据库之外。

## 策略包合同

- `/api/v1/policy-bundles/current` 导出当前租户策略快照和规范 SHA-256 摘要。包中包括策略 ID、Agent 和数据源 ID、对象、动作、修订号，以及已有的 B2 绑定、列权限和暂存元数据；不包含数据库口令、用户凭据和业务行。
- `plan` 对同一租户的当前摘要做乐观并发检查，返回创建、更新、删除差异。对新增 allow、变更后的 allow 及删除 deny 保守标记放权。最多接受 128 条策略与 32 个精确表回放案例。回放只给出表级 `deny`、`candidate` 或 `unknown`；`candidate` 不代表 SQL 能执行。它不会连接业务库。
- `proposals` 保存规范目标包、来源摘要和发起人。发起人不能审批；审批人须同时有策略管理和审计查看权限。应用只接受已批准提案及原审批人，重新检查来源摘要、目标摘要、租户引用和修订，并在同一元数据事务中写入全部策略、批准基线和管理审计 outbox。任一步失败则回滚。
- 本版**只允许修改无 B2 关系绑定、列权限、列暂存、行过滤、旧版异常标记的表级 allow/deny 策略**。已有其他策略会出现在导出包中，但必须保持原样。每份包最多 128 条，每个提案最多 32 项变更；超出范围会拒绝。恢复旧策略也须重新提交和异人审批。原有单条策略管理 API 仍可使用。
- `status` 用当前规范摘要与最近批准的摘要比较，返回 `uninitialized`、`approved` 或 `drifted`。直接 CRUD 造成的漂移会显示在控制台；本版不因漂移自动阻断业务流量。真实执行仍由现有逐次 Agent/租户授权、数据库最小权限、脱敏和持久审计链决定。

调用链：`管理员身份/租户/RBAC → 规范快照及摘要 → 离线差异/保守回放 → 发起提案 → 异人审批 → 应用时重新验证 → 策略/基线/outbox 原子提交 → 网关逐次读取当前策略`。

## 审计外部见证

`agentsqlctl audit checkpoint-create` 首先校验合规 ZIP 的清单和每个文件摘要，再用运维人员外部保存的 Ed25519 私钥签署 ZIP 字节摘要、归档时间、签署时间、声明的审计链 ID/头序号/头摘要及上一见证摘要。`checkpoint-verify` 需独立保存的公钥、预期上一见证摘要和可接受时限；它重新校验 ZIP、签名、字节摘要与时间窗口。密钥和见证历史由运维方放在 AgentSQL 元数据及审计库之外。

签名证明密钥持有人认可这份 ZIP 与所填链头声明；工具**不能从筛选报表反推完整审计链头**，也不提供 WORM、可信时间戳或自动重放防护。链头须先用 `agentsqlctl chain verify` 实际核对，上一见证摘要须从独立可信记录提供。完整审计链的验证与外部留存由部署方负责。

## 兼容与验收

SQLite 合并元数据 schema 22→23；SQLite/PostgreSQL 分库 metadata 21→22；PostgreSQL 合并元数据 22→23；独立 audit schema 6 不变。旧实例使用显式升级流程和成对备份恢复。发布前必须覆盖 SQLite/PostgreSQL 提案与事务回滚、跨租户不可见、过期提案、自审拒绝、直接 CRUD 漂移、签名/ZIP/前序摘要/时限篡改、控制台构建、正式包升级恢复、真实 MCP 允许/拒绝，以及完整签名交付、公网站点和 Demo 验收。

数据库适配器的既有支持级别不因本版提高；真实 SQL 的授权和审计边界以各数据库对应版本的实测证据为准。
