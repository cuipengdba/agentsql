# AgentSQL v3.0.2 验收记录

**语言 / Language:** [简体中文](v3.0.2-acceptance.md) | [English](en/v3.0.2-acceptance.md)

## 环境与已完成测试

- Windows 宿主机 Docker Desktop 隔离项目 `agentsql-v302-test`；PostgreSQL 16、MySQL 8.4 演示库，仅合成数据。
- Web 类型检查、1398 项翻译词条检查、17 个测试文件 56 个用例与生产构建通过。
- Go 1.26.10 下 `internal/mcpserver`、`internal/policy` 测试通过；新用例证明未授权列的字段类型不进入 MCP 输出。
- 真实浏览器在 1600×600 视口下，浅色导航背景 `rgb(255, 255, 255)`、文字 `rgb(23, 32, 51)`；菜单高度 536、内容高度 970、滚动距离 434，最后条目底部 596，可达。
- SQLBot 官方 v1.10.2，提交 `aa41fc1033bb974a703df9200a98ec8b9eec5f25`；镜像索引 `sha256:1a573b42481b4cf95ac225ed9e93fbc6821d56f1ced859f779c0e014df24acb4`。适配安装器核对原始数据库模块 SHA256，六个高层入口接管、七个底层连接入口阻断。
- 在实际 SQLBot Python 运行时调用数据库入口，完成连接、表发现、5 个有类型字段发现、允许查询、手机与邮箱脱敏、显式数字别名转换、越权拒绝、跨工作空间拒绝、无效 Key 拒绝、直连阻断及网关不可用拒绝。持久 SQLite 审计核对 `302=allow`、`303=deny`。
- 适配器单元测试覆盖权限决策、审计 ID、结果结构、数字精度、源码漂移与不重试路径。

- 补充实际故障验证：停用 Agent 后拒绝请求；SQLite 审计插入触发器模拟故障时不交付结果，删除触发器后同一允许查询恢复。首次恢复用例误用了无法通过现有 B2 身份证明的未限定列 SQL，修正为已验证的合成 JOIN 后整组复测通过；不是放宽授权。
- 新 Logo 以 SVG 母版统一官网、GitHub README、Web 登录页和侧栏，副本一致性由 CI 检查。

## 验证边界

SQLBot 验收针对指定官方镜像、PostgreSQL 执行入口和合成数据；没有声称完成外部模型账号下的完整自然语言问数、全部图表和多工作空间生产验收。数据库原有版本、协议和拓扑边界保持不变。

## 发布门槛

完整文档、PDF、CI、签名双架构资产、匿名下载、升级恢复、GHCR、官网与公网 Demo 均已完成本版验收，实际提交、摘要和运行结果见[发布证据](v3.0.2-release-evidence.md)。

补充 Key 撤销实测：为独立合成 Agent 建立 MCP 会话后轮换 Key，原会话的后续工具请求被拒绝；新 Key 重新握手成功。测试后删除该合成 Agent，不影响演示预设身份。适配器单元测试最终为 11 项。
