# AgentSQL v4.15.0 · 业务语义与双表关联

**语言 / Language** [简体中文](v4.15.0-design.md) · [English](en/v4.15.0-design.md)

用户可以用业务术语提问，也可以在已授权的订单表和地区字典之间做关联汇总。复用已有术语、SQL 示例、表列备注和原版关系配置。固定 SQLBot Community v1.10.3 问数矩阵的开发目标为 Q4、S1、S2、S3，全部通过后累计 14/25。最终得分以本版同一正式签名包的逐项复测为准。 [评分合同](sqlbot-community-chatbi-score-v1103.md)

## 当前授权与模型上下文

问数先读取当前受控网关授权字段和行列规则，再依据问题压缩模型需要读取的结构。关系配置先按完整的当前授权结构校验，再让模型读取两端字段均在本轮所选结构中的关系。仅因选表省略的关系不会影响单表问题。当前授权表数未超过选表上限，或首问已明确点名至少两张当前授权表时，直接用已确认的结构生成 SQL。若存量关系的表、连接字段或绑定已撤销，问数在模型和网关查询之前拒绝。配置的关系提供等值关联提示，执行仍由受控网关绑定实际对象、验证授权并记审计。

术语和示例留在当前工作空间及其允许的数据源。术语描述提供业务定义，SQL 示例用于帮助模型生成本轮 SQL。PostgreSQL 单表示例可为聚合结果命名，列校验只检查实际引用的字段。每次请求重新检查配置与当前授权结构。配置更新、数据源绑定变化和权限收紧都要复测新问及相关历史行为。

## 验收场景

| 场景 | 验收条件 |
| --- | --- |
| Q4 双表关联 | 使用隔离 PostgreSQL 的订单与地区字典，通过等值关联按区划聚合。订单侧包含重复地区键，结果按区域和金额与独立 SQL 核对。审计只涉及预期表。选表上下文保留两端后，图中其他当前授权关系不会阻塞本问。 |
| S1 业务术语 | 同一中文问题在术语新增、禁用、删除前后对照。核对 SQL 使用的值和实际结果，检查非授权数据源及工作空间隔离。 |
| S2 SQL 示例 | 用同一问题观察有效示例对真实模型生成结果的影响。示例禁用、不同数据源或引用不再授权的字段后，从模型上下文中排除。 |
| S3 备注与关系 | 分别更新备注和关系，对照实际选表、生成的连接字段和结果。撤销关系涉及的表列后，失败请求不返回数据。 |

正式验收使用本地真实模型、实际 PostgreSQL 及受控网关，复测原生页面和未修改的 SQLBot Community v1.10.3 客户端。准备中文实拍、签名离线包、双架构断网验证、原版升级和故障回滚。官网标注模拟 Demo 和试验范围。 [发布流程](RELEASE_ROUTINE.md)
