# AgentSQL v1.9.0 发布说明

**语言 / Language:** [简体中文](release-notes-v1.9.0.md) | [English](en/release-notes-v1.9.0.md)

v1.9.0 改进管理员首次接入 Dify 与 MCP Inspector 的操作路径。控制台「接入向导」将 Agent、数据源、连接预检、目标 SQL 离线策略解释和真实调用后的审计定位放在同一流程中。此版不改变网关的授权、执行、脱敏或审计合同，也不扩大数据库支持范围。

## 新增与改进

- 生成 Dify 1.17.1 和 MCP Inspector 0.16.8 的 `/mcp` Streamable HTTP 接入说明。管理员须填写客户端可达的网关根地址；页面拒绝含账号、密码、路径、查询串或片段的地址，并提示 Dify 容器内 loopback 地址的含义。
- 对远端明文 HTTP 提示 Agent Key 传输风险；应使用 HTTPS 或限定在隔离内网。
- 接入说明只含 `<Agent API Key>` 占位符，不在控制台收集或回显真实 Key。Dify 说明显式列出 `MCP-Protocol-Version: 2025-06-18`；Inspector 0.16.8 不要求手工重复添加该请求头。
- 沿用上方选择的 Agent 和数据源，调用现有策略离线预检解释一条 SQL。明确拒绝时列出静态规则、对象和策略 ID；其他结果一律显示“尚不能确认允许”，需真实 MCP 调用验证。
- 可输入真实 MCP 响应的审计 ID，直达审计记录。补充认证失败、数据库不可达、超时和只读拒绝的排障引导。

## 兼容与边界

- 数据面、控制面 schema、已有 MCP 入口、身份和权限模型均不变。连接 Ping、策略存在性和离线解释不能代替真实授权或执行验收。
- 客户端说明针对已验证版本；其他 Dify、Inspector 或 MCP 协议版本须另行验证。公网 Live Demo 仅使用合成数据和预置权限。
- 真实客户试点尚未开始，不提供外部用户首次接入完成率。数据库支持继续按各版本已验证的厂商版本、模式和拓扑限定；临时许可、单实例测试不等于完整生产支持。

设计、负向用例与正式交付证据见[设计说明](v1.9.0-onboarding-design.md)及[验收记录](v1.9.0-acceptance.md)。
