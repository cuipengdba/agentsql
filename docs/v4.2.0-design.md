# v4.2.0：多轮问数与业务语义

**语言 / Language:** [简体中文](v4.2.0-design.md) | [English](en/v4.2.0-design.md)

状态：设计与开发中，尚未发布。基线为 AgentSQL v4.1.0 和固定的 SQLBot 社区版 v1.10.2 对照环境。任何“兼容”结论都要由原客户端请求与响应的对照测试支持。

## 目标与范围

| 能力 | 交付行为 | 必须验收的边界 |
| --- | --- | --- |
| 多轮追问 | 同一会话保留有限的已完成问题与 SQL 语境，追问沿用本轮选择的数据源 | 每轮重新获取身份、当前授权元数据和绑定；失败轮次、其他会话及查询结果行不得进入模型上下文；最终 SQL 仍走受控网关 |
| 推荐问题 | 管理员可为数据源配置推荐问题，普通用户只能读取有权使用的数据源推荐项 | 推荐只作为文本呈现，点击后仍以当前用户权限重新执行；无权数据源不返回推荐 |
| 术语与 SQL 样例 | 工作空间和数据源范围内创建、启停、查询业务术语及示例 | 所有权、长度和数量受限；示例不能成为绕过解析、列授权或审计的执行入口 |
| 授权检索 | 只从用户当前可见的表、列及已授权业务词条检索上下文 | 权限撤销立即生效；不把行数据、密钥或跨用户材料送入模型 |
| 文件数据 | 合成 CSV/XLSX 导入隔离的托管数据源并用于受控问数 | 文件大小、类型、行列数和公式风险受限；导入、查询、删除及审计均按所有者隔离 |
| 复杂 SQL 与行列规则 | 增加经数据库适配器明确允许的只读形态与细粒度规则 | JOIN、聚合、别名和通配符逐类校验对象绑定；不确定时拒绝，不降级为宽泛授权 |
| 历史迁移与离线 | 从固定 SQLBot 版本迁移可验证的会话元数据；在本地断网环境运行已配置模型 | 保留来源、失败项和回滚点；不把身份迁移误称为完整历史迁移；模型权重与运行时须明确列入离线包清单 |

## 托管文件数据接入契约

- `parseExcel` 只解析并暂存，不能产生可查询表或扩大授权。暂存原文件为每个工作空间、用户最多一份，限时且加密；客户端的 `filePath` 只是与当前暂存记录比较的令牌。
- `importToDb` 先重新认证管理员，再按原文件重新解析每个选中的工作表。请求中的列名、顺序和类型必须与暂存表头一一对应；整数采用十进制精度的四舍五入并检查 64 位边界。原路径和网关窄接口已有候选实现，网关再次解析原文件，不信任客户端提交的数据行或表名。
- 真正建表只能进入预配置的隔离托管 PostgreSQL 数据源及其专用模式，不得用客户端提供的连接信息或向既有业务数据源发 DDL。ChatBI 不持有直接执行任意业务 SQL 的句柄；后续由网关的窄范围管理操作负责建表、列策略登记和持久审计。
- 已在受控数据库能力域加入独立的 PostgreSQL 暂存建表原语：服务端随机表名、固定 `agentsql_files` 模式、类型化参数、最多 8 个工作表及 16 MiB 转换后数据，所有建表与写入在一个事务中完成。只有模式所有者能调用，且拒绝超级用户、建库/建角色及绕过行级安全的建表账号；建表时不授予 SELECT，并核验默认权限没有把新表授给非所有者，同时检查读取角色的实际 SELECT 权限，拒绝角色继承造成的提前可读。隔离 PostgreSQL 16 真库测试用独立普通建表角色覆盖隐藏、默认权限和角色继承拒绝，以及授权后读取、列策略绑定和带审计发布。
- 控制库在物理建表前以随机操作 ID 和文件摘要记录 `preparing`，再把精确表名映射、`staged` 状态和管理审计同事务提交。候选发布流程先对专用读取角色授予 SELECT、为每张表做数据库绑定的列策略登记，再检查当前 SQLBot 绑定与逐表策略证据，将 `policy_ready` 和 `published` 分别与管理审计同事务提交。查询与结构发现仍检查委托用户、绑定 ID、Agent、数据源及表所有权；未发布表始终不可见。启动时按明确配置的租户与数据源回收 `preparing`、`staged`、`policy_ready`、`deleting` 和 `cleanup_needed`。已发布表删除先经所有者与当前绑定检查，把 `deleting` 和审计同事务提交，令网关立即停止放行，再删除物理表和列策略；失败可重试。
- 新表在数据写入、当前用户列策略登记与审计成功之前不可见。跨控制库和托管库的失败必须保持不可查询，并由可恢复的操作记录清理临时表；授权查询、撤权和删除继续走网关现有身份、列保护、结果封存及审计链。
- 发布验收须用原 SQLBot 客户端的 `parseExcel`、`importToDb`、`datasource/add`、问数和删除请求做响应对照，覆盖跨用户隔离、公式/压缩炸弹、重复列、数值越界、故障关闭及重启恢复。候选接口已把每次导入放入独立子绑定，并实现一次性领取的 Excel 数据源数字 ID；隔离 PostgreSQL 16 后端已验证子绑定隔离、发布、删除故障注入和恢复。原客户端完整调用、复杂工作表选择、导入成功但响应丢失的遗留回收及进程重启后的端到端验收仍是发布阻断项。
- 每个导入子绑定记录创建时父绑定的修订号。父绑定轮换、停用、修改或删除后，子令牌解析、运行时校验、新导入、策略发布和已发布表的网关所有权判断均立即拒绝；管理接口省略隐藏父字段也不能绕过撤销。隔离 PostgreSQL 16 验证了撤销后恢复调用先记审计删除状态，再移除物理表；真实进程重启验收仍待完成。

## 发布标准

### 当前实现与对照记录（未发布）

- 已实现同一会话最多 3 轮已完成问题与 SQL 的上下文，以及数据源推荐问题和最近问题接口；真实本地 Qwen3 4B 对合成销售表完成追问，从 `LIMIT 3` 调整为 `LIMIT 2`。
- 固定 SQLBot 社区版 v1.10.2 的 OpenAPI 含 114 个路径、135 个方法与路径组合。当前注册路由数量仅用于发现缺口，不能作为功能兼容率。
- 对照环境已确认术语与 SQL 样例的分页字段、创建返回数字 ID、删除返回空数据。Go 实现按当前工作空间管理权限提供创建、查询、启停和批量删除；对象与审计同事务，批量删除整体回滚。
- 已新增当前工作空间、当前绑定数据源和问题关键词限定的业务术语检索，最多向本地模型提供 8 条、合计 4 KiB 的文本提示；每轮仍重新获取网关可见元数据。
- SQL 样例只有在匹配本轮问题、解析为单条只读 SELECT、仅引用当前可见的一张表及可见列且函数处于窄白名单时，才作为最多 4 条、合计 6 KiB 的示例文本进入提示词。样例本身不会直接执行，模型产生的新 SQL 仍须经网关授权、执行与审计。
- 本机 Qwen3 4B 的独立生成测试中，术语 `GMV = amount 总和` 得到 `SELECT pg_catalog.sum(amount) AS gmv FROM public.sales LIMIT 20`；这是模型生成验证，不等于网关执行、数据结果或全链路兼容验收。
- 本机 Qwen3 4B 对合成销售表生成了带 `pg_catalog.sum`、`GROUP BY` 与 `LIMIT 3` 的聚合 SQL。已补齐 PostgreSQL `NATIVE_C_V1` 列策略的两阶段登记：发现与加锁复核使用同一列来源校验，复核持有业务关系锁直至控制面提交，登记时不执行 SELECT。隔离 Quickstart 候选网关对 `public.products` 登记 `name,price` 后，限定名聚合实际返回 3 行，审计 317 为允许并记录 4 条列使用；裸 `SUM` 因缺少限定被拒并审计 318，未授权的 `stock` 列被拒并审计 319。测试策略已删除，隔离网关恢复 v4.1.0。此证据仅覆盖该合成 PostgreSQL 查询形态；行级规则、更多聚合和业务系统兼容仍未验收。
- 新增固定 SQLBot v1.10.2 的只读会话元数据导出与原 ID 导入，明确排除旧 SQL、结果行、图表及凭据。导入要求目标用户和个人数据源绑定已存在，并把旧记录标为不可重放；单批最多 1000 个会话、每会话 200 个问题，整批与审计同事务。本地固定 SQLBot 实例实际导出 10 个会话和 10 个问题，读取校验通过；完整历史数据和原客户端对照尚未验收。
- 新增 SQLBot `check/{id}`、`getTables`、`getFields` 读取接口，只通过受控网关检查当前用户绑定的数据源，并返回实时可见的表和列。远端读取后再次核验身份和绑定；撤权、绑定变化或未知表均不返回元数据。表/列备注暂为空，尚未完成原客户端响应对照。
- 新增 SQLBot `previewData/{id}` 路径：忽略客户端提交的列和 SQL，仅对当前网关可见表列组装最多 100 行的只读查询；网关结果必须包含审计 ID，返回前再次核验身份和绑定。当前尚未保留 SQLBot 原始表 ID 映射或完成原客户端预览数据类型对照，不能据路由存在宣称零改动兼容。
- 术语与 SQL 样例增加 Excel 模板、导出和 `.xlsx` 上传导入；仅工作空间管理员可用。导出成功前需落盘管理审计，审计失败不释放文件；导入每条成功记录均与管理审计同事务。单元格作为普通字符串处理，拒绝公式、宏、外部链接，并限制压缩包、工作表、行列及单元格规模。本地固定 SQLBot 导出模板的解析测试已通过。导入按行报告成功、重复和失败；失败行生成可通过 SQLBot 原下载路径获取的错误 Excel，文件按用户加密隔离并审计下载。每个用户仅保留最近一份，7 天后失效；旧 `.xls` 及多种复杂工作簿格式仍未兼容。
- `parseExcel` 已支持有界 CSV/XLSX 预览与按工作空间、用户加密暂存；暂存与包含操作者、行数和文件摘要的管理审计同事务，审计失败回滚。拒绝路径名、重复列名、超限文件和 XLSX 公式。固定 SQLBot v1.10.2 对合成 CSV 的实际响应字段、类型和预览值已对照一致。`importToDb` 原路径通过双凭据网关重解析原文件，并在独立子绑定下完成隐藏表暂存、物理 SELECT 授权、数据库绑定列策略和带审计的发布。ChatBI 加密保存一次性导入凭据；原 `datasource/add`、`get/{id}`、`list`、`delete/{id}/{name}` 路径已按客户端字段实现候选接口，创建时重新检查子绑定的可见列，数据源 ID 在 JavaScript 精确整数范围内，删除先关闭网关可见性再移除本地别名。隔离 PostgreSQL 16 后端验证了基础绑定无法看见子绑定的表、删除故障后失去可见性及恢复清理；HTTP 定向测试覆盖合成 CSV 从入库到创建、读取、删除。参考 SQLBot 容器有现存适配层，创建请求被映射检查拒绝，不能充当未改造原客户端的完整对照；复杂工作表选择、响应丢失回收、进程重启验收和旧 `.xls` 仍未完成。
- 更复杂 SQL 样例的安全检索，以及更多 SQLBot 接口仍待实现；完整兼容与发布验收尚未完成。

- 固定 SQLBot 社区版请求样本、响应结构、错误与权限行为，逐项报告通过、差异或未实现；静态路由数量不能代表兼容率。
- 用原 SQLBot 客户端和 AgentSQL 客户端，在合成 PostgreSQL/MySQL 数据上分别完成单轮、多轮、撤权、拒绝、脱敏及故障关闭对照。
- 验证真实本地模型；公网官网只提供明示的模拟交互，不部署或调用模型。每轮 SQL 的授权、执行和落盘审计都单独成立。
- 离线包须在断网 Linux 环境完成安装、启动、升级、回退及数据保留。若模型权重或运行时未包含，只声明相应基础安装能力。
- 正式提交的 CI、签名资产、双架构镜像、GitHub Release、官网和 Demo 均按版本独立验收。用户现有业务系统零改动替换仍需其真实隔离环境，在 v4.5.0 单独验收。
