# AgentSQL v4.7.0 数据权限扩展合同

> 开发中。正式支持范围以最终精确提交、签名资产和发布验收记录为准。

## 目标与边界

v4.7.0 扩展 AgentSQL 独立问数 Agent 与 MCP Server 安全网关共用的数据权限执行链。重点是活动规则组对多个明确用户的行列限制、规则组和规则项的非空 `white_list_user`、以及带角色限定的明确用户集合。原版 SQLBot Community v1.10.3 客户端作为协议对照；AgentSQL 的授权决定始终由服务端当前身份、工作空间、绑定和受控网关作出。

原版固定镜像的隔离 PostgreSQL 预览黑盒表明，组 `user_list` 包含普通成员时行列限制生效；仅有 `auth_target_id` 但 `user_list` 为空时不生效；将同一成员写入组或项的白名单后限制仍生效；组或项 `enable=false` 的预览行为也与 AgentSQL 草稿语义不同。这些观察仅限原版预览，不推断其它路径。AgentSQL 不把白名单解释为绕过行列规则的许可。

## 受支持的活动形态

- 规则组 `user_list` 是明确的当前工作空间用户集合，最多 100 人；没有显式项目标时，该组的有效行列规则对集合中的每人执行。
- 活动组与项的非空 `white_list_user` 仅允许列出该组的用户。字段加密保存、按原版 API 读回并纳入规则修订摘要；它是展示元数据，不豁免行列限制，也不能扩展受权主体。
- `auth_target_type=role` 只接受 AgentSQL 内建工作空间角色 ID `1`（工作空间管理员，`weight=1`）或 `2`（普通成员，`weight=0`），并要求规则组列出明确用户。保存时逐人校验当前成员身份；查询时按当前身份重新校验。新加入该角色但尚未列入规则组的用户访问数据时故障关闭，直到管理员更新并预检规则；已列用户角色改变时也故障关闭。这个形态是**角色限定的明确用户集合**，不是从原版任意角色 ID 自动扩展用户。
- 单用户 `auth_target_type=user` 继续要求目标 ID 与组内唯一用户一致。多用户组的显式单用户项、未知角色 ID、白名单指向组外用户及无法安全编译的规则保持拒绝。数据库连接由运营方登记的受权网关别名决定。

## 逐入口安全验收

在最终相同提交和最终签名包上，使用当前受权 PostgreSQL 合成表、本地真实模型、同源码 ChatBI/Gateway 和原版客户端，验证预览、原版问数页、MCP SDK、基本/高级助手、Type 4 页面嵌入、历史和 CSV/Excel 导出中的行列限制。至少覆盖两个普通成员、角色变更、白名单改动、新角色成员未列入、规则项/组禁用、模型处理中撤权、网关查询后撤权、存储与审计故障。每项记录 HTTP 状态、返回 SQL/数据、受控网关审计与是否有新查询；失败不得释放旧 SQL 或结果。

AgentSQL 自建的 `enable=false` 组仍是草稿，不执行。**不能将原版权限库直接导入并沿用此标志**；原版禁用组预览仍执行的差异必须在导入设计中显式转换或拒绝。v4.7.0 不声明原版权限数据库的直接迁移。其它数据库、任意原版角色和未列出的客户端路径不因本版扩大支持。
