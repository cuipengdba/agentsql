## 架构与边界

Go 问数服务承担 SQLBot 接口、身份、会话和模型编排。使用独立监听地址，保留原 `/api/v1` 协议，避免与 AgentSQL 管理接口的同名路径和认证空间混用。迁移时由服务端接管原入口，业务方无需改地址。浏览器仍使用 JavaScript/TypeScript。

身份经过认证后，解析明确的工作空间、用户、数据源与 Agent 映射；元数据与查询继续使用现有受控网关。客户端提交的用户、租户或数据源 ID 不构成授权。模型只看已授权元数据，生成的 SQL 仍须经过解析、权限、执行、脱敏和持久审计。权限拒绝不能通过模型重试或改写 SQL 绕过。

协议清单由固定版本的公开源码静态提取，另行记录动态依赖路由、浏览器 SDK、MCP、错误格式、流事件及迁移行为。静态清单不冒充全部运行时接口。SQLBot 的部分社区运行路径依赖 `sqlbot_xpack`；需用原客户端对照验证，不假设其代码已包含在公开仓库。

新增 Go 代码独立实现协议和业务行为，不把上游 GPL/附加条款代码复制到 Apache 许可文件中。若交付必须包含上游资产或派生代码，须逐项记录来源、许可、版权标识与对应源码要求，不能因改写语言就忽略原许可。

## v4.1.0 验收阻断项

- 未认证、停用、过期、撤销、跨用户及跨工作空间访问均拒绝；旧身份和大整数 ID 不丢失精度。
- 登录加密、令牌、响应封装和流事件与固定基线逐项对照；无法验证的路径保留为待完成。
- 使用真实本地模型与 PG/MySQL 合成数据，验证授权元数据、SQL 结果、脱敏及落盘审计。不得用固定 SQL 或模型模拟响应替代真实验收。
- 模型超时、取消、网关拒绝、审计失败及存储失败有明确终态，不泄露上游密钥或未脱敏数据。
- 迁移预检不修改源库；导入在隔离目标验证；保留原服务与备份，发布不能自动迁移用户生产数据库。
- 离线包须区分仅解包校验与实际断网安装启动；缺少运行时、模型或数据库驱动时不能宣称完整离线问数。

## 最终替换证据

v4.5.0 需固定用户实际部署版本与接入清单，保留域名、端口、路径、凭证、应用密钥、SDK、回调及历史标识。对同一业务程序执行切换前后测试，并记录业务代码和配置校验值。当前尚未获得用户业务测试环境；通用兼容测试可先推进，不能据此宣称用户现有系统已完成零改动替换。

## v4.5.0 补充范围与对外口径

- 独立实现 SQLBot 社区版固定基线的全部页面能力和接入流程，逐页核对问数、数据源、图表、仪表板、助手、设置与管理功能、请求和权限行为。页面使用 AgentSQL 自己的设计、代码、图标和品牌，不复制上游前端源码或资产。
- 同一产品支持两种经测试的部署形态：作为现有 SQLBot 的受控数据库安全网关，以及在停用 SQLBot 后由 AgentSQL 独立提供问数和全部兼容入口。官网、GitHub 和 AgentSQL Web 清晰说明两种形态与各自的验收范围；零改动替换仅在原版客户端和实际业务集成通过后宣称。
- v4.5.0 发布时把官网、GitHub 首页、现行文档和 Web 的版本说明统一到实际发布版本，检查中英文页面和在线 Demo。在线模型交互标明为模拟演示，不调用真实模型。
- 当前发行版的官网和 GitHub 授权说明只呈现 Apache-2.0，清理其他许可营销文字、链接及现行说明文件。保留真实历史版本的原许可记录、第三方版权与许可义务，不把上游受限代码或素材混入 Apache-2.0 交付物。
