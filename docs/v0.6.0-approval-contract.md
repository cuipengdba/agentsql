# v0.6.0 普通 SQL 审批执行合同

**语言 / Language:** [简体中文](v0.6.0-approval-contract.md) | [English](en/v0.6.0-approval-contract.md)

状态：已实现单次执行路径，正在完成升级和发布验收；不属于 B5 事务审批。

## 申请与封存

`request_approval` 只保存申请，不执行 SQL。记录绑定租户、Agent、数据源 ID 与连接配置摘要、SQL 原文与规范化 SQL、申请说明和触发原因，并设置 24 小时有效期。HMAC 封存关键字段。审批人、审批备注和决策时间另存，不覆盖申请内容。旧记录没有封存字段，可查看但不可执行。

当前普通 MCP SQL 工具没有参数数组输入，因此该路径只能封存字面 SQL；参数化审批待单独设计，不接受在执行时附加参数。

## 单次执行

管理员批准后，原 Agent 调用 `execute_approved`，只传 `approval_id`。存储层以租户、Agent、状态和有效期原子认领，将 `approved` 改为 `claimed`。并发调用仅一个能成功；进程重启后的 `claimed`、失败或结果未知记录均不可自动重试。

认领后先核验封存、当前 Agent 身份和审计可用性，再以原 SQL 重新通过数据源配置、解析、策略、风险规则、数据库执行和脱敏。当前策略拒绝仍拒绝；人工批准只消除本次“需要审批”的等待，不提升 Agent 权限。B2 列级授权 SELECT 路径暂不接受普通审批执行，以免绕过其独立执行合同。

成功落 `completed`；明确拒绝落 `failed`；数据库或审计结果无法确定时落 `unknown`，要求人工核对。认领审计、执行审计与审批记录关联，执行审计 ID 在管理 API 和 MCP 查询结果中可见。若终态持久化失败，记录停留在 `claimed`，禁止重放。

## 已验证与待验证

SQLite 持久层已覆盖认领、重放、重启、过期、Agent 不匹配及旧单拒绝。G100 Build 9 PG 模式 MCP 真库测试已覆盖申请、批准、单次执行、脱敏、数据源变更拒绝和撤销策略拒绝。PostgreSQL 18 与 MySQL 8.4 的受限账号、合成表 MCP 真库测试均确认申请阶段不写入、批准后写入一次、执行审计可关联、重复调用被拒绝。Web 类型检查、54 项测试和构建已通过；全量 Go 快速回归仍需在隔离负载下复跑。元数据与审计分库故障、真实客户端界面和部署升级回滚仍为发布门槛；不能把这些用例的缺口视为生产验收通过。
