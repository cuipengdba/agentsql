# AgentSQL v4.0.0 升级与回退

**语言 / Language:** [简体中文](v4.0.0-upgrade.md) | [English](en/v4.0.0-upgrade.md)

本版不新增 schema；目标为 SQLite 27、PostgreSQL 分库 metadata 25/audit 7。旧版可能需要中间迁移，不应仅替换二进制后依赖运行时自动修复。

| 来源正式版 | SQLite | 分库 PostgreSQL | 发布前结果 |
| --- | --- | --- | --- |
| v3.0.2 | 从其正式包初始化，备份后逐步迁移至 27 | 从正式包初始化两库，迁移至 25/7 | 待矩阵演练。 |
| v3.5.0 | 同上 | 同上 | 待矩阵演练。 |
| v3.9.0 | 27 保持不变 | 25/7 保持不变 | 待矩阵演练。 |

## 升级步骤

1. 核对数据库产品/版本/拓扑和当前能力证据；先在隔离环境使用当前配置的脱敏副本演练。升级不会自动增加数据库支持能力。
2. 停止所有网关实例写入，处理未完成的审批与 B5 事务；保存配置、原始 SECRET、metadata、audit、B5 WAL/恢复数据、证书和实例 ID。SQLite 使用一致性备份；PostgreSQL 分库要求在同一停写窗口成套备份。
3. 通过独立受信公钥验证完整发行目录，保留原版二进制和备份哈希。执行 `agentsqlctl doctor` 与 `migrate --check`，明确 pending、blocked 与 ahead 的区别。
4. 使用迁移账号执行 `agentsqlctl migrate --config <config>`，再次检查，再使用最小运行账号启动。不要在生产环境长期保留迁移权限。
5. 复核身份、权限、脱敏规则、配置加密字段、审计记录和新请求允许/拒绝行为；确认就绪、通知与外部客户端。没有通过前不恢复所有流量。

## 回退规则

先停写，将 SECRET、配置、metadata 与 audit 及适用的事务恢复数据成套恢复到升级前，再启动对应旧版程序。恢复会丢弃备份之后的数据，因此回退窗口和数据损失必须由部署负责人预先确定。不要仅回退程序、不恢复较新的 schema；不要混用不同时间点的元数据、审计或密钥。

```powershell
pwsh ./scripts/v4.0-upgrade-matrix.ps1 -FromVersion v3.0.2 -PackageDirectory '<official-package-directory>' -CandidateDirectory '<v4-binary-directory>' -FixtureRoot '<new-isolated-fixture-root>'
```

演练脚本只建立固定前缀的隔离容器与新目录，使用合成记录，不接收客户生产 DSN；输入包先核对已下载的 SHA-256 sidecar。正式来源认证另由发布验签流程完成。脚本检查旧版启动、迁移、新版启动、记录保留、备份恢复、旧版回退启动及 SECRET 文件一致性；原始结果见[验收](v4.0.0-acceptance.md)。
