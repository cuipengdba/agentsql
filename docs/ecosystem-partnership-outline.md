# 国产数据库联合案例大纲

> 文档状态：对外合作讨论框架，不是兼容性认证或支持声明。AgentSQL 当前原生支持 PostgreSQL 与 MySQL；首批联合厂商规划为电科金仓与瀚高，均须在厂商提供的目标版本环境完成端到端验证并经双方确认后，才能形成联合发布结论。

## 1. 联合案例价值主张

AgentSQL 作为数据库中立的安全网关，位于 Text2SQL 应用、AI Agent 与国产数据库之间，为模型访问数据库补上统一的安全闸门：API Key 鉴权、SQL AST 规则评估、对象与列授权、结果脱敏和全链路审计。数据库厂商无需把上层 AI 应用绑定到单一实现，即可与 AgentSQL 共同展示“AI 访问数据库也要经过可控、可解释、可追溯的安全边界”，并将经过双方验证的案例作为 AI 安全最佳实践对外发布。

对外口径必须以实测证据为准：协议可连接不等于 SQL 方言、系统目录、驱动、类型、`EXPLAIN`、取消语义和故障关闭均已兼容。未完成目标版本验证时，只使用“联合评估中”或“适配验证中”，不使用“已支持”“原生兼容”或“联合认证”。

## 2. 最小可验证场景

### 2.1 统一架构

```text
Text2SQL 应用 / AI Agent / MCP 客户端
                  ↓
AgentSQL 安全网关（鉴权 · AST 规则 · 授权 · 脱敏 · 审计）
                  ↓
厂商数据库 Docker / 授权测试实例（仅合成演示数据）
```

每家厂商复用同一套骨架，只替换数据库目标版本、合法镜像或测试实例、官方推荐驱动与必要的方言配置。验证必须覆盖正常路径与 fail-closed 路径；只有“驱动连接成功”不能作为联合案例验收。

### 2.2 演示剧本（5 步）

| 步骤 | 演示动作 | 预期画面 / 验收点 |
| --- | --- | --- |
| 1. 连接数据源 | 在隔离环境部署 AgentSQL 与厂商数据库测试实例，记录双方版本；使用最小权限测试账号新增数据源并测试连接 | AgentSQL 控制台显示数据源连接成功，数据源类型、目标版本和部署形态有留档；页面与日志不展示口令 |
| 2. 发现与规则 | 对 `customers` 等明确选定的演示表运行敏感发现，人工确认手机号/邮箱候选，生成并启用脱敏规则；为演示 Agent 只授权所需表列 | 发现页显示候选类别与置信度但不返回原始样本；脱敏规则和 Agent 授权边界在控制台可见，未授权对象保持默认拒绝 |
| 3. 危险 SQL 拦截 | 通过 AgentSQL 对 `customers` 提交一条无 `WHERE` 的 `UPDATE` 验证用例，并填写 `reason`；具体标识符按目标数据库方言调整 | 返回 `deny`，画面显示规则命中与原因；复查测试表确认数据未变更，审计中可追溯该次决策 |
| 4. 脱敏查询 | 通过受控查询读取 `customers` 的 `phone`、`email` 等已授权列 | 查询为 `allow` 或带可解释告警；结果中的手机号、邮箱按已启用规则脱敏，页面显示脱敏单元格信息，不展示原值 |
| 5. 审计导出 | 在审计页按本次 Agent、数据源和时间范围筛选，查看允许/拒绝记录并导出 | 详情可见 SQL、命中对象、规则、决策和耗时；成功导出 CSV 或 JSONL，导出行为产生 `audit.export` 管理留痕 |

步骤 2 的发现能力、步骤 3 的方言解析和步骤 4 的列来源/脱敏都必须在目标数据库真实版本上验证。任何一步若只能安全拒绝，应如实记录为已知边界，不以关闭规则或放宽 fail-closed 方式换取“跑通”。

### 2.3 最小验收证据

- AgentSQL 版本、数据库产品全称、版本、兼容模式、部署形态及驱动版本清单。
- 可复现的非敏感配置模板与演示数据生成方式；所有密钥、口令和内部地址均已清除。
- 五步剧本的截图或录屏，以及允许、拒绝、脱敏与审计导出的结果证据。
- 方言、类型、系统目录、`EXPLAIN`、超时取消和已知限制记录；解析不确定时必须证明安全拒绝。
- 双方技术负责人确认的结论与对外措辞，明确适用版本和不适用范围。

## 3. 演示数据口径

统一使用公开、可重复生成的合成示例数据，不接触任何真实客户或生产数据。表结构沿用 AgentSQL demo 的业务口径：

| 演示表 | 用途 | 数据要求 |
| --- | --- | --- |
| `customers` | 展示客户查询、列授权与脱敏 | 使用合成的客户标识、姓名、手机号、邮箱、地区和时间字段；手机号、邮箱仅用于验证规则，不得来自真实联系人 |
| `orders` | 展示客户与订单的普通关联查询 | 使用合成订单标识、客户标识、商品标识、数量、金额、状态和时间字段，不包含真实交易 |

各数据库可按方言调整 schema、标识符、数据类型和建表语句，但业务含义、用例数量级和预期安全决策保持一致。对外材料需注明“全部为合成演示数据”；数据库镜像、驱动和示例数据脚本的分发还须遵守厂商许可证。

## 4. 双方分工

| 工作项 | AgentSQL 方 | 数据库厂商方 | 共同确认 |
| --- | --- | --- | --- |
| 环境与部署 | 提供 AgentSQL 网关、部署说明、非敏感配置模板与问题定位 | 提供合法测试环境/镜像、目标版本、最小权限账号、网络条件和官方推荐驱动 | 环境拓扑、版本冻结、测试窗口和数据销毁方式 |
| 兼容性验证 | 负责接入、规则、授权、脱敏、审计与 fail-closed 验证，记录差异 | 协助确认连接参数、方言、系统目录、类型、`EXPLAIN`、错误码和驱动行为 | 通过项、限制项、未通过项及是否需要适配开发 |
| 演示与证据 | 提供统一五步剧本、演示数据口径、截图/录屏清单和审计证据 | 复核数据库侧行为，确认测试表未被危险 SQL 修改 | 可复现性、结论边界和可公开证据 |
| 联合文案 | 起草案例页、技术文和演示讲稿，保证 AgentSQL 能力表述准确 | 提供厂商品牌规范、产品介绍、数据库侧技术审校与发布渠道 | 标题、Logo 使用、版本口径、发布时间和联系人 |

## 5. 联合发布物清单

- **官网联合案例页**：问题背景、联合架构、五步演示、实测版本、关键截图、已知边界和获取方式。
- **公众号技术文**：建议标题一《让 AI Agent 安全访问国产数据库：AgentSQL ×〈厂商/产品〉联合实践》；建议标题二《从 Text2SQL 到可审计执行：〈产品〉AI 数据访问安全五步验证》。标题中的“联合实践”仅在双方完成验收并书面确认后使用。
- **技术附件**：经过脱敏的部署拓扑、版本矩阵、演示数据说明、验证清单和已知限制；不公开 API Key、`AGENTSQL_SECRET`、数据源口令或内部地址。
- **群内联合直播 / 录屏（可选）**：15–30 分钟完成背景、架构、五步实演和答疑；提前准备断网录屏与脱敏后的审计导出作为备份。

## 6. 落地步骤

首批联合厂商规划为 **电科金仓 + 瀚高（含 IvorySQL 社区版 / HighGo 商业版）**，共两家。两家可并行推进；若测试环境、技术联系人或验证窗口需要错峰，则先电科金仓、后瀚高。该顺序是落地规划，不代表已签署合作协议、已完成适配或已获得兼容认证。

瀚高 HighGo 与 IvorySQL 是同一厂商、同一产品线的商业版与社区版：联合合作和技术联系人按瀚高一家厂商统一对接，演示与验证可分别覆盖 IvorySQL 社区版和 HighGo 商业版两条线。两条线仍须分别记录目标版本、兼容模式、驱动和验证边界，不以其中一条线的结果自动替代另一条线。

| 阶段 | 关键动作 | 出口条件 |
| --- | --- | --- |
| 1. 评估 | 选定 1–2 家及具体产品版本；确认联系人、驱动、许可证、测试环境、兼容模式和联合意愿 | 双方形成一页范围说明，未确认项进入待办，不承诺发布日期 |
| 2. 试跑 | 导入统一合成数据，按五步剧本跑通并记录连接、解析、规则、脱敏、审计及安全失败路径 | 证据齐全；问题按“阻断发布 / 已知限制 / 后续增强”分类，危险漏拦为发布阻断项 |
| 3. 定稿 | 固化版本矩阵、复现步骤、截图/录屏、已知限制与联合文案 | 双方技术与市场负责人书面确认，敏感信息清理完成 |
| 4. 发布 | 同步上线案例页和技术文，按需安排直播/录屏；保留问题反馈入口 | 发布内容与验收版本一致，不把单一版本结论外推到其他产品线或兼容模式 |

首家案例完成后，把差异点沉淀为可复用检查表，再启动第二家。任何产品升级、驱动切换或兼容模式变化，都需要重新执行至少五步回归后再更新对外口径。
