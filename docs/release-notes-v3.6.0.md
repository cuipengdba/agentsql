# AgentSQL v3.6.0 发布说明

**语言 / Language:** [简体中文](release-notes-v3.6.0.md) | [English](en/release-notes-v3.6.0.md)

状态：已发布。正式交付结果见[发布证据](v3.6.0-release-evidence.md)和 [GitHub Release](https://github.com/cuipengdba/agentsql/releases/tag/v3.6.0)。

## 本版改进

| 范围 | 变化 |
| --- | --- |
| 跨环境策略交付 | `agentsqlctl policy-transfer` 对源租户的简单表级规则创建 Ed25519 签名封套，在目标环境用受信公钥、显式资源映射和目标策略快照生成提案输入。提案仍走现有预检、异人审核、摘要比较和原子应用。列授权、关系绑定、行过滤、通配对象及旧版不可表达规则拒绝迁移。 |
| 可靠 Webhook | 新增按租户/通道持久游标、稳定 Delivery ID、租约领取、有界退避和死信。通知从已经提交的审计流读取最终结果；接收端应按 Delivery ID 去重。管理端显示积压和最老待投递时间，死信重放需要权限并先写管理审计。Syslog 与普通 Webhook 维持原有尽力发送语义。 |
| 长期审计核验 | `agentsqlctl audit checkpoint-chain-verify` 按外部固定的前序摘要、链 ID、公钥与最终摘要验证多份归档及 Ed25519 checkpoint 的连续性、顺序和新鲜度。签名密钥及可信终点由部署者在网关外保管。 |

## 升级与边界

metadata 新增可靠通道标志和通知游标表。合库迁移至第 26 版；分离 metadata 迁移至第 24 版，audit 保持第 7 版。升级前应成套备份 metadata 与 audit，并按[发布验收流程](RELEASE_ROUTINE.md)完成停止旧实例、迁移、核验和恢复演练。旧版本不能直接读取新 schema，回退应恢复成套备份。

可靠 Webhook 是**至少一次**投递；远端成功后本地确认前崩溃会重发。通道端点、凭据或筛选条件变更时应创建新的通道 ID，待旧通道积压清空后停用。启用前已有审计不自动补发；首次游标从配置发布前读取的已提交流尾开始，跨库间隙允许少量重放。审计库故障仍按现有执行路径失败关闭；通知目标故障不会把已提交审计标成失败。

链式 checkpoint 验证不能证明导出覆盖源库每条记录，也不提供 WORM 或第三方合规认证。外部存储不可变策略、窗口覆盖和备份恢复须由部署者另行验证。数据库支持等级不因本版通知及归档能力而自动提高。
