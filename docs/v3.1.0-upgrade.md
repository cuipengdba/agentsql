# AgentSQL v3.1.0 升级与恢复

**语言 / Language:** [简体中文](v3.1.0-upgrade.md) | [English](en/v3.1.0-upgrade.md)

## 版本与迁移

| 布局 | v3.0.2 | v3.1.0 |
| --- | --- | --- |
| SQLite / PostgreSQL 组合流 | 23 | 24 |
| 分库 metadata | 22 | 23 |
| 分库 audit | 6 | 6 |

新增表 `sqlbot_bindings` 保存租户、外部工作空间/用户、内部用户与只读 Agent、数据源、凭据摘要和映射版本。已有 API Key、人员委托、数据库策略和审批数据继续使用原有合同。

## 操作顺序

1. 停止写入并成套备份元数据、审计、配置和密钥；保留 v3.0.2 程序。SQLite 使用 backup API，或在完全停止后复制完整数据库状态。
2. 在隔离副本用 v3.1.0 执行 `agentsqlctl migrate --check --config /path/config.yaml`，确认待迁移范围。
3. 使用迁移负责人账号执行 `agentsqlctl migrate --config /path/config.yaml`，再次运行检查及 `doctor`。正式运行账号不增加 DDL 权限。
4. 启动并验证旧 Agent 的允许、拒绝、脱敏、审批和审计，再配置 SQLBot managed v2 映射。
5. SQLBot 使用全新 v1.10.2 基础镜像安装适配器；先验证安装清单和诊断，再验证当前用户、实际查询及只读审批。
6. 回退时停止新版，恢复升级前配套数据、配置、密钥及旧程序，重新检查健康和业务链路。不能让旧程序直接打开新增 schema。

## 旧配置与故障

SQLBot v1 配置保持原有工作空间级映射边界。迁移到 v2 时，每个人员都需独立映射和连接凭据；明文凭据只在创建/轮换时展示一次，不从列表或导出重新取回。禁用映射用于停止该接入，撤销 Agent Key 用于停止该 Agent 的全部访问。

映射变更后旧令牌及对应旧会话失效，客户端重新解析并初始化；查询不自动重试。恢复审计故障后，先以合成数据确认持久审计恢复，再恢复业务调用。实际演练结果见[验收记录](v3.1.0-acceptance.md)。
