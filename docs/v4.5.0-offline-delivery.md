# v4.5.0 可安装离线包设计与验证

[中文](v4.5.0-offline-delivery.md) | [English](en/v4.5.0-offline-delivery.md)

状态：候选方案，尚未构建或发布 v4.5.0 正式离线包。

`scripts/assemble-offline-release.py --installable` 从已签名且验签通过的 15 项正式资产组装一个传输包。包内有 `assets/`、版本文件、`install-offline.py` 和只读数据库预检 `check-postgres-binder.sh`。组装器不下载软件，也不安装到当前机器。离线安装器把资产复制到私有暂存目录，先核对固定的资产清单、发行公钥、三份 Ed25519 签名、文件哈希，再从已认证的本机架构包中提取 `agentsqlctl` 执行完整的发行验证。全部通过后，才调用已验证的 `install.sh --from` 安装网关及问数服务；安装过程中不访问网络。

正式发行时，从同一源码提交取得 15 项资产及独立保存的可信公钥，组装并公布离线包及其 SHA-256。用户下载、解压后，可执行一条命令：

```bash
sudo python3 agentsql-v4.5.0-offline/install-offline.py install
```

该默认命令核对脚本中固定的 AgentSQL 发行公钥文件 SHA-256（`83d507dd59659aff490725184b2e65a5c1036181fc79c350028905df723a1542`）。要从离线包外独立确认发布者身份，先从另一可信渠道取得公钥，再执行：

```bash
sudo python3 agentsql-v4.5.0-offline/install-offline.py install --trusted-public-key ./trusted-release-key.json
```

也可将 `install` 换成 `upgrade`，或加 `--verify-only` 做不安装的验签。要求目标机为受支持的 Linux amd64/arm64、glibc 环境，预装 Python 3 和 OpenSSL 3，并为私有暂存及备份准备足够空间。安装器只处理签名资产和本地包；网关数据库连接、真实模型和业务系统切换仍须分别配置、验收。`--no-start` 仅用于隔离预安装，不证明 systemd 启动成功。

本地已用正式 v4.3.0 的 15 项资产在 `--network none` 容器中演练同一组装与安装逻辑：独立公钥验签通过，默认固定公钥验签通过，篡改 `provenance.json` 被阻断，`--no-start` 安装后网关二进制、问数二进制及问数库均存在。这证明脚本对既有正式包有效；v4.5.0 的最终签名资产、双架构真实安装、升级/回滚、服务启动和下载入口尚待本版本发布验收。

PostgreSQL 问数还依赖部署在数据库服务器上的原生 `agentsql_binder` 扩展及读取角色的 `agentsql_catalog` 使用、函数执行权限。当前 15 项正式资产的一键包未包含或安装该数据库扩展。2026-10-28 的本地真实模型聚合问数在缺少角色授权时按 `AUTH_BINDER_MODE_REQUIRED` 故障关闭，按 `deploy/quickstart/postgres/02_readonly.sh` 的最小授权方式补齐后才执行成功。因此，v4.5.0 的“下载后真正一键可用”仍须完成数据库扩展的可信离线交付、安装或明确的外部数据库预配置流程，并在断网环境验证扩展版本、运行角色授权、聚合问数和审计；现有演练仅证明应用服务离线安装。

预检脚本通过 libpq 的 `PGHOST`、`PGPORT`、`PGUSER`、`PGDATABASE` 和 `PGPASSFILE` 环境配置连接数据库；以实际运行角色连接时直接执行，使用有权切换角色的安装账号时可加 `--runtime-role 读取角色名`。它只读取扩展版本、schema 和函数权限及能力标识，不安装扩展或修改数据库。隔离 PostgreSQL 16 实测：配置正确返回 `POSTGRES_BINDER=PASS`；无扩展、缺少 schema 使用权限、缺少函数执行权限及非法角色名分别按对应原因拒绝。
