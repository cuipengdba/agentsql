# AgentSQL v2.1.0 发布说明

v2.1.0 深化崖山 YashanDB 指定实例的受控只读验证。此前已有独立驱动、窄 SELECT 方言和测试夹具流水线；本版把真实最小权限账号、HTTP MCP、表权限、脱敏及持久审计串成同一条可重复的测试链，并用 MCP Inspector 与 Dify 实际调用。业务库断线和独立审计库停机均按无原始结果交付的原则验证。

验证对象为 YashanDB Enterprise Edition 23.4.1.109、`COMPAT_VECTOR=yashan`、`yashandb-go v1.4.4` 和独立 C 客户端 23.4.7.100 的 Linux x86_64 实例。AgentSQL 数据源使用临时只读账号，服务器自身拒绝 INSERT。单张表、明确列投影和有界 WHERE 的 SELECT 子集可按 Agent 策略执行；越权表 R010 拒绝，手机号按表列规则脱敏，决策写入持久审计库。适配器仍不开放写入、事务和 EXPLAIN。

## 升级与支持边界

- 本版无元数据或审计 schema 变更。仍应先按部署文档备份成套 metadata/audit，并演练从 v2.0.0 正式包的迁移、恢复和回退。双网关 Kubernetes 部署仍需维护窗口；本版未扩展其数据库适配范围或承诺无停机滚动升级。
- 真实客户端与指定崖山实例的测试使用合成数据。支持声明为**指定版本、指定模式的受控只读子集已验证**，不是所有崖山版本或生产拓扑的完整生产支持。TLS 证书验证、主备切换、持续负载、复杂 SQL、函数、系统目录、客户端取消及超时终止仍以实际后续验收为准。
- C 客户端再分发依据项目维护者所述厂家口头授权，仓库没有书面授权文件；不宣称厂商认证。自行构建时仍须取得匹配架构的客户端，并用 `CGO_ENABLED=1` 和 `-tags yashan` 编译，设置运行库路径。缺驱动或客户端库时失败关闭。
- 本版补齐已认证 Agent 的 `query`/`execute_write` 数据源可见性预检拒绝审计。最后一条 allow 策略撤销后仍不触达业务库，但会先持久记录 `deny` 并返回审计 ID；审计不可用则返回错误。此路径不保存未经解析的 SQL，`list_schema` 等非 SQL 工具和身份认证失败仍不属于 SQL 交通审计。

真库测试、失败尝试及未验证范围见 [v2.1.0 验收记录](v2.1.0-acceptance.md)。正式 CI、安装包、镜像、官网和 Live Demo 的发布证据将在封版后另行补充。
